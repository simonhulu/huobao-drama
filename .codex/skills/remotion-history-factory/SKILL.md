# Remotion History Factory

以尽快得到可用整片为默认目标：本地视频优先，图片补缺，空间部署、战役成败、势力范围消长、行军路线及各方势力兴衰消亡按需用地图，信息动效附着在镜头上解释内容。素材类型和来源保存在制作记录，不默认渲染“情景素材”“AI生成画面”“非事件实录”等常驻角标；成片文字用于字幕、叙事解释和用户指定的包装。禁止用独立纯色文字卡替代镜头；同一成片的视频或图片资产只能使用一次，换裁切、改入点、翻转、改色都不算新素材。制作总控只有这一份；网页统一使用 `/remotion` 和 `/remotion/episode/<真实 episodeId>`，不再建立独立精细化工作台。

## 入口与原稿

- `/history-scripts`：统一点击“继续生产”。尚无有效二创稿时，从下载、转录、校对、二创的有效检查点续作；已有有效二创稿时直接复用，不重新改写。后台先同步花生原任务，再补齐或继续花生版与精细化版；花生创建结果不明时先查找原项目，未能唯一确认则提示核对，同时允许精细化版继续。重复点击复用正在执行的任务，两版已完成则查看已有成片。精细化分支锁定 `rewrittenScript` 创建或复用对应 Episode 与 Remotion 任务。制作阶段不再二创、润色、删句或改写旁白；分镜拼接须逐字等于已保存的 `rewrittenScript`。未保存修改先保存；旧版本任务和成片保留。“同步花生状态”仅核对现有项目，不创建、确认或导出作品。
- 精细化任务接纳不受花生额度、制作结果或当前工厂执行槽位影响。接纳后即创建或复用可见的 Episode/queued 任务；只有工厂 runner 控制实际并发（最多两项准备、单项整片渲染），外层流程不能再用并发数量阻止入队。两版各自完成、各自交付并自动发表百家号。
- 已有 Episode：复用本集稿件、标题/发布包装、匹配的干净配音母带、时间码及合格资产。URL 的 episode number 不等于数据库 ID；通过现有 API 或 inspector 解析真实 ID。
- 用户明确要求为已完成花生作品补精细化版时，提交 `POST /api/v1/history-scripts/huasheng/refine-completed {"sourceIds":[明确选择的稿件ID]}`，沿用当前二创正文。后台以 `motion_backfill` 排队，优先核验复用同正文的已有成片，缺少成片才制作，完成后自动发表百家号；原花生版不重做、不补发。
- 本地新稿：仍可用下方 `--source-only` 完成原材料入库，再从真实 Episode 启动统一制作。`source-ready` 不代表成片完成。

```bash
node .codex/skills/remotion-history-factory/scripts/history_intake.mjs \
  --source-only --script <final-script.md> --drama <drama-id>
```

新系列用 `--create-drama --style <已选 style-id>` 代替 `--drama`。保留 frontmatter 的确认标题和同目录 `07-publishing-package.json`，不从文件名再生成另一套包装。网页/API 操作、任务状态和恢复见 [统一执行](references/unified-workflow.md)。

## 效率默认值

1. 复用工件优先。已有母带与正文相符就不重配音；保留确定性分镜、有效设计、已下载素材、生成图及地图缓存。重试同一镜头可复用工件，但同一成片不同镜头不得重复视频或图片；用素材 ID 和真实文件哈希双重去重。
2. 自动推进。规划按批处理；受限检索后按排序检查素材，新素材最多抽两帧并缓存观察，明显画面/时代错配才有限顺延，最多检查前三候选。视觉服务超时明确记录未核验，不无限等待。缺素材先补图；地图或生图失败记录可重试的 fallback，并只复用合法、尚未使用的底层视频/图片。没有底层媒体时保留缺口并允许重试，不用独立信息画面冒充素材；不为普通缺口设置逐镜审批或置信度闸门。
3. 表达够用就停止精修。优先解决错配、丢旁白、读不清、遮挡、双字幕、声音冲突和中断；不以动画数量、精确古边界、全镜细调作为完成条件。
4. 正常制作技术通过后自动交付，人工审美和历史复核在成片后进行。首次接通新路线或发生具体渲染问题时先测代表片段；既有成功路线不反复增加前置试片。

## 每镜先决定表达，再决定材料

写清该镜要让观众理解什么，保持锁定旁白与顺序，再选择视频、图片、地图或信息图。导演规划只决定表达，不改正文，不把无据推论写进标题或图表。具体检索与记录字段见 [素材与编辑合同](references/material-contract.md)。

- **视频**：由受限服务调用 `HuashengMaterialLibrary.search()`，只检索已下载、推荐前三名的有限候选。模型不能读取整个 SQLite、执行 SQL 或自行指定候选外路径。候选标注、原分镜和实际画面观察分开记录。影视素材默认作情景说明，不能称为事件实录。
- **图片**：复用合格图片，缺口才调用现有图片服务；同人物/场景保持服饰、器物、构图和提示词一致。画面不烧普通字幕与动态标题；制作记录标为情景示意，不自动加画面角标。提示词一致不等于已证明人物身份连续。
- **地图**：当空间关系或部署变化、战役成败、势力范围消长、行军路线、各方势力的兴盛衰落或消亡中的任一项是本镜核心，且能用地图讲清时，使用 [history-map-animation](../history-map-animation/SKILL.md)，不要求同时出现行军或部署。`purpose` 写清要表达的关系、动作或结果；只出现地名或胜负、兴衰词语不足以选地图。战役结果与势力兴衰按正文明确的撤退、守住、据点易手或阶段结果表达，不能由战败推断失城、由失城推断势力灭亡，或把兴盛直接画成疆域扩大。先把该镜定为 `locate`、`route` 或 `encirclement`，只提交核实的 `places`/`routes` 与叙事关系；地图准备器负责相机、箭头和部署几何，模型不得自行填坐标或古代边界。5 秒镜头优先“建立 → 一个动作 → 结果停留”，`encirclement` 的圈形和压缩始终标“部署示意”。可执行字段见 [镜头设计](../history-map-animation/references/shot-design.md#可执行字段示例)。自动路线使用可核查现代地理锚点并标明示意；无史料不画精确古代国界，不把长平案例套给其他战役。地图准备失败记录可重试 fallback，并改用合法、尚未使用的底层视频/图片承载叠层；不能把独立信息画面当作地图缺口的替代媒体。
- **信息动画**：时间、数量、关系、引文作为视频/图片上的悬浮解释层，保持主体可见，避开底部字幕；不能成为独立纯色信息镜头，不把整段旁白再排一遍。底层素材缺失时补独立图片；补位失败留可重试缺口，不交付空画面。

视频需要单独判断原字幕、原声音、镜内切换、人物运动及裁切。默认静音素材原声，保留旁白与独立音效；现成运动已足够时不再叠推拉。短素材先用最多 0.8 倍的温和减速填补小缺口，剩余尾帧停留写入记录，不静默循环；明显长定格优先检查同一叙事的较长候选，或在旁白已经引出地图/图片时提前入画，不以时长足够为由选无关素材。镜头接续使用短画面叠化：普通视频约 8 帧，进出图片/地图约 12 帧（30fps），短镜进一步缩短；全局字幕和声音保持连续，上一镜的标题与信息叠层不延续到下一镜。地图来源长文字与素材类别留在制作记录，成片不默认烧录。仅有 `ffprobe` 结果不能宣称已检查画面语义、字幕或镜内切换；用本次代表镜头回看补足证据，发现具体问题再局部修复。

## 保留创作与精修能力

分镜逐字覆盖确认正文，优先复用对应母带的时间码，累计帧数守恒。镜头切点不得早于本镜旁白结束；短叠化从该边界后开始，不为减少尾帧或填素材缺口提前切镜。厂商返回整段时间码时不能靠字数均分决定句内切点，使用现有本地 Whisper 按锁定原文映射词尾/分句末尾，识别文本只用于找时间，不能替换原稿；字幕使用同一份音频对齐。识别结果按音频哈希缓存，合格逐镜时间码无需重复识别。无法细分的边界标明估算及实际回看范围，不能声称已精确对齐。底部完整字幕负责听读，大字负责重点；动态文字包含入场、阅读停留、退出。

人名、帝号等识别错字导致短镜文字匹配偏低时，仅在全文已匹配、本镜与前后文字连续完整映射、镜内有连续精确锚点且镜尾落实测分句末尾时，允许复用该段末时间。保留实际置信度和偏差警告；段内切点、丢句或缺少上下文仍暂停，不能整体降低匹配阈值。错误提示区分识别程序/模型缺失与已完成识别后的具体镜尾匹配失败。

简繁差异只在匹配端使用本地 ICU `uconv` 归一，不修改正文、字幕或原始识别记录；可通过 `HISTORY_ALIGNMENT_UCONV` 指定程序路径。古文中的同音错字只在完整连续映射、邻文精确锚点、精确镜尾、完整 token 和实测停顿共同支持时恢复，保留原始文字置信度，不能用同音匹配放过丢句。程序不可用时保持严格匹配。对已缓存母带和识别结果，可用 `backend/scripts/history-motion-recover-audio.ts <episodeId>` 验证；`--apply` 仅在原任务未运行且快照未变化时写回时间码，备份保存在 `data/reports/history-audio-recovery-<episodeId>/`，不触发配音或重新识别。

补图对明确未受理的临时上游拒绝采用有限退避重试，沿用原生成记录；已有 task ID 只续查，结果不明仍禁止重复提交。等待上游任务时保留结构化恢复标识，由现有队列自动继续，不能包装成普通失败或重做前镜。

新配音使用当前旁白配置的默认音色（当前为 `ttv-voice-2026072016135626-xnywYYL4`）。普通重试复用确认母带；用户明确更换音色时必须校验音色元数据，不能因存在 `plan.audioPath` 或 Episode 缓存而绕过。换音色保存新版母带，重对齐镜头、字幕、地图阶段和音效，保留旧母带与成片；仅有配置修改不代表已有成片已换声。

地图战事使用 `mapPlan.forces` 表达武将与军队：姓名、阵营、1–3 字旗号、城市锚点、动作、可选路线引用，以及镜内秒数 `start/end`。武将示意头像按人物缓存，全任务默认最多新增四位，其他使用步兵/骑兵符号与姓名；头像失败不阻断制作。行军与撤退沿现有路线移动并在抵达后驻留，只有明确 `occupy` 才换城市归属并留下旗帜。军队标记不能冒充精确兵位或数量，人物头像作为身份叠层复用不等于重复底层场景。军队、路线、地图阶段和相机在换声时一起重对齐，头像随底图一起冻结到本地渲染资产。

地图底图通过同一准备器自动组合实测高程、独立河网、海面和有来源的山川名称，不让模型填写地理几何。优先缓存，细数据不可得时记录实际降级并继续；不为每镜重新下载。城市、军队和地理名称共同避让字幕，次要地名放不下就省略。已知现代河道差异按全文历史语境处理；实际数据覆盖和限制见 [地图数据与复用](../history-map-animation/references/data-and-reuse.md#通用制图实现)。升级已有成片时保留正文、音轨及切镜时间，只重渲染必要区间并回写原任务，旧版仍保留。

语义运镜、动态大字、地图、信息图、本地 SFX 已由统一 composition 组合。需要人物情绪、道具指认或特定风格精修时，按需读取 [videoeditor](../videoeditor/SKILL.md) 和 [逐镜精修规则](../videoeditor/references/refined-editing.md)，复用现有组件与执行器，只修改相关镜头。人物头部/道具动画需要实际画面坐标；动态人物不能照搬静态图片坐标。未进入最终 composition 的效果不能计入交付。

音效按转折、抵达、揭示等具体动作选择；无适合音效可留白，默认无 BGM。使用已有本地音效库，冻结真实来源和时间段，优先旁白可懂度。现有自动音效匹配与响度处理不等于已试听通过，不要求每镜有声。

## 成片与证据

默认横屏 1920×1080、30fps，完整 Remotion composition 直接输出 H.264/AAC；竖屏使用独立 1080×1920 布局。沿用 [上传编码与体积合同](../videoeditor/references/refined-editing.md#上传编码与体积验收)及 `scripts/videoeditor/upload_encoding.mjs`，不通过删字幕、降尺寸或全片 PNG 落盘换速度。旧字幕专用硬件 worker 是另一条已有出口，不代替这里完整 composition。

交付应有完整成片、带声音精选、逐镜决定与来源/入出点、地图依据、技术报告及实际回看范围。输出登记到 Episode/Remotion；存在历史稿件关联时回写交付记录，并保留既有版本。关联失败单独重试交付，不重新渲染。

技术报告证明帧数、时长、音轨、编码、体积及输入哈希；这些不能证明历史结论正确或影片好看。回看记录写明镜头/时间段与播放方式，未听审就写未听审。只对本次实际产物报告完成，不把 UI 状态、文件存在或旧示例当质量证据。历史稿件的新交付各自写入自动发表意图，由 `history-video-publish` 流程直接发表百家号：哪版先完成先发哪版，不等另一版。成片记录按 producer 和文件 SHA256 分开保留，不能因花生已回写旧 videoUrl 而跳过精细化交付。Episode 单独制作且无 history source 时仍按用户指定渠道交付。

## 兼容边界

`history-motion-video-factory` 是本 skill 的旧名兼容入口；`videoeditor` 保留专项精修能力；五格/comic runner 只在明确恢复旧任务时读 [legacy-five-panel.md](references/legacy-five-panel.md)。旧任务、旧产物保持可访问，不启动旧 runner 来伪装新制作完成。

真实代码与已验证边界见 [架构核实](../../../docs/history-remotion-unified.md)。
