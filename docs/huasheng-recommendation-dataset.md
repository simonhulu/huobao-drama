# 花生推荐素材采集

按项目的分镜顺序采集右侧推荐信息，将标注、推荐关系和下载状态保存到项目的 SQLite 主库，并下载每个分镜排名 1、2、3 的原视频。使用编辑器点击分镜时的同一只读接口，不替换已选素材、不重新搜索或生成视频。

当前用户指定统一存放在 Mac 本机磁盘：视频和分镜备份位于仓库的 `data/huasheng-recommendations/`，主数据库为 `data/huobao_drama.db`。不再以 `/Volumes/wd3` 作为采集目标。按已下载视频大小估算，全部分镜前三名去重后约需 60-75GB，建议预留 100GB。

2026-10-24 已完成全部可用前三名视频：65 个项目、4,592 个分镜、13,737 个本地视频路径，涉及 9,938 个不同素材；视频文件按硬链接去重后为 63,720,962,936 字节（约 63.7GB）。全部文件的大小和 SHA-256、素材表外键及项目分镜数量均通过复核，未完成下载为 0。27 个分镜在官网只有一至两个候选，已全部保存现有候选。完整结果位于素材目录的 `verification-report.json`。

## 运行

日常更新可打开前端的 **素材库** 页面（`http://127.0.0.1:3013/library`），点击 **更新素材库**。每次都会重新读取当前花生账号下的全部项目和推荐信息，补齐新增分镜和缺失视频；已有视频核验后复用。页面只提供全库更新，不需要选择项目。

页面显示等待开始、更新中、正在中断、已中断、已完成和失败，以及项目进度、当前分镜、开始与结束时间。状态保存在主数据库的 `creation_tasks` 中，刷新或重新进入页面会继续显示。执行期间点击 **中断更新** 会停止新请求，等待在途下载清理后结束任务，已经保存的标注和视频保留。再次点击更新会检查全部项目并复用已完成素材。同一时间重复点击只会返回同一个活动任务。

后台复用现有采集器，固定全量模式、8 个项目并发、每个分镜排名前三的视频；不重新生成或替换花生项目中的素材。汇总区分新增、复用、不可用候选、元数据计数提醒和真实失败。候选本来不足三条、包含非视频素材或平台报告总数偏差不会单独导致任务失败；请求或下载失败时任务显示失败并保留已保存内容，重新全库更新即可补齐。花生登录过期或专用浏览器未打开时，页面提供打开浏览器的入口，登录后重新更新。

后端接口为 `GET /api/v1/huasheng-materials`、`POST /api/v1/huasheng-materials/updates`、`POST /api/v1/huasheng-materials/updates/:id/stop`。两个操作请求仅接受 `{}`，其中 `id` 是本地更新任务编号，不能指定项目或文件路径。服务异常退出后会将过期租约或已退出进程的任务标为已中断，不自动启动新的采集。强制杀进程留下的 `.all-projects.lock`、`.collect.lock` 或 `.part` 仍需按下文确认并处理，按钮不会自动删除未知锁或未完成文件。

复用项目现有的花生专用浏览器登录会话，默认端口 `9243`、目录 `data/huasheng-browser-profile`。浏览器未启动时，在历史脚本工作台打开花生登录窗口并登录。采集程序只读取此专用会话的花生 Cookie，不打开或控制页面；Cookie 只在内存中用于花生接口请求，不写入产物、不发送给视频 CDN。

在仓库根目录运行：

```sh
cd backend
node --import tsx scripts/huasheng/collect-recommendations.mjs --all-projects --project-concurrency 4
```

如需将素材写入外置盘，可追加 `--output`，例如此前使用的目标：

```sh
node --import tsx scripts/huasheng/collect-recommendations.mjs --all-projects --project-concurrency 4 --output /Volumes/wd3/huasheng-recommendations
```

目标目录必须已挂载且可写。已有素材迁移时应先复制并核验文件，再调用 `HuashengMaterialLibrary.relocateRoot(旧根目录, 新根目录)` 事务更新路径；该方法只更新数据库，不搬运文件。主数据库无需移到外置盘。

`--all-projects` 自动分页读取当前账号 `https://www.huasheng.cn/project` 下的全部项目，再采集每个项目的全部分镜。默认串行，可使用 `--project-concurrency 1..16` 设置同时处理的项目数；每个分镜的前三个视频并发下载，完成后逐项入库。某个项目失败时记录原因并继续其他项目，尚未制作、没有分镜的项目登记为空项目。每个项目保存到素材根目录下自己的项目 ID 目录，原有单项目进度可以直接复用。

仅指定一个项目时运行：

```sh
node --import tsx scripts/huasheng/collect-recommendations.mjs --project https://www.huasheng.cn/video/260077122691088
```

默认数据库为 `data/huobao_drama.db`，兼容 `DB_PATH` 环境变量，也可用 `--database <文件>` 指定另一个 SQLite 库。视频默认保存到 `data/huasheng-recommendations/<pid>/`。可追加 `--output <目录>` 指定素材目录（全量模式表示项目目录的父目录），`--limit 1` 先采集每个项目的第一个分镜，`--metadata-only` 只采集元数据。全量模式的 `batch-report.json` 记录本次所有项目、完成状态、元数据缺口和错误。参数和路径可用 `--help` 查看。命令行采集可独立运行；前端按钮需要现有前后端服务和后台任务执行器在线。

## 数据库

数据库是采集记录和恢复进度的依据，每个视频完成后事务更新。只使用已有的 `better-sqlite3` 依赖，自动创建本工具的表，不执行主库其他启动迁移。

| 表 | 内容与唯一性 |
| --- | --- |
| `huasheng_material_projects` | 项目名称、链接和分镜总数；项目 ID 唯一。 |
| `huasheng_material_clips` | 分镜文稿、检索描述、已选素材、采集状态；项目 ID + 分镜 ID 唯一。 |
| `huasheng_material_assets` | 素材来源、画面描述、时长、尺寸与帧率；素材 ID 唯一，跨项目去重。 |
| `huasheng_material_recommendations` | 分镜与素材的关联、推荐排名、原始字段、下载状态及错误；重复采集更新原记录。 |
| `huasheng_material_files` | 已核验文件的绝对路径、来源项目和分镜、字节数、SHA-256 与媒体信息；路径唯一。 |

同一个素材可以关联多个分镜和多个检索描述，数据库保留这些关系。视频文件仍在磁盘上，数据库保存路径；推荐排序刷新不会删除已经登记的本地文件。同一素材 ID 在其他项目或分镜已有成功文件时，先核验字节数与 SHA-256，再创建独立路径的硬链接，减少重复下载和磁盘占用；跨磁盘时正常下载新文件。文件路径为绝对路径，移动素材目录后需要同步调整路径。

查看统计和检索可用视频（在 `backend/` 目录）：

```sh
node --import tsx scripts/huasheng/collect-recommendations.mjs --stats
node --import tsx scripts/huasheng/collect-recommendations.mjs --search 红军 --limit 10
node --import tsx scripts/huasheng/collect-recommendations.mjs --project 260077122691088 --search 瑞金
```

查询直接读取本地数据库，无需浏览器登录或网络请求。搜索匹配检索描述、画面描述和分镜文稿，默认只返回已下载成功的素材，包含绝对文件路径。服务代码中的 `HuashengMaterialLibrary.search()` 同时支持项目、分镜、推荐排名范围及分页，便于后续创作流程直接调用。

首次迁移旧采集结果时运行：

```sh
node --import tsx scripts/huasheng/collect-recommendations.mjs --project 260077122691088 --import-existing
```

迁移读取现有 `manifest.json` 和分镜检查点，离线核对每个已完成文件的大小和 SHA-256 后入库。重复运行不会新增重复记录，已有数据库记录优先于旧备份。文件缺失或校验失败时保存失败状态，不将它登记为成功文件；迁移不重新下载视频。

## 本地文件

```text
data/huasheng-recommendations/260077122691088/
  manifest.json
  clips/
    001/
      annotation.json
      标注.txt
      01_68cbb710-ec4e-4feb-a799-af76fc00691d.mp4
      02_667d1a5d-3f55-45ee-bd22-fca6606f2e0c.mp4
      03_0103c6f57376bc30e836eb8ac414c62b7bde78fc.mp4
    002/
      ...
```

- `annotation.json`：自动生成的分镜检查点备份，包含文稿、右侧描述、素材元数据和下载结果。
- `标注.txt`：右侧描述和该分镜文稿，方便人工查看。
- `manifest.json`：本次采集范围内各分镜的备份清单。

后续采集不再生成或更新 `dataset.jsonl`。原有 JSONL 保留为历史文件，标注维护和程序检索以数据库为准。即使删除 JSON 备份，采集器也能从数据库恢复已完成视频的校验记录。

`query` 是花生为该分镜生成的检索描述，可能包含人物、地点和年代。它是推荐关联标注，不能证明视频确实拍摄于该地点或年代。`sourceCaption` 单独保留平台已有的素材描述；接口未提供时留空，不自行生成。一个视频在多个分镜中出现时，各分镜的标注关系分别保留。

推荐列表按每页 60 条读取，保留原顺序，不把“使用中”的素材强制放到第一位。官网接口偶有报告总数与实际可见数量不一致的情况，例如报告 60 条实际返回 59 条：保留已返回候选、下载可用的前三名，并在分镜元数据 `_recommendationCollection` 中记录报告数量和实采数量，批次报告通过 `metadataWarnings`、`metadataComplete` 单独标明元数据缺口，不将缺口伪装成完整列表。只下载前三名，不用第四名替换失败或不可下载的候选。图片、流媒体播放清单或空地址会记录原因，不伪装成 MP4。

## 大模型检索

SQLite 保存项目、分镜、素材、推荐关系和本地文件的原始记录。语义检索适合作为可重建的派生索引增加：分别对分镜检索描述和素材画面描述生成向量，以项目/分镜/素材 ID 关联回主库，返回有本地文件的素材，并结合结构化条件筛选。同一素材关联的不同分镜描述不能合并成一条未经核实的画面事实。

当前尚未生成 embedding 或启用向量扩展，`--search` 是 SQLite 关键词查询。后续本地部署可使用 `sqlite-vec`；需要多服务共享检索时再评估 Qdrant 等服务。是否能按实际画面检索取决于索引内容：平台推荐描述只能支持推荐语义，实际画面需要独立的帧分析或多模态向量，并保留标注来源。

## 中断与恢复

按原命令重跑即可。每个视频先写 `.part`，检查下载字节数和 `ffprobe` 的视频流、时长与尺寸后才公布最终文件；数据库记录字节数和 SHA-256。重跑时从数据库读取已有进度，只复用文件名、素材 ID、字节数及 SHA-256 全部匹配的成功文件，重新读取推荐信息以取得有效地址。

每个视频成功后更新分镜检查点。`Ctrl+C` 会停止下载并清理本次未完成的 `.part`；已成功的文件保留。整个输出目录用 `.collect.lock` 防止两个进程同时写入。异常断电或强制杀进程后，确认锁中记录的进程已经退出，再移除遗留的锁和未完成的 `.part` 后重跑。既有文件校验不匹配时保留原文件并报告错误，不覆盖。

部分失败时仍保存成功分镜和错误原因，命令以非零退出码结束。下载日志不输出 Cookie 或签名地址。数据库和 JSON 备份中的来源链接可能含临时 CDN 签名；本地文件可脱离链接继续使用。

全量采集还使用根目录的 `.all-projects.lock` 防止重复批次。可用磁盘空间接近 1 GiB 或容纳不下下一个已知大小的文件时，停止整个批次、清理本次未完成的下载并保留已成功的记录；扩容后按原命令重跑。并发流会定期复查空间，保留阈值不是对最终剩余字节数的严格保证。
