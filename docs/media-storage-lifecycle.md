# 创作流程的磁盘管理

入口：<http://localhost:3013/settings?tab=storage>。

## 回收规则

| 文件 | 自动处理条件 | 保留的内容 |
| --- | --- | --- |
| 历史、科普采集原件和 ASR 分片 | 完整转录及来源、文字指纹已持久保存；无外部工程引用、执行锁或保留标记 | 来源链接、全文、分片转录证据、清理清单 |
| 历史渲染 bundle 和复制的素材 | 完整成片及技术检查、回看证据可用，原始素材逐一校验通过；整组无其他消费者 | 成片、原图、配音、计划、审核证据 |
| 不可变素材、交付副本 | 两边实际 SHA-256 相同，文件身份未变化，无活跃消费者 | 每个任务的原路径和内容；通过硬链接共用底层文件 |
| 最终成片及同版制作原件 | 精确对应当前文稿、视频 SHA，全部目标平台已确认发表，默认 0 天，无待处理消费者；原件须与该交付的制作任务精确关联且实际 SHA 一致 | 上传回执、文稿、工程及清理审计 |

完成或删除任务本身不构成删除文件的凭证。CBA 删除任务改为保留文件及上传检查点的逻辑删除。CBA、Remotion 的草稿保存或简单成功标记不能授权自动删除成片。

成片保留期可设为 0–90 天；0 天表示取得可信的“已发表”回执后即可在回收轮次中释放，“已提交、等待审核”仍保留。已经保存的保留期不会被新默认值覆盖。精细化制作只匹配该交付绑定任务的 `render-*/movie.mp4`，花生只匹配同任务、同稿件版本的已完成导出；不会因为一个来源上传成功就清空该来源所有成片。每个文件继续独立检查 SHA、保留标记和消费者。同一路径只进入一种回收动作，待删除的文件也不会被用作去重的原始副本。

整组回收前重新检查所有成员，而非仅检查候选文件。任何成员被固定保留、共享或用于其他工程，就保留整组。直接在转录结束后执行的清理，也检查登记表和当前工程引用。引用检查失败时保留并登记原因。

## 人工核验

点击“人工核验”后，可按任务类型、任务编号和产物类型筛选，再打开文件详情。列表分页显示总数并支持加载后续文件；“归属待确认”只显示尚未确认实际任务的文件。详情包含实际视频、音频或图片预览、下载、SHA-256、关联任务和阻止回收的原因。

- “保留文件”会同时保存数据库标记和目录保留清单，自动程序不能回收。
- “归档保留”需要一个已经存在于受管数据目录之外、内容完全相同且独立的备份文件。校验和归档记录保存成功后才移除本地原件；可以恢复为原路径下的普通文件，恢复失败时保留重试机会。
- “删除成片”需要人工确认制作结果、所有必需平台上传成功，填写回执链接，并通过最新任务、依赖、SHA 检查。工程输入及工程记录不能通过这个按钮删除。
- 没有可靠任务归属的历史文件显示“归属待确认”。先查看媒体并关联一个实际存在的任务，留下文件指纹和人工关联记录，之后才能继续核验。关联动作本身不会授权删除。

旧花生导出和合成任务结果会补登记历史归属。受管媒体目录中的其余遗留文件进入待确认队列，不按文件年龄自动删除。

## 空间保护与执行

YouTube 来源优先下载压缩音频，低分辨率视频仅作为兼容回退，并设下载大小上限。CBA 编辑仍保留所需真实视频。抖音现有下载服务没有可靠音频选项，在转录完成后回收本地原件和可确认的下载器缓存。

默认保留 10 GiB 空间，可用 `MEDIA_DISK_RESERVE_GIB` 调整。新下载及渲染启动前检查余量；历史渲染和 CBA 整场录像下载期间持续检查，花生成片下载还按剩余长度预检并在传输中检查。CBA 下载取消会停止下载器和合并进程所在的进程组，必要时强制结束，保留断点后释放任务锁。空间不足时停止新增写入，保留临时成片、原工程或下载断点，清理后可重试。此保护不能约束其他应用或已经加载旧代码的运行进程。

独立维护服务监听 `127.0.0.1:5681`，由本机 LaunchAgent 启动，每小时按凭证回收。前端存储接口单独代理到该服务，可在主生产进程持续运行时使用。维护锁跨进程互斥，仅恢复确认已经退出的进程所留下的锁。

```sh
cd backend
node --import tsx scripts/storage-maintenance.ts scan --report=../data/reports/storage-scan.json
node --import tsx scripts/storage-maintenance.ts cleanup --kinds=transcribed-source,render-cache --report=../data/reports/storage-cleanup.json
node --import tsx scripts/storage-maintenance.ts cleanup --kinds=duplicate-material
```

`storage_artifacts` 登记文件，`storage_artifact_refs` 保存各任务及其使用目的，`storage_cleanup_runs` 保存执行审计。原件目录的 `storage-release.json` 在删除前持久保存来源与全文指纹、每个文件的身份，删除结果再次写入。

回收文件占用与磁盘净可用空间分别记录。后台生产继续写入、APFS 共享块和 Time Machine 本地快照都可能令两者不同。清理不会自动移除本机备份恢复点。
