# 花生工作区账号

## 目标与改造边界

历史脚本与科普分别使用自己的花生制作账号。账号管理需要同时说明工作区归属、官网用户身份和最近一次有效性检查结果。制作账号与百家号发表账号是不同概念。

本次改造按以下顺序实施：

1. 用隔离目录和模拟官网响应锁定账号、会话、任务恢复和导出的回归行为。
2. 复用科普现有账号编号与登录目录，为历史原有登录目录建立固定的历史账号记录。
3. 共用账号身份检查能力，官网用户 UID 首次核验后固定；后续错号或跨工作区重复身份必须阻止操作。
4. 历史任务和导出记录保存账号编号，旧记录归属原历史账号，恢复时继续原项目与导出检查点。
5. 历史与科普使用一致的账号管理界面，显示绑定身份、当前身份、有效性和检查时间。
6. 验证相关回归与页面；加载代码时先确认现有生产任务，避免打断制作。

不复制或合并两个浏览器的 Cookie，不移动现有远程项目，不批量重做或发表作品。账号设置只管理制作身份；既有统一发表工作台保持自己的发表任务和回执。

## 账号与身份

- 历史页面固定使用 `history_huasheng_legacy`。首次初始化保存原历史浏览器的地址和登录目录，后续环境变量修改不会把旧任务迁到别的目录。
- 科普保留已有 `science_huasheng_*` 编号、端口、登录目录及默认账号。更改科普默认账号只影响新任务。
- 首次成功读取官网 `GET https://api.huasheng.cn/x/web-interface/nav` 后保存 `mid` 和展示名。以后 `mid` 必须一致，昵称变化不视为换号。账号备注、浏览器连接成功、页面看起来已登录均不能代替官网身份核验。
- 两个工作区不能使用同一官网用户，也不能共用调试端口或登录目录。重复、错号、登录失效和暂时无法核验分别保留状态；不自动覆盖原绑定。
- 网页只返回账号备注、绑定身份、本次观察身份、核验状态和检查时间，不返回 Cookie、签名字段或本机目录。

## 操作与恢复

历史页顶部所有视图提供「花生账号」，科普页沿用同名入口。面板提供登录窗口和检查账号，显示所属工作区、绑定用户、本次登录用户、UID 和最近检查时间。打开面板只读取已保存结果；检查是官网只读核验，历史检查成功后保留原来对有效等待登录任务的恢复行为，仍重新核对当前稿版本。

历史制作及导出记录新增 `huasheng_account_name`。旧记录归属原历史账号，不改原项目、原导出任务号、文稿或已经发送的意图。导出接续时再次核对与原制作任务的账号关联；已下载视频的本地包装不因浏览器关闭而受阻。

实际制作允许重新打开该账号的专用浏览器；被动检查不启动浏览器，历史手动同步仍可恢复一次连接。账号动作区分并发的检查和打开请求，等待可以取消。官网身份核验在浏览器操作的发送意图之前完成，取消核验不会留下假的「已发送」检查点。确定未点击的控件失败恢复原步骤，未知发送结果继续保留防重复确认保护。

API 缓存按浏览器、目录和绑定 UID 隔离。缓存命中也读取当前会话；Cookie 或用户代理改变后重新取得官网签名字段。导出 POST 在保存发送意图之后、实际请求之前再次核验，确定未发出的请求可安全恢复；已经发出但结果未知的请求继续禁止自动重发。只读查询的网络重试也重新核验账号。

## 实现位置

- `backend/src/services/huasheng-accounts.ts`、`huasheng-identity.ts`：工作区账号、持久绑定、官网身份核验与跨工作区冲突检查。
- `backend/src/services/science-accounts.ts`、`science-workflow.ts`：兼容科普原账号记录，并在制作和恢复时使用原绑定。
- `backend/src/services/history-huasheng.ts`、`history-huasheng-discovery.ts`、`history-huasheng-export.ts`：历史任务与导出账号迁移、显式配置和原检查点恢复。
- `backend/src/services/history-huasheng-browser.ts`、`history-huasheng-export-api.ts`：浏览器动作前身份核验、缓存隔离和发送结果不明时的保护。
- `backend/src/routes/history-huasheng.ts`：历史账号列表、登录及检查接口。
- `frontend/app/components/HuashengAccounts.vue`、`ScienceAccounts.vue`：共用账号管理面板与科普兼容入口；历史、科普工作台及制作组件接入面板。
