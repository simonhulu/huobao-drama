## 二创准备记录

科普二创分为原文分析、远端正文缩写和原文对照核验。`gpt-6.1-terra` 通过严格工具 `submit_science_plan` 完成理解和大纲，再由远端写作模型 `Qwen3.5-9B-Writing-DPO-i1-Q4_K_M` 通过 JSON Schema 返回标题和正文。分析包含全文主题、作者立场与表达动机、情绪变化及其原文依据、选材取舍，以及必要机制、故事结构和好奇心推进。情绪弧线描述观众的感受变化，故事节点保留揭晓与转折的顺序，不能用知识目录代替。

正式大纲先拆原稿怎样讲：`sourceTelling` 说明知识、形式、开场、精彩原因、声音与幽默、结尾兑现；`narrativeBeats` 按原文顺序记录故事和实验细节、讲述手法、观众原先的疑问、此处揭晓什么、留到后面的悬念以及具体笑点。每段大纲的 `telling.sourceBeatIds` 对应这些节点，必须全部覆盖并保持顺序，避免把故事重排成知识目录。证据摘录必须出自原稿；选定的材料必须进入大纲，引用必须存在。模型若改写了原文摘录，会收到具体无效项并有一次纠正机会；仍无法核对就停止，不保存无效分析、不进入正文。

正文质量优先于字数，1000 至 1500 字仅作宽松参考，可以明显超过 1500 字或更短。尤其保护前半部分的开场、铺垫、好奇心、情绪推进和关键解释，不把过程压成结论，不提前揭晓答案；同时完整保留后半部分的论证和结尾。按内容作用决定详略，先删重复、相似例子和次要枝节，不按固定比例平均压缩，短稿不扩写凑字数。正文输出预算为 4000 token，避免原先 2200 token 预算过早限制展开；平台 10000 字符上限仍生效。保留情绪弧线、故事推进和完整因果，选择有代表性的实验、比喻和趣闻，删减来源身份与广告。按用户要求写得自然通顺、逻辑合理、通俗易读，保持原意，不强塞幽默或人设口头禅。讲述者为“小鹭”，不冒认原作者亲历。固定介绍“大家好，我是小鹭，你们的冷知识讲解员。”使用独立视频，正文直接切入话题。写作输入包含原文，以及按故事顺序排列的简洁可读材料 `readingMaterial`：节点、必要事实与限定、机制、情绪和结尾。不要求小模型解析交叉引用；已明确省略且不被采用的摘录从原文输入中移除，编辑备忘不传入正文。

写完由 `gpt-6.1-terra` 通过 `review_science_script` 对照原文与必要主线，只列会改变原意、造成逻辑断裂或破坏主要情绪推进的事实、因果、转折和结尾问题；不为个人措辞偏好、精确提问位置或大纲中的每个数字阻挡合理缩写。它不代写正文，也不为凑字要求扩写。问题附稿件中的逐字原句段与修订要求。1 至 2 处引用唯一且互不重叠的问题由同一远端 Qwen 局部修订；多处问题、缺失整段或无法准确定位时一次返回完整修订稿。修订请求包含必要原文摘录和上一稿上下文，局部修订尽量保留无问题句段。

每份稿件、核验意见、修订轮数以及局部修改进度立即保存为 `writingCheckpoint`，绑定原文哈希、写作版本和模型；未通过的稿件不作为正式正文交付。每次执行最多核验 8 稿，仍需修改时进入 `retry_wait`，自动接着修同一稿，最多再延续 3 次，避免无限消耗。制作队列等待当前任务自动续修，采集独立继续入库。服务重启后复用原分析、稿件和意见，未经核验的恢复稿仍须先核验。与原文相同、混入分析标记或改稿说明等可修正文稿问题同样进入修订循环；核验通过后自动进入制作。自动延续次数耗尽、认证或配置异常才保留检查点并显示需要处理。模型核验不能替代人的最终编辑判断或外部事实查证。

当前写作版本为 `source-paraphrase-v8`：二创以原稿为唯一依据，沿主要顺序换表达、适度缩写，保留原意、情绪和主要论证，已经通顺的句子可以保留。1000 至 1500 字仅作参考，不要求明显拉开措辞差距，也不重新策划或补充原稿没有的限定。首稿、整篇修订及句段修订都能读取完整原稿，分析不再裁掉写作输入或添加强制内容。审核只接收原稿与待改稿，检查明确改意、编造、数字等信息改错，以及严重残句、指代或关键因果缺失；不因文风、悬念技巧、素材覆盖、外部事实评价或相似表达反复退稿。旧版分析及修订检查点失效，已绑定制作项目的正文保持原绑定。空正文、原样复制、改稿说明及平台 10000 字符上限仍有本地校验。`backend/scripts/science-rewrite-pending.ts [任务ID...]` 可为已有原稿且尚无制作/上传检查点的任务重写正文，保存改写前备份和对照。它只运行文稿准备，不创建华生项目或发表。用 `--resume <对照目录>` 可沿原目录恢复未完成项。

工作台详情“二创准备记录”可查看原稿主题、立场、情绪、材料和顺序的简洁记录；这些记录只用于展示，不作为额外的写作及退稿标准。旧计划仍可查看，版本不一致时重新分析；已有正文不自动覆盖。分析检查点和正文分开保存，写作失败可复用同源、同分析模型、同写作版本的有效分析。最终记录分别保存分析模型 `model` 和实际正文模型 `writingModel`。

原作者自我介绍、频道身份、上期回顾、关注订阅与会员广告必须去除。开头的“大家好，我是……”同时有本地清理，不能因忠实原稿保留作者身份。审核定位到唯一、不重叠的句段时只替换这些句段，不再因问题多于两项就重写全文；整段广告删除允许返回空替换，完整正文仍必须非空。远端接口会区分完整稿与句段修订的输出指令。

可用 `backend/scripts/science-recreation-preview.ts <science-job-id>` 对已有真实原稿运行独立对照：结果保存到 `data/static/science-recreation-study`，包含原文、旧稿、实际工具调用分析、可阅读的 `reading-and-outline.md` 和新稿。它不覆盖任务、不触发制作或发表，适合完整读稿后判断改写是否保住原文的表达欲与知识价值。

可追加 `[saved-plan.json] [draft-checkpoint.json]` 从已保存分析和稿件续做，恢复稿必须先通过原文对照，不能直接作为成稿。每轮稿件保存在独立预览目录的 `draft-checkpoint.json`，避免网络中断后重写已经完成的内容。

## 使用

1. 在顶部「花生账号」管理科普制作账号，打开该账号的「登录窗口」完成登录，再点击「检查账号」，确认绑定身份与当前登录一致，显示「已核验，可制作」。百家号账号由「百家号账号」单独管理，使用百度 App 扫码。如果已在手机确认却显示失败，可以点击「重新检查登录」，复核已经保存的登录态，无需先重新扫码。待登录、失效和异常状态的账号列表也提供「检查登录」。
2. 点击“频道管理”，添加常用科普频道主页或 videos 页并保存，最多 30 个。频道列表会持久保存；频道主页和 videos 页视为同一来源，不接受重复频道或单条视频链接。
3. 点击“批量采集 / 生产”，设置新视频入库数量，或选择“采到频道末尾”。制作模式和账号用于独立制作队列；未绑定账号也可采集。采集不等待下载、二创、制作或发表，达到入库数量后结束。已完成采集会释放采集锁，后台制作期间也可启动下一批采集。
4. 工作台显示当前频道、扫描数、新视频数、跳过数、实际成功产出和失败任务。已保存视频会跳过，单条内容问题保留检查点并继续后续视频；不足目标时显示真实完成数量。临时接口和模型故障先自动退避重试；重试耗尽、登录失效、额度不足、限流或缺少模型配置会停止整批，处理后继续原批次，避免反复消耗后续视频的转写和二创。
5. 在批次“本批产出与异常”中打开单条任务，查看文稿、预览和下载成片、查看发表结果。二创完成后直接进入制作，同账号忙碌时显示“排队制作”，不再有 `review` 状态或单独的文稿就绪阶段。排队和执行时锁定文稿，可停止；暂停或异常后可修改尚未绑定制作的材料，再继续自动流程。华生文稿上限为 10000 字符。
6. 原批次即使已达到目标，仍可用“重试未完成任务”恢复已有任务，也可选定其中几条重试。恢复范围单独保存并显示进度，不再采集新视频，不改变原频道、目标和账号。恢复中停止或服务重启后，继续本批会沿用这一范围；已经完成的任务会跳过。批次列表会同步单条任务的实际结果，避免成片已就绪却仍显示旧失败。

任务列表、详情和批次条目均显示完整任务 ID。列表支持按 ID 搜索，详情提供“复制 ID”和复制结果提示，便于准确定位异常任务。

“补充单条视频”要求选择华生账号，启动后自动下载、转写、二创、制作、生成封面和导出，默认不发表；API 可显式指定 `mode: 'upload'` 制作后发表。重复导入同一视频会打开已有任务，不重复创建，也不修改频道列表。旧版 `drafts` 偏好在新建批次时使用视频制作模式；后台仅稿准备工具仍可用于独立稿件对照。

每个批次保存启动时的频道、产出模式、目标和账号快照。修改频道或默认账号只影响下一批；继续原批次沿用原配置，并跳过已完成作品。每条任务开始制作后绑定文稿与华生账号，开始上传后绑定百家号账号。科普的账号目录、登录会话、默认账号和任务记录独立于历史及体育工作台。

## 运行条件与恢复

- YouTube 复用既有 yt-dlp、FFmpeg 下载环境及 `HISTORY_YOUTUBE_YTDLP_BIN`、`HISTORY_YOUTUBE_PROXY`、`HISTORY_YOUTUBE_COOKIES_BROWSER`/`HISTORY_YOUTUBE_COOKIES_FILE` 配置。
- 原稿提取在 `backend/.env` 配置 `QWEN_API_KEY` 后默认使用 `qwen-audio-3.1-asr-flash-filetrans`；未配置时沿用 MiniMax，也可用 `ASR_PROVIDER=qwen|minimax` 明确选择。`QWEN_ASR_BASE_URL` 可指定匹配密钥地域的业务空间原生 API 地址。按 480 秒分段、自动识别混合语言；成功片段会保存，失败后继续或切换服务时无需重复转写。依据 [Qwen 官方文档](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-filetrans-http-api) 和 [MiniMax 官方文档](https://platform.minimaxi.com/docs/api-reference/speech-to-text)。也可在下载完成后手动补充完整原稿，再生成二创稿。
- 分析沿用现有文本服务与密钥，指定 `gpt-6.1-terra`。正文通过已有 SSH 凭据连接远端回环端口 8788；实际部署为 llama-server 的 OpenAI 兼容接口，模型为 `Qwen3.5-9B-Writing-DPO-i1-Q4_K_M`，上下文已在 2026-11-05 提升到 131072（128K）token。配置 `SCIENCE_WRITER_MODEL`、`SCIENCE_WRITER_REMOTE_PORT` 可覆盖模型和端口，`SCIENCE_WRITER_API_URL` 可直接使用本机接口。写作独立于 8787 的 LatentSync，不静默裁剪来源或回退其他模型。响应截断或上下文超限会停止并保留分析。历史页现在共用该远程模型，按[保持原意的全文改写](history-source-paraphrase-20261105.md)执行；正文及思考预算使用独立 `HISTORY_WRITER_*` 配置，思考默认开启，科普默认关闭。
- 科普分析、写作及核验分别对网络、HTTP 408/429/5xx 暂时错误最多尝试四次，按 2/4/8 秒退避，并遵守有上限的 Retry-After。成功分析立即保存，写作重试不会重做分析。正文阶段单轮网络重试耗尽会保存当前稿件并进入流程级退避续做。来源摘录不匹配仍有一次具体反馈的纠正机会；正文质量问题按上述持久化修订循环处理。认证、配置、结构化参数错误不自动重试，也不更换写作模型。
- 华生每个账号有独立本机浏览器目录和端口，制作与导出都使用同一个账号配置。百家号复用现有 social-auto-upload 环境，以 `science_` 账号保存登录。
- 华生会等待文稿编辑器加载，核对全文和页面字数同步后才点击创建；收到匹配当前文稿的创建响应即保存项目链接。明确尚未点击或被平台拒绝时可以继续原任务；响应不明确时保留待确认状态，避免重复创建。恢复项目时校验完整文稿，不以相同开头判断项目归属。
- 华生创建与确认后，通过项目接口查询制作状态，再复用历史工作台的接口创建导出、查询导出进度和下载。`/api/innovideo/project/info` 核对项目编号及原始全文；沙盒项目额外查询 `/api/v2/innovideo/project/info`，要求实际制作阶段、分镜状态和生成进度均已完成。未确认方案的项目也可能返回 `progress: 100`，不能仅凭该字段导出。整个查询、导出与下载过程无需打开“导出”弹窗，实际下载完成后才显示“成片已就绪”。
- 项目与导出状态的只读 GET 查询遇到短暂连接中断时，最多尝试三次，并支持立即取消；创建导出的 POST 不自动重发。收到导出任务编号后持久保存，恢复时只查询该原任务。
- 流程层会对可重试的制作状态查询、导出准备、导出查询及下载最多尝试四次，按 5/10/20 秒等待，任务日志显示自动重试进度。导出准备只在请求尚未发送时允许自动重试；一旦发送且回执未知就停在原检查点。下载重试会重新查询原导出编号获得新地址，并沿用原 `.part` 文件。临时故障耗尽后暂停批次，待恢复后续做。
- 浏览器通过标签页元数据选择本任务页面，不初始化全部历史标签页。连接与页面准备阶段的暂时超时会有限重试；进入创建或确认操作后不重放整个流程。临时页初始化失败只清理本次新建的页面，保留用户和任务窗口。
- 确认制作后如果页面连接中断或超时，使用已经保存的原项目、账号和完整文稿再次查询制作接口。接口确认已排队、制作中或完成后继续原流程；接口仍显示未开始、无法核验或文稿不匹配时保留检查点，不重放确认。视频编辑器可能折叠原稿，不能把 DOM 中看不到全文当作平台没有接收。
- 页面分别提供“停止采集 / 继续采集”和“停止制作 / 继续制作”。停止采集保留已入库来源；停止制作不影响正在运行的采集。继续采集仅恢复原频道范围，继续制作只消费已入库任务。采集目标使用 `counts.selected`，制作完成和失败另行计数。无账号的入库任务可在单条任务中绑定账号后制作，批次原账号快照不自动改写。
- 采集与制作分别使用 `collector.lock` 和 `worker.lock`。同一时刻各自只有一个执行者；服务重启后分别恢复未主动停止的工作。旧版合并批次恢复时迁移阶段状态并补采未完成范围，仍在运行的旧版采集禁止并行启动新采集以避免重复入库。制作沿用原任务及平台检查点，新增来源会接入制作队列，不重做已完成结果。
- 单条自动任务在下载、二创、账号排队、制作、封面和发表阶段共用一个可取消的执行句柄，等待完成不会在二创后提前返回。服务重启后，仅明确启动过且未主动停止的单条自动任务会自动恢复，沿用原文稿、账号和平台检查点；不自动重试需要处理的失败。旧 `review` 记录读取时迁移到 `queued / produce`，读取不会自行创建平台项目；原批次任务由批次继续或定向重试接管。主动停止会撤销单条自动恢复意图。
- 后端不会自动热更新。当前本机科普工作台通过 `SCIENCE_API_TARGET` 代理至独立服务 5683，更新科普逻辑时优雅重启该进程并核验健康检查；不要误停承担其他任务的 5679。存在执行任务时先保留其检查点；主动暂停的任务保持暂停。
- “采到频道末尾”表示本次依序读取列表中频道至末尾，不是定时检查订阅更新。再次启动新批次会跳过已采集视频。
- 若华生创建/导出响应丢失，展开“恢复原项目”，填入原项目链接或原导出任务编号和版本。系统先通过绑定账号核对；填错时可更正，验证通过后才绑定。
- 上传恢复会核对当前成片、横封面、竖封面及账号。素材变化时只核对原草稿，不会用旧任务指纹上传新内容。

## 独立标题海报（2026-10-30）

成片接口下载完成后，工作流进入 `covers` 阶段，自动设计并生成两张独立海报：横版 1280×720、竖版 810×1080。画面用独立生图服务生成，中文标题由本地排版器叠加，不使用视频截帧。设计风格为主体特写、简洁暗背景、大号白字和黄色关键词；短问题必须有当前文稿依据。

`POST /api/v1/science-pop/workflow/jobs/:id/covers` 接受 `{regenerate?: boolean, instruction?: string}`，指令最多 1000 字。重新生成使用新的版本目录；失败保留上一版和当前生成检查点，同一未完成版本继续时复用已完成生图。任务页支持预览、下载、修改指令和重新生成。`coverGenerationPending` 为 true 时，旧图片可预览但不能用于新发表。

封面生成与平台上传分开。生成只保存本地海报，不要求百家号在线；上传只校验并使用已完成海报，不调用生图模型。尚未保存或发表的原编辑页可通过 `update-video-covers` 仅替换双封面，保留原账号、视频、编辑页和文案。修订中断后只恢复原修订，不重新上传视频。已提交作品禁止重生成；历史已保存草稿允许本地设计，但暂不支持直接替换其平台旧封面。

主要实现：`science-cover-poster.ts`（严格工具调用设计、生图检查点），`science-workflow-media.ts`（成片/海报校验），`science-workflow.ts`（生成与交付状态），`social-auto-upload.ts` 和 `bridge.py`（原编辑页封面修订）。

图片配置列出多个模型时，仅在服务明确返回模型不可用、记录已失败且没有远端任务编号的情况下，自动使用同配置中的下一模型。原拒绝记录和备用模型选择写入检查点；已受理任务、超时和不明确失败仍只恢复原请求，不重复提交。该恢复仅用于科普独立海报，不修改全局图片配置。
