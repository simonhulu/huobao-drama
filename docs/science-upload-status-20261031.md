# 科普上传状态与自动续传

## 本次排查

2026-10-31 的工作台记录中有 39 条本地成片：13 条已保存百家号草稿、10 条已提交审核、1 条已发表，另有 15 条未完成上传发表。

未完成的 15 条分别是：4 条后台浏览器连接失败、5 条原编辑页或结果待核对、1 条需要人工安全验证、3 条封面未完成、1 条主动暂停，以及 1 条制作时没有开启上传。

原页面仅凭 `videoUrl` 显示“成片已就绪”，旧草稿只显示“已完成”。这无法表达上传是否成功。后台对批次成片的自动续传也未覆盖 `ready` 状态；连接检查失败后没有有限重试。

沿原记录重试后确认另一处实际故障：可选话题选择失败后的清理操作与平台编辑器的选区处理冲突，误删了正文最后一个字。荔枝、仙人掌、大白菜的原编辑页均复现，随后原文校验正确地阻止了发表，不能通过放宽文案身份校验解决。

继续验证发现另一种时序：完整正文仍保留，但平台编辑器没有清除全部查询文字，留下 ` #热爆趣` 或 ` #热`。最终对尚未选择任何 DOM 话题的情况，先严格验证原正文和本次标签查询前缀，再使用编辑器支持的 `fill(base)` 恢复正文；已经选择的话题标签保持不动。

## 调整

- API 以 `uploadStatus` 独立表达待上传、排队、上传中、已上传草稿、已提交审核、已发表、异常、待核对、暂停和未成片；以平台回执区分草稿、提交和发表。
- 列表、详情、操作摘要及上传面板显示对应状态，封面和上传失败保留具体原因。
- 单条导入选择百家号后明确执行 `mode: 'upload'`，按钮显示“开始制作并发表”；没有选择百家号时仅制作。
- 同账号的科普上传先排队，再访问平台编辑页，避免互相争用。
- 临时连接故障最多尝试 4 次；每次从同一任务的持久化检查点恢复。人工验证、版本变化和结果不确定不触发自动重发。
- 自动发表任务已成片或在上传中重启时，自动恢复覆盖批次的 `ready` 和 `paused/upload` 状态。主动停止仍被保留。
- 修复话题失败后的正文误删及查询残留，保留正文身份校验与话题等待上限。
- 提供 `repair-topic-description` 处理已确认的旧任务损坏：严格核对原编辑页、文档标识、视频指纹、封面及当前文案，仅修复正文，不保存或发表。
