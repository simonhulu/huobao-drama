# NBA 新闻视频工作流

## 目标与边界

在 `/nba-video` 提供体育新闻工作台，参考科普工作台的 YouTube 频道配置与采集，以及 CBA 的任务队列、恢复、预览和百家号上传。配置频道中的比赛、采访、媒体日、专题、历史回顾、赛季合集、选秀及其他体育视频均可进入新闻检索。一篇独立报道对应一个视频任务，同一视频共享下载和人声分离结果。数据保存于 `data/nba-video`，百家号沿用 CBA 当前选择的账号，开启自动上传时直接提交发表并添加现有 `#NBA#` 话题。

## 内容要求

- 默认同时启用中文和英文，从配置的 YouTube 频道发现视频，保存标题与描述，提取人物、事件和主题，搜索匹配的完整新闻。比赛身份可辅助检索，但不要求每条视频都有比赛日期、两队和终场比分。YouTube 上传日期不能代替比赛日期。两种语言均有合格文章时交替入队，不要求强行凑齐相同数量。
- 频道默认配置为 NBA 官方频道，允许增删、排序，最多 30 个；每频道单轮扫描 1 至 1000 条，单轮新闻目标 1 至 100 篇，默认仍为 6 篇；手动模式最多填写 100 个独立新闻链接。单轮扫描量不是频道累计上限：优先检查最新视频，制作队列空闲时按持久游标继续历史扫描；繁忙时不推进历史游标。大批量正文读取预算随目标增加，不再固定截断在前 60 个候选链接。已覆盖本轮语言的视频跳过，临时失败和旧规则排除的非比赛视频允许重试。历史只采英文的视频在启用中文后补搜中文新闻，已有正文仍参与去重；来源故障或仅剩一个名额时不能把两种语言都标成已搜索。
- 手动链接作为单独模式保留，支持新闻 URL、YouTube 比赛 URL、ESPN 比赛编号和比赛日期。保存正文、来源、作者、发布时间与正文摘要值。
- 中文正文至少 100 个汉字，英文正文至少 100 个英文词；只使用原站完整正文，搜索摘要和 YouTube 描述不能当作新闻稿。找不到匹配正文时保留重试，不自动编稿。
- 按规范化新闻 URL、正文哈希、规范化全文及同语言相似段落去重，识别通讯社转载；不同域名或标题不能证明报道独立。每篇英文报道单独翻译，中文报道使用各自原稿，不能将同场新闻合并为相同稿件。不同语言对同一原稿的转述目前不保证全部识别，不增加模型事实审核。
- 单场比赛可从结构化记录补充当地日期、主客队及终场比分；主题报道不需要构造比赛对象，也不因缺少比分阻断翻译、配音或制作。
- 英文报道只做完整中文翻译，保留原稿信息、顺序、数字、引语和说话人身份，不创作、概括删节或补充信息。中文报道直接使用原稿。成片不出现媒体出处，工作台保留内部来源。不执行事实审核、事实映射或事实修正循环，也不以历史审核结果阻止制作或上传。
- 不规定四分钟时长，长度随稿件与语速变化；配音只保留正常标点停顿。中文配音与字幕使用同一锁定稿件。
- 压低原解说并保留球场声，分别控制原音与分离声床；模型可能残留解说或削弱欢呼，提供实际信号检查，不能宣称完全消除。
- 在完整回合或反应结束后过渡至源视频片尾，叠化约 0.5 秒，保留约 4 秒收尾并淡出。无法判定可用镜头时暂停并记录原因，不在投篮半途中强行截断。
- 已识别比赛的封面保留独立对阵海报：同场实际出场球员的真实半身或全身动作照、中文队名、真实比分、比赛当地日期和当前新闻标题。优先选择英文原标题提及的出场球员，否则按同场得分排序，每队最多尝试三人。通过 TheSportsDB 精确检索透明人物原图，检查实际球衣球队、躯干和手臂；旧球队球衣、纯头像不能入选。保留头顶、肩臂和持球动作，默认直接使用真实照片，保留球衣及篮球上的自然品牌，不逐个修补小标。图片不可用时自动使用队名版。
- 主题报道直接使用所匹配的原视频，允许不同体育频道与原声音轨语言。主题片尾使用源视频末段叠化与淡出，不显示虚构比分或“全场结束”；封面采用清晰原视频画面与顶部灰底中文标题。
- 球员采访、赛后发布会、媒体日根据来源视频标题自动识别，采用连续同源画面和环境声，中文旁白完整收句后约 1.1 秒自然淡出；原讲话降至原声设置的 15%，避免双语抢声。采访无需连续四秒球场声，仍须通过成片首尾静音、配音对齐、解码及削波检查。采访封面使用原视频清晰人物画面加中文标题，即使关联报道带有已核验比赛，也不改用对阵海报。比赛视频保留原有球场声和片尾核验。恢复失败采访时复用已有文稿、配音与字幕识别，只重做剪辑及交付。
- 横版 1920×1080、竖版 1080×1440 分别排版为 PNG，长标题自动换行并检查安全区；竖版不从横版裁切。保存球员图片来源、原生尺寸与摘要，海报画布尺寸不代表照片原生分辨率。已有交付可独立修复封面，无需重新配音或渲染视频；已提交上传继续复用原回执，不因新封面重复发表。

## 页面与操作

顶部提供频道管理、开始采集、选中续做、上传待传、停止和设置；队列支持状态、语言、关键词筛选。详情展示成片与检查结果、完整原文和中文稿、比赛身份与共享素材、执行记录。运行记录保留视频、新闻来源成功失败及排除原因。播放与下载通过受限资产接口支持 HTTP Range。

默认采集参数包含语言、单轮新闻数量、每频道扫描数量、“采集后自动制作”和“制作后直接发表百家号”。采集与制作是两个独立队列，各自串行，可以同时运行。采集只负责读取视频主题、检索完整新闻、去重和入库；完成后将已入库任务交给制作队列。制作、上传耗时或失败不会占用采集执行权，也不回写采集成功状态。未开启自动制作时，来源入库即完成采集。手动模式显示链接和比赛参数。运行时可修改频道，当前轮使用启动时的频道快照，修改在下一轮生效。设置支持显式开启定时采集、采集间隔、中文音色、语速和球场混音。定时默认关闭，定时采集只等待采集队列空闲。

页面分别显示采集队列、制作队列和待制作批次数，各自提供停止操作；停止排队中的制作批次仅撤销该范围。制作忙时可以启动下一轮采集，也可以将其他任务续做或上传请求加入制作队列。相同活动任务不能重复入队。停止采集保留入库记录，停止制作保留稿件、素材和上传检查点，不影响另一队列。

百家号显示 CBA 使用的同一账号，不另建账号库。上传状态与制作状态分别保存：已完成的成片遇到发表失败仍为已完成，可单独继续；同账号相同成片摘要已提交发表时不重复上传。结果未知只恢复原上传身份并核对回执，不创建替代任务。每次上传保存独立视频、16:9 与 3:4 封面版本；精确选择平台真实 `#NBA#` 话题并读回验证，不能用相近推荐或普通文本代替。简介为话题预留平台 50 字预算，原标题和正文保持不变。

新作品描述参考 CBA，使用 `YYYY-MM-DD NBA｜人物表现或新闻事件，双方与比分 #NBA#`，例如 `2026-11-02 NBA｜东契奇42分13助攻，湖人138-117热火 #NBA#`。日期只取已匹配比赛的当地日期，不能取新闻发布或采集日期；无有效比赛日期时保留人物事件描述。按平台 UTF-16 计数预留话题空间，优先保留完整分句、引语和比赛数据，不拆开引语拼接比分。描述展示在成片页的百家号发表区域。

新文案以 `publicationCopy` 绑定不可变上传清单；旧上传缺少此字段时仍按旧规则恢复。已经派发的旧上传继续原身份，同账号同成片已有提交回执时复用原回执。已发表作品的描述修改在同一作品 ID 上执行，单独保存平台读回证据和 `publishedDescriptionRevision`；原上传 payload、成片和账号绑定保留，不因更新描述重传视频。

编辑器的真实字数限制与话题数量分别读取，`1/10` 话题计数不作为描述上限。必选精确话题查询会在既有超时内等待当前候选，忽略上一次查询残留的暂时空列表，避免新查询还未发出就提前失败；仍须读回真正的 `#NBA#` 标签后才能发表。

发表时沿用平台创作声明填写与读回校验，AI 配音内容选择“含AI生成内容”。发表结果区分 `submitted`（已提交平台审核）和 `published`（平台确认已发表），草稿不再算作上传完成。历史草稿在原编辑页更新封面和话题后直接发表，保留原视频、账号、上传任务和作品 ID。发表前持久记录意图，提交结果未知时只读恢复；原地发表的旧草稿身份及封面修订证据单独留档。

## 数据与状态

共享 TypeScript 契约：`backend/src/services/nba-types.ts`。

- `Article` 保存完整正文、长度、来源、语言和正文哈希，以及可选 `topic` 视频主题。
- `Topic` 保存原视频编号、链接、频道、标题与描述，独立于可选的比赛身份。
- `Game` 保存比赛身份、主客队比分、时区与核验链接。
- `Media` 按比赛或原视频主题共享，保存下载文件、人声分离音轨、摘要、媒体参数及镜头结束点。
- `Job` 保存独立文章、中文译稿、媒体引用、交付与各阶段日志；旧审核字段仅兼容历史记录，不参与生产或上传判断。
- `Run` 保存采集、制作、续做或上传请求、频道快照、视频核验结果、来源报告、排除列表和任务队列。新批次标记 `queueVersion: 2`，采集 `collect` 与自动制作 `produce` 分别保存，通过 `productionRunId` / `collectionRunId` 关联。制作批次在可见入队前保存音色、混音及发表账号快照，启动新任务或修改默认账号不会替换排队任务的原配置。
- `Upload` 保存绑定账号、实际成片摘要、固定草稿 payload、上传恢复检查点与平台回执。API 不暴露本地上传素材路径。

频道独立配置在 `.channels.json`，视频采集记录在 `.channel-history.json`，其中 `searchedLanguages` 保存完成搜索的语言；旧记录通过关联文章语言推断。历史扫描进度在 `.channel-scan.json`，每轮优先查新再从 `nextIndex` 继续，历史区间保留少量重叠。完整描述和元数据在 `collections/<runId>/`。必须先落盘文章任务，再提交视频成功记录和扫描游标，避免中断后跳过尚未建档的文章。

### 全天运行

开启定时采集、自动制作、自动发表后，采集与制作队列独立推进。定时采集失败后按下一周期重新读取，不把失败采集加入制作队列。全天制作批次会先处理已有成片的发表检查点，每完成一条新成片就尝试发表，后续慢素材不会阻塞已完成视频。未知结果仍只恢复原发表身份。

已有制作任务的视频在新闻检索前直接跳过，不因历史语言搜索未完成或来源曾失败而反复占用新闻额度；优先继续扫描下一个新视频。尚未建任务的视频仍按中英文配置检索，允许临时失败后重试。

主题匹配要求新闻正文具有体育语境，避免把 Jelly 等重名词匹配到时尚内容。视频标题明确两队、新闻也明确对阵时，排除不同对手的战报；采访和专题仍不要求日期、比分或完整比赛记录。这属于素材相关性筛选，不审核新闻事实。

全天模式下，服务异常退出的制作队列会自动恢复；正常服务退出会保存重启恢复标记。明确手动停止的范围保持停止。制作及发表临时网络故障在原队列内最多追加三次延迟恢复，间隔为 1、5、15 分钟；确定性素材或内容问题保持待处理，不无限重试。运行期间可保存默认设置或关闭定时采集，已接受的制作配置和发表账号快照保持不变。

macOS 常驻服务通过 `node backend/scripts/install-nba-service.mjs` 安装为用户 LaunchAgent `com.huobao.nba-video`。支持 `--print` 预览和 `--write-only` 只写配置。服务登录时启动、崩溃重启，使用 `caffeinate -i` 防止空闲系统休眠，日志位于 `.logs/nba-video-service.log`；关闭网页不影响后台任务。电脑关机、退出登录、断网或合盖强制休眠时不能保证工作，恢复后按已保存队列继续。

生产阶段：采集 → 主题匹配 → 中文翻译 → 素材与分离 → 配音 → 字幕对齐 → 剪辑 → 交付核验。状态为排队、运行、已停止、待处理、失败、完成。停止使用取消信号并保留已完成检查点。重启后中断任务转为可续做，不能把残留 running 状态当作完成。有效缓存依据输入和文件摘要复用。翻译缓存标记为 `translation-only`；旧任务已有可用译稿时直接复用，原审核结论移入历史记录，不再调用审稿模型。

### YouTube 自动恢复

素材下载共用现有代理、Cookies 与 yt-dlp 配置，并明确使用当前 Node 运行时解析 YouTube。每轮使用权限为 `0600` 的临时 Cookies 副本，结束或刷新时清理。只读取描述时允许缺少可播放格式；实际下载必须取得真实画面和音轨，不能用元数据读取成功代替下载成功。

遇到 `Sign in to confirm you're not a bot` 等登录失效，自动从现有 Chrome 会话导出一次有效 YouTube Cookies，使用同一个比赛视频检测下载权限，再续传原下载。不会新建任务、重写已保存译稿或循环刷新。浏览器确实需要人工验证时，任务保留检查点并显示明确的 Chrome 操作提示。

下载优先选用 1080p H264、英文原声的 HLS 格式，保留原有分离画面与英文音轨格式作为回退。采用四分片并发、最多五次分片重试与有上限的指数退避；任何分片最终失败都中断下载并保留进度，禁止静默跳过缺片。下载单次最多 45 分钟，停止会终止下载及其合并子进程。

临时网络故障最多追加两次制作恢复，分别等待 5 秒、15 秒，并复用已保存的译稿、下载断点与共享素材。等待期间可以停止；登录验证仍失败、明确的 403/404、视频不可用及其他生产阶段不会进入此网络重试。下载结果按实际选中格式核验英文音轨，兼容 yt-dlp 在 `.info.json` 中省略 `requested_formats` 的情况。

若下载已经完成，但进程在写入共享清单前中断，会先发现该视频目录下的完整文件与元数据，重新核对视频编号、比赛、英文音轨、真实1080p媒体参数和来源时长，并计算实际文件摘要；无需再次访问 YouTube。该恢复只能建立未审核素材，仍须执行真实片尾与完整回合审核。编号错误、英文音轨未确认、路径越界或时长缺失均不能绕过检查。

## API

统一前缀 `/api/v1/nba-video`，返回 `{code,data,message}`。

| 方法与路径 | 行为 |
| --- | --- |
| GET `/` | 设置、任务、共享比赛、运行记录及统计；`activeCollection`、`activeProcessing` 和 `queuedProcessing` 分别表示独立队列状态，`activeRun` 保留兼容 |
| GET `/jobs/:id` | 完整任务、正文、稿件、核验及资产链接 |
| POST `/runs` | 默认 `{requestId,collectionMode:'channels',languages,limit,videosPerChannel?,autoProduce,autoUpload?}`；manual 模式可传 articleUrls/youtubeUrl/gameDate/espnEventId |
| POST `/resume` | `{requestId,jobIds}`，只续做指定任务 |
| POST `/uploads` | `{requestId,jobIds}`，串行直接发表或恢复所选成片；历史草稿原地更新并发表，账号与 CBA 共用 |
| POST `/runs/:id/stop` | 只停止指定采集、制作或排队范围，保留产物，不影响另一队列 |
| POST `/runs/:id/resume` | 恢复原制作或发表队列，沿用任务范围、配置、账号和自动发表选择，不重新采集；相同任务已有活动队列时返回冲突 |
| PUT `/channels` | `{youtubeChannels}`，可在运行期间保存，下一批生效 |
| PUT `/settings` | 保存采集、音色、混音与定时设置 |
| GET `/accounts` | 复用 CBA 百家号账号注册表 |
| PATCH `/jobs/:id` | `{youtubeUrl}`，给已有任务补充或替换比赛视频，保留稿件后续做 |
| DELETE `/jobs/:id` | `{expectedTitle}`，禁止删除活动任务，共享媒体保留 |
| GET `/jobs/:id/assets/:kind` | 注册产物的范围播放与下载；kind 为 video/cover/portraitCover/voice/subtitles/source |

写请求限制本机来源并校验 JSON；所有 ID 和媒体路径必须校验。启动与续做以 requestId 加输入摘要幂等，重复 ID 携带不同输入返回冲突。采集用 `.collection.lock`，制作与发表用 `.production.lock`，各自禁止跨进程并发执行。共享控制台通过短时 `.console.lock` 合并指定运行记录，避免采集和制作覆盖彼此的新状态。排队任务持久保存，服务启动和队列释放时自动接续；用户主动停止的范围不自动恢复。未知上传结果继续沿用原身份核对，既有防重复发表保护不变。

## 验收

1. 中英文长度筛选、全文提取、通讯社转载去重、比赛日期比分核验有针对性测试。
2. 频道发现、完整描述留档、已知跳过、失败重试、启动幂等、停止、重启恢复、只续做指定任务、共享媒体保留、资产越界及 Range 有服务和路由测试。
3. 英文原稿只调用一次翻译，中文原稿与有效译稿缓存不调用文本模型；历史审核失败不能阻止续做或上传。真实稿件可依次完成翻译、配音、字幕、分离与剪辑，交付检查包含解码、时长、片尾淡出及旁白停顿；缓存不能代替真实产物。
4. 导入本会话已经制作和核验的三条英文来源中文视频，明确标为既有产物。工作台真实播放这些视频，不放模拟任务。
5. 桌面与移动端浏览器核验任务选择、筛选、表单、原文、播放、下载及运行记录；提供可直接打开的工作台地址。
6. 百家号同账号直接发表、精确 `#NBA#` 话题、原草稿换封面发表、未知结果只读恢复、防重复，以及不影响已完成制作状态均有针对性验证；实际提交或发表结果记录在验收文档。

## 本地运行

主后端注册了 NBA 路由。开发时也可在 `backend` 运行 `npm run start:nba`，独立监听 `127.0.0.1:5684`，避免重启其他正在生产的流程。Nuxt 开发代理默认将 NBA 请求发到此端口，`NBA_API_TARGET` 可覆盖目标；页面地址为 `http://localhost:3013/nba-video`。同一数据目录的运行由生产锁互斥，禁止两进程同时制作。

复用应用设置中的文本模型与旁白音频服务。下载复用 `HISTORY_YOUTUBE_PROXY` 和 Cookies 配置；新闻可通过 `NBA_NEWS_PROXY` 单独指定代理。分离使用兼容的 Torch/Torchaudio Python 环境（`NBA_AUDIO_PYTHON`）及校验官方权重的缓存（`NBA_DEMUCS_CACHE`）。字幕使用本地 Whisper CLI 和模型，相关配置示例位于 `backend/.env.example`。

本会话已核验的历史产物可由 `backend` 中的 `node run-tsx.mjs scripts/nba-import-session.ts` 幂等导入。该命令核对原始正文、源视频、分离音轨和成片摘要，优先使用硬链接保留真实文件，不创建模拟成片；已存在的文章不重复建档。导入记录会明确显示“既有产物”。
