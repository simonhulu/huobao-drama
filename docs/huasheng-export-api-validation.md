## 参数来源

| 参数 | 来源与组装方式 |
| --- | --- |
| pid | 本地记录的花生项目 URL `/video/<pid>`；发送前核对来源稿件和当前版本。 |
| watermark / ai_watermark / aspect_ratio | 水印使用已验证的 `0 / 0`。生产实现先读取项目 info，核对公开编号 `project.pid`（不是旧字段 `project.id`），再使用项目自己的 `aspect_ratio`，不沿用示例比例。 |
| csrf | 当前花生域 Cookie `bili_jct`；POST 添加到查询参数。已实测与网站发出的参数一致。 |
| _ra | 官网会话校验 `/api/innovideo/attest` 返回的令牌，由官方前端缓存和刷新；不是 task_id，也不是手写请求体哈希。沿用真实会话，不复制用户粘贴的旧令牌。 |
| _bs | 官网客户端生成的浏览器环境标记；用户示例为 `c`，本次实际为 `wbh`，两者不能写死。 |
| _fv | 当前官网版本，来自 `_BiliGreyResult` / `_GreyResult` 的版本字段；本次为 `310404`，不应固定。 |
| Cookie | 当前已登录花生会话，限定花生域；只在请求内使用，不输出或写入日志。 |
| task_id / project_hash | 创建导出成功后，从服务端 `data` 读取并绑定对应 pid；不自行推算。 |

官网当前 `FetchInterceptor` 会给站内 fetch 补齐上述动态参数和 POST csrf。校验令牌有缓存和刷新逻辑。可以通过专用登录会话的正常请求取得当前参数，随后由 Node 组装 HTTP 请求；本次 Node POST 在断开 Puppeteer 连接后发送成功。这个验证不等于已实现完全脱离浏览器的登录和令牌刷新。

## 请求顺序

1. `POST https://www.huasheng.cn/api/v2/innovideo/project/export/video/task`，查询参数为当前 `_ra/_bs/_fv/csrf`，JSON 为项目自己的导出设置及 pid。
2. 要求业务码 `code === 0`，保存 `data.task_id`、`data.project_hash` 和 pid。本次 #61 返回 `pa5af24c2c66ad3d68729535499124dc2fec30041160784e324480ecf62aa53ca` 与 `a5af24c2c66ad3d68729535499124dc2fec30041160784e324480ecf62aa53ca`，与用户已有任务一致。不能仅凭这次结果推定所有重复 POST 都安全。
3. `GET https://www.huasheng.cn/api/v2/innovideo/project/export/video/info`，传入该任务的 pid、task_id、project_hash 和当前 `_ra/_bs/_fv`。
4. 只有 `code === 0`、`progress === 100` 且 url 非空，才进入下载。直接解析 JSON；其中的 `\u0026` 会自动还原为 `&`，无需字符串替换。
5. 使用返回 URL 下载。本次 Node GET 返回 HTTP 200、Content-Type `video/mp4`；传入 Referer `https://www.huasheng.cn/`，无需把账户 Cookie 发送给视频 CDN。URL 含有效期，过期时应重新查询接口获取有效地址。

官网编辑页的 fetch 包装层可能把成功响应拆成 `data`，丢失外层 `code`；本次浏览器侧通过原始网络响应核验业务码。独立 Node 请求得到完整 envelope，生产实现也应检查完整业务响应。
