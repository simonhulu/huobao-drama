## 自动化恢复与独立审核改造（2026-10-24）

工作台现按固定顺序执行：新闻建档 → 获取素材 → 编辑 → 独立审核 → 配音/渲染 → 成片验证 → 原账号草稿。新闻与编辑子执行器不能调用批准、配音和渲染；后端在独立审核通过后调用这些命令。已建档任务恢复时直接处理该任务，不重新遍历首页，也不因为其他任务文件发生变化而将其加入本轮。

`acquire-media` 先重验本地视频的 SHA256、音轨和时长；需要下载时，只尝试属于日期和双方球队均核实的官方赛事页回看列表的候选，最多三个。官方身份未证实、检索未找到、访问或解析失败分别记录。`media-acquisition.json` 与归档保存本轮实际命令、时间和结果；旧错误日志不能代替本轮尝试。`production.json` 保存各步骤开始、结束、失败和中断记录，恢复仍以真实成果验证为准。

新自动任务的审核绑定稿件摘要、原报道正文、每个入选镜头的真实切点和中间画面。独立 Codex 上下文检查原报道事件、事实归因、制作话术、资料标识、回合边界和画面对应关系；只写“通过”不足以开启配音。可修正问题最多改两轮；证据阻断或仍不通过时保留原因，工作台“文稿与来源”展示具体意见。后台恢复期间页面持续同步，草稿核对完成后自动更新。原有人工核验且摘要未变的成片保持兼容。

上传恢复在服务启动和本轮结束后自动运行，最多三轮。保存响应不明时读取原检查点并优先只读查证；只有原检查点明确允许，才能继续原上传或保存。排队后尚未派发的崩溃窗口也能接续，但当前成片须再次验证。冷却期或旧执行器尚存活时仍安排后续核对；用户明确停止的原任务不会自动重启上传。账号、素材和制作版本保持绑定；旧版本草稿保留原身份，不算新版本交付。平台只提示“保存成功”而未给出草稿身份时，继续只读查证，不再提前标为完成。

- 新编排核对浙江、北控现有四条成片，复用全部交付；两个原 `job.json` 均未变化，未调用配音或渲染。

## 标题规则与生产边界（2026-10-24）

现有标题来自编辑执行器对虎扑报道正文的概括，存入 `job.news.title` / `job.highlights.title`；百家号原先直接使用这些字段并在50字符处截断。视频号原先使用球队对阵加“赛后复盘/关键回合”的通用短标题。因此既没有统一日期/CBA，也不一定保留原新闻角度。

后续未交付任务采用 `profile.titlePolicy: source-date-cba-v1`：主新闻原标题精确取 `match.seedUrls[0]` 对应来源，移除栏目标签，结合正文轻微改写。两版完整标题均为 `YYYY-MM-DD CBA｜标题正文`，不超过50字符；视频号使用独立 `shortTitle`，含CBA且不超过16字符。规则在独立审核与付费配音前校验，上传使用已审核字段，不临时截断。格式检查不能证明标题忠实，人物、事件、比分和引语原意仍由独立编辑逐项核对。

日期只取核实的 `match.date`。本次天津、山东、辽宁三场均为2026-10-23；两个任务目录的24日以及新闻24日发稿，均不是比赛日期。示例（供后续编辑参考，未改写原有平台草稿）：

## 模型中断的恢复能力（2026-10-25）

本次仅诊断、修复和隔离测试，由用户手动启动真实生产验收。没有替用户恢复生产、生成真实旁白、渲染新成片或上传新草稿。

当前新增新闻无产出的直接证据：吉林任务 `2026-10-24-guangsha-jilin-news-643241167/production.json` 记录素材获取成功，随后编辑子执行器因请求频率限制失败，尚未进入独立审核、TTS 和渲染。最近运行 `run-9c140360-793d-4854-9d24-b708c0052cc8` 则在研究阶段遇到模型上游暂时不可用。此前咪咕球队别名缺失造成的漏检和研究中断阻挡已建档新闻生产，也已经修复。

这次对协调器补充的恢复行为：

- 研究、编辑和独立审核遇到并发限制、429 限流、502/503 或暂时断流时，最多尝试三次，默认等待10秒、20秒。认证、计费额度不足和普通编辑错误不自动重试；额度不足即使带429也不会当作临时限流。
- 每次尝试都写入运行记录的 `modelAttempts`，包含阶段、关联任务、开始/结束、结果、失败原因和计划重试时间。重试耗尽保留具体原因，仍可手动继续；服务中断后未完成的尝试标记为 `interrupted`，不自动重启生产。
- 研究子进程每次退出后先合并整份清单，再给重试指派未完成新闻，防止只回写部分行时丢失前次进度。部分研究失败仍可推进已建档新闻，其余保留待处理。
- 编辑中断后重新读取当前稿件；如果已保存的改动通过结构校验，则交给独立审核。未完成的改动按当前文件继续修正。审核每次重新核对当前证据包，并清除前次响应残片，防止误读旧审核结果。
- 等待重试期间点击停止会立即取消等待，不启动下一次子进程。整个退避期间仍占有运行名额，不能并发启动另一个生产器。编辑重试耗尽不会进入TTS或渲染。

## 单条失败后继续队列（2026-10-25）

原有循环只处理生产函数正常返回的失败，直接抛出的异常会落到整轮兜底并结束队列；研究阶段某组新闻重试耗尽也会提前返回，后续组没有执行。此次修复将失败限制在当前新闻任务或研究组内：

- 制作、成片校验出现异常时，保存该条真实失败阶段与原因，标为待处理，继续本轮下一条新闻。已经通过成片校验的任务在上传异常后保留有效成片和原上传检查点。
- 模型临时故障仍最多尝试三次。次数耗尽后继续后续任务，失败条目不在同一轮无限循环；单任务“继续生产”仍只处理所选任务，不自动扩大到未授权的旧批次。
- 研究组失败后保留已建档条目，将未完成条目标为 `needs_research` 并写入原因，然后继续后续组。整轮处理期间一直保留生产名额，直到队列结束才汇总为完成或部分待处理。
- 用户点击停止时不启动下一条；生产记录初始化异常也会释放本条协调器锁，保留原始损坏记录，避免后续恢复被旧锁阻挡。
