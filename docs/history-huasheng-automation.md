# 历史脚本 → 花生自动制作

> 2026-11-01 账号更新：历史页面各视图顶部均提供「花生账号」，使用历史专用登录和绑定的官网 UID，与科普账号隔离。面板可查看绑定身份、当前登录及最近核验结果，详见 [花生工作区账号](huasheng-workspace-accounts.md)。

> 2026-10-28 更新：手动及新二创自动制作均接入花生版 + 精细化版，按版独立交付并发表百家号，见 [现行流程](history-workflow-upgrade-20261028.md)。下文单花生入口和自动文章分支为旧版记录。

入口：`http://localhost:3013/history-scripts`。顶部是自动制作总览，每份稿件详情中有“送到花生制作”和该稿的任务记录。

## 使用流程

1. 点击顶部「花生账号」，在「登录窗口」中完成历史专用账号登录，再点击「检查账号」。绑定身份与当前登录一致、显示「已核验，可制作」后即可使用；检查成功会自动恢复通过当前稿版本校验的等待登录任务。登录保存在历史专用目录，后续复用；错号或与科普账号重复时停止操作，不覆盖原绑定。
2. “二创成功后自动制作”默认开启。后端在新二创稿成功保存后入队，不补交已有历史稿。已有稿件可从详情手动提交。
3. 后端依次输入已保存文稿、创建项目、选择 **A - 素材剪辑成片**、确认成片需求、选择“确认，开始制作”打开规划书，再“确认并继续”。
4. 花生进入视频编辑页，或最终确认后明确显示制作排队，任务才显示“已进入创作”。确认需求、生成规划书、本地等待提交都不算已开始。点击项目链接查看平台进度；这个状态不代表成片已经完成。“查看制作结果”也可能指向项目页面，不是 MP4 下载地址。

抖音素材沿用下载、语音转写、校对、二创流程；百家号文章在原文入库后直接校对、二创。两种来源都使用当前保存稿进入同一花生队列，文章不需要音频模型或下载器。

自动确认仅适用于 driver 能明确读取到总预估消耗为 0 的情形。消耗非零或无法读取时，任务显示“需要处理”及原因；到原项目确认后点击“恢复”，继续检测同一个项目。界面没有额外付费设置。

最终确认读取同一项目的实际响应，HTTP 200 不代表业务成功。业务码 `10008` 表示当日标准模式额度耗尽，保存为 `quota_waiting`、任务“需要处理”、制作状态“未开始”，保留原稿和规划书。用户选择继续保留标准模式，额度恢复后从原项目恢复；自动流程不点击“快速模式继续 / 使用快速模式加速”等付费按钮。

规划书未确认时仍可打开零消耗的“确认并继续”，但不能保证该动作一定获得免费排队资格。若平台拒绝，不重复发送最终确认；若返回成功，继续等待真正的算力排队或编辑页。响应不明也不当作成功或重复发送依据。本地 `confirm_pending` 只记录已尝试确认，不能代替平台状态。

自动制作开关仅控制新二创稿的自动入队。关闭后，已经接受的 `queued` / `running` 任务继续执行，仍可手动提交稿件或恢复已有任务。重新开启也不会补交历史存量。刷新、离开或关闭工作台不会取消后端任务；须保持后端进程可用。关闭网页与点击“取消任务”含义不同，取消也不撤销花生已经接收的制作指令。

## 批量自动生产

在“制作看板”逐项勾选任务，或点击“全选当前筛选中的已加载任务”，再点击“批量制作视频（N）”。没有花生链接、尚未开始的任务也可以选择。全选仅包括当前已加载且符合筛选的行，不包括隐藏行或尚未加载的任务。单次最多 100 项。

批量生产逐项核对当前保存稿件版本，然后串行启动所选任务；失败、等待登录、需要处理或已取消的任务从原项目及检查点恢复。已经运行、已进入花生排队、创作中和完成的任务跳过。创建结果不明且没有花生链接的任务须先绑定已有项目，避免重复创建。始终使用标准模式，额度不足时保留原项目并显示原因。

页面逐项显示接纳、跳过或未提交的原因；已接纳任务取消勾选，未提交任务保留勾选，可处理原因后再次提交，或使用“只选失败任务”。请求响应丢失时先刷新核对任务，不自动重发。接纳成功仅表示加入本次执行，仍需看到“排队中”或“创作中”才表示花生真正开始制作。

自动生产请求最多等待 30 秒，组件状态读取最多等待 15 秒；超时后结束等待、显示待核对或读取失败，恢复刷新入口，不自动重发生产请求。迟到响应不覆盖之后的任务状态。批量校验期间发生的取消优先保留，取消后的待执行任务可重新勾选恢复。

本次手动批量执行不依赖总 worker 开关，只处理所选任务，不启动其他存量任务，也不打开循环监测。关闭网页不会取消已接纳的后端执行；后端进程重启且总 worker 仍关闭时，重新勾选未完成任务继续，原项目和检查点保留。视频完成后的导出、下载及文章生成使用单独的“批量下载并生成文章（N）”。“制作视频”把保存稿送到花生；“下载并生成文章”处理已经制作完成的视频，并接续发布文案、封面方案和公众号文章。

## 批量检查创作状态

制作看板勾选项目后，可以点击“检查选中项目状态”，只检查勾选的具体花生任务；排队中、创作中、完成的项目都能选择，未关联花生链接的任务不能检查。空选不会触发全量检查，同一稿件的其他版本也不会被自动加入。原有“检查全部创作状态”和稿件详情的当前稿检查仍保留。检查在后台串行执行，同一个项目链接只检查一次，结果持久保存，页面会自动读取进度。单次检查不会开启循环监测，不创建新项目、不确认制作、不下载视频或发布。

稿件详情的“花生制作”页直接显示“检查当前稿创作状态”文字按钮。手动检查遇到专用浏览器未连接时，每批只尝试恢复一次连接：启动专用浏览器、复用已保存登录，再继续检查原项目；不会恢复制作队列。单项手动检查包含启动时间最多 90 秒。首页需等待账号信息加载，短暂出现“创建”或“登录”不直接判为登录失效；持续的登录提示才要求人工登录，加载超时显示连接未就绪。详情页的连接错误旁提供“打开登录窗口”，登录后可在同页再次检查。自动循环检查仍不负责重开浏览器。

勾选框由制作视频、状态检查与下载生成文章共用，旁边分别显示各动作的可处理数量。未关联花生链接的任务可以选择用于制作，但不能检查。已完成视频不需要再次制作；“批量下载并生成文章”可接续已有等待、导出、下载或生成中的同版本任务。“选择待下载项目”只选择当前筛选中视频已完成、后续尚未完成的任务。失败任务使用原任务的重试入口，导出提交结果不明时保留人工核对保护。搜索或切换筛选后，隐藏项目的勾选会清除。

2026-10-23 选中检查改动涉及 `frontend/app/components/HistoryHuasheng.vue`、后端 `routes/history-huasheng.ts` 与 `services/history-huasheng.ts` 及对应测试。前端真实本地页面使用 mock 接口回归 56 项、后端队列／路由／监测回归 54 项、类型检查通过；真实接口另验证空选拒绝、无匹配任务不触发全量检查。没有为本次测试打开实际花生项目，循环监测保持关闭。

制作看板底部可开启“循环监测”。开关和下次检查时间保存在后端，基础间隔为一轮结束后 60 秒；检查失败时按 2、4、8、10 分钟退避，成功后恢复基础间隔。只检查当前保存版本的未完成项目，跳过取消和完成的项目；不会恢复额度受限任务或切换模式。监测器本身只读取状态；启用下文的产物自动处理后，独立后台任务会接续完成项目的导出和下载。默认关闭，刷新、关闭网页不改变已保存的开关；后端须保持运行。多进程共享检查周期，不会因多个网页重复触发整轮检查。

## 自动导出、下载与生成产物

制作设置中的“视频完成后自动下载并生成文章”与循环监测独立，不会开启循环访问花生的状态检查。首次启用记录当前花生任务编号，仅自动接续之后新建、当前稿版本匹配且本地已确认制作完成的任务。已有项目通过“选择待下载项目”和“批量下载并生成文章”处理；重新开启开关不会清除首次启用范围。关闭自动开关停止新任务入队，已接纳任务继续执行。

自动开关控制接纳范围，后台进程负责实际执行，两者分别显示。界面通过进程心跳显示自动处理是否运行，进程停止时可以手动继续已有任务。手动接纳会直接执行所选任务，不依赖通用任务 worker；自动处理则由独立导出进程持续消费本地已完成的记录。尚未完成的视频只等待本地状态更新，不自行打开花生检查；需要时手动“检查选中项目状态”。

历史产物生产使用全局 **2 个项目**的并发上限，API 与独立 worker 通过 SQLite 事务共享名额，不是每个进程各自运行两个。从开始导出、下载，到标题／简介／封面方案和公众号文章两条分支全部结束，原项目持续占位；一次状态读取或队列步骤返回不会释放名额。其余已接纳项目显示“等待生产名额”，完成或明确失败后再接续下一项。尚未制作完成、等待登录及需要人工处理的项目不占住后续生产名额。

手动生成标题方案、公众号文章以及手动关联视频后的文章任务也共用这两个项目名额；同一稿件的多个生成分支只算一个项目。文章队列优先完成已经占位的项目，避免未获名额的队首任务挡住它们。项目名额保留在数据库，worker 重启会接续原项目；实际生成分支以进程存活和结束释放保护，进程退出后清理遗留名额。等待名额期间不调用模型，也不消耗文章模型执行超时。界面展示“生产并发：正在生产 N/2 · 等待 M”，满额仍允许批量提交排队。

此限制针对本地下载与产物生产，不限制状态检查，不修改花生平台自身的制作队列，也不把检查频率当作生产并发。它控制同时生产的项目数，并不承诺供应商的请求数／token 配额永远不会触发。

自动流程依次执行：等待花生允许导出 → 创建导出任务 → 轮询导出进度 → 下载并校验 MP4 → 关联当前稿件 → 独立生成发布文案与封面方案、公众号文章。花生四种制作状态保持不变，产物处理额外展示导出百分比、下载字节和两条生成分支的状态。“封面方案完成”不是封面图片完成，本流程不调用封面生图或平台上传。

公众号以完整校对原文为内容来源，在同一次模型调用中生成独立文章标题和正文，不沿用视频的主持话术或平台包装；标题换行自动合并，缺失或非文字标题回退到已清理的来源标题，不因此丢弃正文或重复调用。没有新增篇幅限制或审核关卡。产物入口会读取最新结果，保留尚未保存的稿件和发布文案；人工点击生成方案时，在成功结果返回前也保留原编辑内容。外部标题参考检索属于可选增强：关键词提取、搜索或标题改写不可用时，自动切换为基于当前原文和原题的可编辑标题，继续生成简介与封面方案，不因检索失败阻断产出。

认证复用花生专用浏览器的真实登录会话，由官网正常请求取得 `_ra/_bs/_fv` 和 Cookie 中的 csrf。认证信息仅缓存于内存；Node 使用接口进行创建和轮询，不点击“下载成片”，不固定项目画幅、会话令牌或前端版本。登录或浏览器不可用时任务进入等待登录，每分钟再检查，原任务编号保留；已关联视频的本地文案和文章任务继续运行。

导出接纳前核对当前稿 SHA256、花生项目链接与实际 `project.pid`，并读取实际 `aspect_ratio`。创建前持久记录发送意图，收到成功响应后保存 `task_id/project_hash`。只有业务码成功、进度 100 且下载地址有效才下载；HTTP 200 本身不代表成功。明确的登录拒绝可在会话恢复后继续；创建响应丢失或编号不明时不自动重发，显示具体原因供原项目核对。

成片先写入 `data/huasheng-exports/<pid>/video_<projectHash>.mp4.part`。支持服务器 Range 续传，服务器不支持时重下该文件；URL 过期时查询原导出任务取新地址。下载字节数和媒体检查通过才改名为 `.mp4`，随后复用成片关联接口。已有完整下载会复用，已关联且版本匹配的视频也会直接复用。不会覆盖人工上传的其他版本、失效关联或后来保存的稿件。

任务每一步落库，进程退出后由新进程接管原任务；多进程以数据库执行权和存活进程标记防止重复提交。网络查询、下载可有限重试，失败项目不阻塞其他项目。发布方案和文章独立完成，明确重试只处理失败分支。已有有效文案、文章和人工修改得到保留；手工内容未写完时提示补齐，补齐后点击“继续处理”核对现有结果。模型调用结果不明时先保留现场，不通过无限重试重复调用模型。

手动执行队列遇到临时数据库异常时保留选择并有限重试；持续失败显示“需要处理”，从原导出编号恢复。并发步骤全部结束后才释放执行锁；本进程已结束步骤遗留的执行权也可恢复，避免进程还活着却永久占住任务。

新增 API 前缀 `/api/v1/history-scripts`：

| 方法与路径 | 请求 | 用途 |
| --- | --- | --- |
| `GET /huasheng/exports` | 可选 `sourceId` | 自动开关、任务状态、`worker.status/message` 和全局 `production.limit/activeProjects/waitingProjects`；不返回会话凭据或签名下载地址 |
| `PUT /huasheng/exports/settings` | `{ "enabled": true }` | 新项目自动处理，与循环监测独立 |
| `POST /huasheng/exports` | `{ "sourceIds": [61, 62] }` | 幂等接纳或继续所选已有活动任务，直接执行所选步骤，返回 HTTP 202 |
| `POST /huasheng/exports/:id/resume` | `{}` | 从失败步骤或修复后的待处理状态继续，保留成功产物 |

数据表为 `history_huasheng_export_settings`、`history_huasheng_export_jobs` 和 `history_delivery_design_intents`，后端启动只恢复已接纳任务。`HISTORY_HUASHENG_EXPORT_WORKER_DISABLED=1` 可停用产物队列 worker。接口实测与参数依据见 [花生导出接口实测](huasheng-export-api-validation.md)。

| 创作状态 | 判定依据 |
| --- | --- |
| 未开始 | 尚无花生项目，或项目仍处于需求、方案阶段 |
| 排队中 | 最终制作确认后的花生项目显示算力调度排队；生成规划书的排队不计入 |
| 创作中 | 已进入视频编辑页，但成片暂不可导出 |
| 完成 | 打开“导出发布”窗口后，“下载成片”可用 |

“等待提交花生”是本地自动化任务的状态，不等于花生“排队中”。“已进入创作”是自动化已完成交接；四种创作状态独立显示，附带检查时间。尚未检查的项目会标明尚无检查结果。登录过期、页面加载失败或导出窗口无响应时保留上次结果并显示检查失败；正在自动操作的项目稍后再检查，避免检查与提交争用原项目。

检查确认项目已排队、创作中或完成时，同一事务将本地交接状态和检查点收敛为 `submitted`，清除已过期的额度不足、等待登录等创建阻塞，最新消息使用此次平台检查结果。恢复接口因此不会把已交接项目重新送入创建队列。启动时也会修复已经保存的矛盾记录，不重新打开花生：仅使用不早于任务最后更新时间的成功检查，保留后续出现的错误、检查失败、运行中的任务及取消意图。下载、文章等产物任务仍独立显示自身状态和失败原因。

平台提示“本地内容可能不是最新的”时，自动化会通过“刷新对话”同步原项目，然后继续核验。刷新保留已确认的步骤，不重复提交文稿和制作指令；连续无法同步会显示需要处理。

方案选择的 `scheme_pending` 只表示已记录选择意图，不表示花生已经收到回复。点击前显示“正在选择，等待花生对话确认”；只读取对应选择卡片中的用户回复，不把按钮文字或正文里的 A 方案字样当作回复。回复连续显示五秒后仍仅显示“页面显示回复，继续等待成片需求”，不提前宣布制作成功。

同一原项目中，如果 A/B 均仍可点击、没有对应回复且对话未处于失同步状态，选择 A 可间隔至少十五秒重试；每次任务执行最多尝试三次。临时回复回滚后重新按未选择处理。超过尝试次数或等待两分钟仍无后续需求时明确转为需要处理，不再占住整条队列等待三十分钟。

成片需求的 `requirements_pending` 同样只表示待确认。仅当需求卡片中的“确认 / 需要修改”仍可用、没有用户“确认”回复时，按同样的十五秒间隔、每次执行最多三次恢复需求确认；已显示回复或进入后续规划书时不重复发送。临时回复回滚也会重新核验。上述恢复仅适用于方案选择及成片需求确认，不重复创建项目或重复最终制作确认。

当前页的乐观回复可能长期显示但未保存。方案或成片需求阶段停滞四十五秒后，重新载入原项目核验；一次执行最多两次，间隔至少四十五秒，不延长原步骤截止时间。重新载入后仍有回复则继续等待；明确恢复成未回答卡片时才允许有限重试。最终制作确认不适用此恢复重试。

## 稿件与恢复边界

- 只提交已保存、非空且来源版本有效的当前二创稿。未保存修改、正在处理、过期稿或版本冲突会禁用提交。
- 提交前重新读取稿件，核对保存版本和正文。任务通过正文 SHA-256 区分版本；已有同版本任务时不重复创建，可按状态恢复。后端仍负责最终版本校验和幂等。
- 已有其他版本任务明确标为“其他已保存版本”；详情不提供恢复旧版本任务的入口。当前稿存在未保存修改时，总览里该稿的恢复入口也禁用。
- `waiting_login`：完成登录后点击“检测连接”；检测为 `ready` 时，后端自动恢复通过当前稿版本校验的任务。版本不符的任务会转为“需要处理”并显示原因。`needs_attention` / `failed`：先处理消息指出的问题，再恢复。`canceled`：可恢复已保存的同版本任务。
- 当任务没有项目链接、状态是 `needs_attention` 或 `failed`，且 `stage` 或 `checkpoint` 为 `create_pending`，表示创建结果不明。展开“绑定已有花生项目”，先到花生“我的项目”核对当前稿件，再填写 `https://www.huasheng.cn/video/数字编号`，点击“绑定并恢复”。不要为了恢复而新建重复项目。
- `queued` / `running` / `waiting_login` / `needs_attention` 提供取消；停止中的任务等待后端退出操作。`submitted` 不提供恢复或取消。

## 前后端接口

统一前缀：`/api/v1/history-scripts`。组件使用现有 `api` 客户端，不修改 `useApi.ts`。

| 方法与路径 | 请求 | 结果 |
| --- | --- | --- |
| `GET /huasheng` | 无 | `{ enabled, monitoring, browser, jobs, productionChecking }` |
| `PUT /huasheng/settings` | `{ enabled: boolean }` | 保存开关 |
| `PUT /huasheng/monitoring` | `{ enabled: boolean }` | 保存循环监测开关，返回 `{ enabled, intervalMs, lastCheckedAt, nextCheckAt }` |
| `POST /huasheng/browser/open` | `{}` | 浏览器连接状态 |
| `POST /huasheng/browser/check` | `{}` | 浏览器检测状态；`ready` 时自动恢复有效的等待登录任务 |
| `POST /huasheng/produce` | `{ jobIds: number[] }`（1 至 100 个） | `202 { results }`，逐项接纳、跳过或阻塞，只串行执行本次选中任务；空数组拒绝 |
| `POST /huasheng/check-production` | 全部：`{}`；选中：`{ jobIds: number[] }`（1 至 100 个） | `202 { checking: boolean }`，异步检查全部或选定的具体任务；空数组拒绝，不回退到全部 |
| `GET /:id/huasheng` | 无 | `{ jobs, productionChecking }` |
| `POST /:id/huasheng` | `{}` | 创建或返回同版本任务 |
| `POST /:id/huasheng/check-production` | `{}` | `202 { checking: boolean }`，异步检查当前稿项目 |
| `POST /huasheng/jobs/:jobId/resume` | 通常 `{}`；仅创建结果不明时 `{ projectUrl }` | 恢复原任务 |
| `POST /huasheng/jobs/:jobId/cancel` | `{}` | 请求停止任务 |

实际路由的浏览器操作返回 `{ browser }`，任务操作返回 `{ job }`，外层遵循项目 `{ code, data }` 响应结构。前端同时兼容直接返回浏览器状态的合同形式。任务编号支持数字或字符串。

每个挂载面板在上次请求结束后等待 5 秒再查询；顶部只查询总览，详情只查询当前稿件。读取与动作串行，不重叠同一面板的请求；动作完成或响应丢失后均重新读取状态，不自动重发写操作。卸载清理计时器，忽略迟到结果，不发送取消请求。连接失败会显示错误，并防止旧的“已就绪”状态覆盖最近一次失败。

## 独立产物 Worker 部署

`backend/scripts/huasheng/export-worker.ts` 仅启动花生导出队列和公众号文章队列，不启动 API、素材采集、花生制作、上传队列或循环制作状态监测。可与正在生产的主 API 共用数据库，无需重启主进程。文章队列只消费已有或新产生的成片关联待办，失败文章不因启动自动重试，也不补建历史文章任务。

独立入口直接调用 `getHistoryHuashengExportService().start()` 和 `getHistoryArticleQueueService().start()`，因此 `TASK_WORKER_DISABLED=1` 及主服务的专用 worker 禁用变量不阻止此入口。它不修改自动导出、制作或监测开关。本地状态尚未完成的花生项目不会被它自动打开检查；先在制作看板勾选项目检查状态，确认完成后再接续导出。已有导出、下载和文章检查点由对应队列恢复。

自动导出仍沿用数据库中的开关与首次启用水位，只接纳范围内、本地创作状态为 `completed` 的当前稿项目；存量项目使用看板的所选项目产物操作。导出接口仍需要有效的花生专用浏览器登录会话，读取授权可能短暂打开会话页。公众号生成使用现有模型配置、关联视频和本地图片准备工具，不打开浏览器。

使用 `backend/scripts/huasheng/export-worker-service.mjs` 管理当前用户的 LaunchAgent。服务名为 `cn.huobao.history-huasheng-export`，配置文件在 `~/Library/LaunchAgents/cn.huobao.history-huasheng-export.plist`。安装会立即启动，并在此用户下次登录 macOS 桌面时自动启动。根据本机 `launchd.plist(5)` 和 `launchctl(1)`，显式设置 `RunAtLoad=true`、无条件 `KeepAlive=true`、`ThrottleInterval=30`；正常退出和异常退出都会恢复，频繁退出会节流。用户退出登录或系统睡眠期间不保证执行。
