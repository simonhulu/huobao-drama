# 科普制作流程升级：远程 MuseTalk

## 部署位置

正式科普程序运行在 macOS 主机 `192.168.0.107`，使用 `mac` 账户通过 SSH 登录维护：
`ssh mac@192.168.0.107`。项目目录为 `/Volumes/wd3/huobao-drama`，
`/Users/mac/huobao-drama` 是该目录的软链接。
RTX 3090 运行 MuseTalk 和原有写作服务，是另一台 GPU 主机。
本工作区的样片和检查不能替代另一台电脑上的更新、重启与验证。
运行科普程序的电脑无需安装 PyTorch、MuseTalk 或 CUDA。

局域网工作台地址为 `http://192.168.0.107:3013`。107 的
`/Users/mac/huobao-migration/start-huobao.mjs` 使用 `--host 0.0.0.0`
启动前端，并为前端设置 `WORKSPACE_PUBLIC_ORIGIN=http://192.168.0.107:3013`。
该来源的同源 API 请求通过前端代理转发；后端继续监听 `127.0.0.1:5679`。
调整 IP 或端口时同步修改该环境变量并重启前端。账号登录窗口仍在 107 桌面打开。

远程配置与参考视频保留在 3090；客户端只提交当前正文的音频。
客户端复用 `.env` 中已有的 `LATENTSYNC_SSH_*`，也支持独立的
`MUSETALK_SSH_*`。密码不进入代码、配置示例、日志或更新包。

## 自动制作

1. 独立采集队列保存来源，发送至制作队列。
2. 远程写作模型改写原稿，保留原意、推进与逻辑，去除原作者自我介绍。
3. 华生使用“音色小鹭” `1595608` 制作正文；固定自我介绍不加入正文。
4. 正文下载后，提取音频，调用远程 MuseTalk 1.5，复用缓存主播素材。
5. 原片头播放后缩入右下角，与正文同步主播圆窗衔接，保留正文原声。
6. 完成封面与原有后续交付。

口型服务默认最多等待 10 分钟。超时或服务失败会记录原因，自动完成仅片头版本。
用户主动停止任务时不触发降级、合成或上传。旧 LatentSync 不参与默认生产。

## 导出恢复

已绑定的原导出连续 5 分钟没有进展时（包括非 0% 和 100% 但下载地址尚未就绪），
程序重新核对原稿、音色和制作状态，最多重新触发一次原项目导出，
并要求返回相同任务编号和版本。每次进度变化都会更新持久化的停滞计时，
普通轮询和服务重启不会重置计时；旧的 0% 计时记录仍兼容。
重试发送标记和计时保存在任务中，重启或继续操作不会重复发送结果未知的请求；
平台明确拒绝的请求不消耗此次重试。进度持续变化的导出继续查询，不重复创建。
90 分钟查询总期限也绑定原导出并持久化，不因重启或继续操作而重置。
超时后仍先查询原任务，若成片已经完成则可以下载。

## 合成与上传进度

视频合成从 FFmpeg 的 `-progress` 协议读取实际处理时长和速率，
通过任务的 `compositionProgress` 返回百分比、处理时长、总时长和最后进展时间。
结构化进度最多每 5 秒更新一次，相同处理时长不刷新最后进展时间；
文字日志最多每 30 秒记录一次，阶段结束除外。
输出校验及原子落盘完成前最多显示 99%，缓存复用不虚构编码进度。

上传保留原有 `uploadStatus` 枚举，通过 `uploadProgress` 区分账号连接、
登录检查、页面准备、视频上传转码、封面确认、发表及回执核验。
重复的相同步骤提示不刷新最后进展时间，暂停或完成后不展示旧的进行中进度。

可选话题搜索在原有最多 10 秒预算内等待候选，避免旧的空列表造成提前跳过。
确实未选中时，将原因保存在 `uploadWarnings` 并在提交成功后继续展示。
原有可选话题策略不变；使用 `required-exact` 的必选话题仍须精确选中才能发表。

2026-11-09 验证：工作流、上传恢复及桥接定向回归 169 项、视频合成 30 项、
Python 话题与发表/封面回归 45 项通过；前端控制器 48 项及桌面、手机进度场景通过，
后端类型检查通过。
扩大检查时发现原提交 `c5cc646` 已有 6 条上传旧测试失败、1 条等待重传的测试超时，
它们仍要求结果未知时创建新上传任务，与现有防重复发表策略矛盾；上述 169 项排除了这 7 条。
`test_checkpoint` 中既有的浏览器清理模拟失败也已在原提交复现，本轮未扩大修改这些测试。

## 107 编码适配

107 是 Intel Iris 6100、macOS 12.7.6 的 MacBookPro12,1。
2026-11-09 实机确认：1080p VideoToolbox 支持码率控制，但拒绝 `-q:v`；
共享编码参数仅在 Apple Silicon 上保留此质量选项，Intel 使用 `-b:v` 等码率参数。
两路并发的 1080p 硬件编码已通过。

该机 360×360、384×384 的硬件编码会话创建失败，而 512×512、640×360、
640×480、720×720 编码成功。当前 360×360 主播继续使用两线程 libx264，
不为硬件编码而放大素材；全尺寸合成优先使用适配后的硬件参数，失败时沿用软件回退。

正文圆窗的静态遮罩和白边只计算一帧，由 framesync 复用；主播画面继续逐帧播放。
叠加阶段保持 YUV，避免两层叠加导致全尺寸正文反复转换 RGB。
仅片头末尾的短暂缩移动效使用最高 360p 的临时画布再放回原尺寸；
静止片头、完整正文、最终主播圆窗和输出分辨率不因此降低。
超时或被强制结束的编码不再从头切换到软件重跑；编码器正常返回不兼容错误时仍可软件回退。

2026-11-09，107 使用真实素材测试：30 秒正文加 5.05 秒片头，1080p/30 FPS、
VideoToolbox 编码、正文同步圆窗和原声，完整合成用时 92.216 秒。
此数值是短片实测，不包含采集、写作、平台制作、口型推理、封面或上传，不能直接当作长片耗时。

## 另一台电脑的配置

代码改动先提交并推送 Git，再 SSH 登录 `192.168.0.107` 检查项目分支和
未提交改动，通过 Git 同步并按原启动方式重启后端。不能把仅提供更新压缩包
当作完成远端升级。两边的代码提交应保持一致；若远端有独立改动，先保留并合并，
不使用 `reset --hard` 或覆盖工作区的方式强制同步。

保留那台电脑自己的 `.env`、数据库、账号会话和任务素材，不用本机文件覆盖它们。
项目技能随 Git 同步；安装在用户目录的个人技能另行同步定义、脚本和参考资料，
保留远端独有内容，备份冲突文件，并处理跨用户目录的软链接。无需复制 Codex
登录状态、密钥、MCP 凭据、插件缓存或 `node_modules`。

在该电脑的 `backend/.env` 中配置：

```dotenv
SCIENCE_PRESENTER_MODE=musetalk
MUSETALK_REMOTE_PORT=8789
MUSETALK_TIMEOUT_MS=600000
LATENTSYNC_SSH_HOST=hz01-ssh.gpuhome.cc
LATENTSYNC_SSH_PORT=30163
LATENTSYNC_SSH_USER=root
```

继续使用已有的 `LATENTSYNC_SSH_PASSWORD`，或配置该电脑上的 SSH 密钥路径。
也可以手动建立端口转发并设置 `MUSETALK_API_URL=http://127.0.0.1:8789`。
明确指定本地 API 地址时，后端不再自行建立隧道。

macOS 支持环境变量密码自动转发，无需手工保持隧道。
如需要手动调试，可以执行以下命令并在终端完成 SSH 登录，
再设置上述 `MUSETALK_API_URL`：

```sh
ssh -N -T -L 127.0.0.1:8789:127.0.0.1:8789 -p 30163 root@hz01-ssh.gpuhome.cc
```

该电脑需要已有的 Node、FFmpeg/ffprobe、OpenSSH，以及固定片头：
`data/science-pop/assets/xiaolu-intro.mp4`。
如片头存放在别处，使用 `SCIENCE_INTRO_VIDEO_PATH` 指向该电脑上的文件。
不要填写 `/Users/zhangshijie/Downloads/...` 等本机专属路径。

设置 `SCIENCE_PRESENTER_MODE=none` 可以明确切回仅片头流程。
更新并重启另一台电脑的科普后端后，以一个新任务验证日志中的远程 MuseTalk、
固定片头、过渡、正文圆窗及实际成片。已提交的平台作品不自动替换。
