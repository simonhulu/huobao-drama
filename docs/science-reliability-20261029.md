## 已证实的原因

| 表现 | 原因与修复 |
| --- | --- |
| `Text model request failed: 502` | 上游文本模型暂时不可用，原分析/写作没有有限重试。现在分别最多尝试 4 次，2/4/8 秒退避，并遵守有上限的 Retry-After。已完成分析立即持久化；认证、配置、解析和稿件校验错误不重试。继续使用 `gpt-6.1-terra`。 |
| 花生接口连接中断 | 单次网络错误曾直接终止流程。现在对状态查询和下载进行有限重试；下载前重新查询原导出任务以刷新地址，并继续原 `.part`。请求已经派发但回执不明时不重发创建导出的 POST。 |
| 导出窗口未响应 | 旧实现以页面弹窗可用性判断制作完成，且原后端没有 watch，部分旧修复未进入运行服务。现在核验原项目全文、制作阶段和分镜状态后，直接使用项目与导出 API；修复后实际重启服务并确认健康接口。 |
| `Performance.enable timed out` | 浏览器连接通过 `browser.pages()` 初始化全部历史页面，使无关旧页面也进入协议初始化。现在先用 target 元数据找对应页面，仅初始化所需页面；连接和准备有限重试，失败时只清理本次临时页。 |
| 已停止本机执行 | 这是检查点保留后的暂停，原界面却与故障共用“需要处理”。现在任务有独立 `paused` 状态，兼容投影旧的停止记录。停止会取消等待、查询和重试，不清除素材与远端任务。 |
| 木瓜确认后连接中断 | 本次真实恢复发现：确认已被平台接收且成片完成，本机随后报告浏览器中断。正式 API 已核验原稿全文、25 个就绪分镜和完成阶段；编辑器中的原稿全文可能不再可见。现在确认后的连接/超时会先用 API 核对已保存的原项目；只有明确已开始才继续，绝不重放确认。底层原异常被旧适配层统一替换，现有日志无法确定具体是哪一次 DOM 操作超时。 |
| 确认后误报“尚未开始制作” | 实测 v2 `project_stage=0` 与 `composite_running=true` 同时出现，29 个分镜中部分尚未完成；原实现过早按阶段 0 返回未开始。现在先判断排队和正在生成，空闲阶段 0 才判未开始。对已保存 `submitted` 的任务，即使阶段尚未同步也只读等待原项目，不重新进入浏览器确认流程；完成仍要求阶段、进度、无运行任务和全部就绪分镜同时满足。 |

批次层新增独立的重试范围，即使原产出目标已经达到，仍可恢复全部或选定的未完成任务。该范围持久保存，停止或重启后继续相同范围。临时故障重试耗尽会暂停批次，避免故障传播到后续任务。批次完成数从实际文稿、视频或草稿结果同步。

## 防重复与验证

- 制作前后绑定原账号、完整文稿和项目 URL；恢复不替换已有项目。
- 已知导出任务始终复用原任务编号和项目版本；未知回执保留待核验状态。
- 页面确认后仅进行只读状态核对，未开始、文稿不匹配或无法核验时不自动重放提交。
- 未完成转写的原视频经过既有下载器校验，修复缺失哈希或不完整缓存；成功转写分段继续复用。
- 回归覆盖模型暂时失败、永久错误、取消、浏览器准备失败、下载地址刷新、原项目恢复、确认后断线、已提交但阶段暂未同步、批次固定恢复范围和上传取消。最终 workflow 测试 35 项、API 测试 23 项通过；其他模型、浏览器、批次和前端相关回归通过，后端类型检查通过。

真实产物使用 ffprobe 检查视频、音频、时长和尺寸；逐条请求本地视频 Range 并要求 HTTP 206，同时比对修复前的原项目、原导出编号、文稿哈希和源视频哈希。工作台另做实际播放器检查。
