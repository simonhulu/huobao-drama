## 采集临时媒体清理

抖音来源的完整转录成功保存到数据库后，立即删除该来源的 `source.mp4`、分段 `audio-*.wav` 及对应未完成文件，并通过本机下载器的 `/api/v1/archive/delete` 同步释放同一来源的视频缓存。保留原始链接、来源信息、转录文字和哈希检查点；校对或二创失败后重试直接复用完整转录，不重新下载或付费转写。未完成的转录保留媒体和分段结果，以便断点续跑。CZGTS 文章不下载视频，无需此清理。

只清理来源专用目录中的规范临时文件，不扫描或删除花生成片、手动关联视频、封面和文章配图。清理与处理共用来源锁；下载器暂不可用时记录 `media.cleanup.error`，不阻塞已完成的转录或二创，下次处理或维护命令可重试。来源页显示“转录已保存，来源视频已清理”，并可通过“查看原视频”访问来源。

抖音图文保留规范命名的来源图片和原链接，供来源页查看。图片下载、识别结果分段保存；正文完整保存后释放下载器缓存，识别或二创失败重试时复用已保存阶段，不进行视频下载或 ASR。本机 OCR 使用 macOS Vision，需要 Xcode Command Line Tools；工具不可用时明确提示修复后重试，已下载图片和已识别结果保留。

图文下载先检查下载器归档；不存在时提交异步 `/api/v1/parse`，保存并轮询原解析任务，确认归档后再提交下载，兼容要求先归档的下载器 worker。解析超时、取消或查询中断后继续使用原任务检查点；明确失败后允许重试，不把“未归档”误报为图片已下载。2026-10-24 以有效图文 `7660509302743290218` 实测解析、下载 1 张图片和 Vision OCR 全部成功，提取正文及图中文字 155 字符；该样本仅用于接口验证，因点赞低于入选门槛，未写入生产稿件库。

已有完整转录的来源可在 `backend/` 执行一次维护清理；带 ID 时仅处理单稿。命令输出释放字节数、清理/跳过数量及待重试原因，不调用模型或启动新采集。

```bash
node --import tsx scripts/history-sources/run.ts cleanup-media
node --import tsx scripts/history-sources/run.ts cleanup-media 72
```

## 如何启动下一轮

### 停止采集

采集排队或运行期间，页面右上角显示“停止采集”；制作看板同样可用。“采集监控”窗口内和采集任务列表的当前任务行也提供停止入口，查看历史日志不会改变要停止的当前任务。

点击后显示“停止中”，执行器会中止当前浏览、下载、转录或文本处理，确认退出后显示“已停止”。未领取的排队任务直接取消，不等待工作进程；已完成稿件和当前来源的检查点保留。停止请求失败会恢复可重试操作并显示错误，重复停止不会创建新任务。

### 历史任务与筛选日志

在“采集监控 → 任务日志”选择任务编号、日期和状态，可查看更早任务并继续加载更早日志。顶部启动/停止按钮始终控制当前任务；查看旧任务不会切换控制目标，实时刷新也不会把固定查看的历史任务顶回最新。日志支持对已加载记录搜索和按级别筛选，显示加载数量，保留完整时间、阶段、累计扫描/入选/入库数及安全的来源链接。任务和业务事件使用独立游标分页，不再限制只能查看最近5个任务、最近100条日志；旧日志按当时已保存的证据展示，不补造当时没有记录的理由。

新日志区分“搜索页初筛”和“详情核验”，并标记“正在判断”“已入选”“已跳过”。候选详情保留当次读取的标题、点赞数、评论总数和入选/跳过理由；未读取的指标不填零。旧日志中的时长、评论样本、标题依据和观众问题按当时证据保留，不作为当前入选要求。后续下载或改写日志不会继承上个候选的证据。页面读取失败时保留最初的失败步骤及安全归类的原因，避免清理标签页错误覆盖原始异常；此改动不保证抖音页面不会跳转或断开。

### 启动操作

默认优先使用抖音视频和图文来源，启动时按需检测登录和普通搜索结果。需要文章素材时，在启动弹窗切换为“百家号文章（czgts.cn）”。历史任务重试沿用原始来源、关键词和数量配置，但执行当前采集规则。

搜索未就绪或采集失败时，顶部任务条、采集任务列表和失败详情均可点击“重试采集”。重试使用失败任务保存的来源、关键词、目标数量（包括持续模式）或文章时间范围；旧任务的分类字段仅兼容保留，不参与当前入选判断。重试创建新的执行记录，保留旧任务日志。抖音重试先运行真实搜索检测，通过才提交；若要求登录或安全验证，会转到连接检测，在专用窗口处理后重试。已入库来源继续按数据库去重，不重复采集。检测或提交失败后按钮恢复，可再次重试；并发请求仍由后端活动任务幂等保护。

搜索就绪要求正确搜索词、非加载中的稳定视频或图文卡片，或明确的结果结束提示。不打开筛选面板、不点击时长、形式或时间选项，也不要求顶部“视频”分类被选中。搜索异常给出实际加载或登录原因及重试入口。模型 HTTP 429 显示并发已满或限流，不归类为抖音登录故障。

首次使用时，在“历史脚本”的“采集监控”连接页打开专用采集浏览器，完成抖音登录。随后点击“启动采集”，选择“按数量采集”（默认 1，支持 1–9999，包括两位数）或“持续采集”，确认并保存采集关键词后启动，无需选择历史类型或搜索筛选条件。已有新鲜检测结果时直接提交任务；未检测或结果过期时，启动流程自动运行普通视频与图文搜索检测，通过后再提交，无需用户反复点击检测按钮。检测失败会显示具体步骤及原因；实际需要登录或安全验证时，在同一专用窗口处理。“检测登录状态”按钮保留为手动诊断入口。持续模式没有总数量或总运行时长上限，单篇处理失败后继续，直到结果明确到底、手动停止或环境、浏览故障停止；没有到底提示且暂时没有新结果时等待 60 秒再继续。顶部仅保留紧凑的任务状态、计数和启动/停止按钮；可分页的业务日志、检测步骤与真实心跳按需在监控抽屉查看，不挤占脚本编辑区。刷新页面仍能看到任务，不依赖页面一直开着。普通用户的登录、检测、启动和停止都在前端完成，不需要使用终端。

### 登录与恢复

“历史脚本”的“采集监控”连接页提供独立浏览器状态和打开窗口按钮。它启动本工具专用的可视 Chrome（本机 CDP `9241`、独立 profile `data/history-source-login-profile`），用户人工登录、扫码或安全验证后，采集器继续使用该环境。不要在其他普通 Chrome 标签中登录后就假定会话自动共享。

检测结果在面板顶部直接显示：通过时为带勾选图标的“可以采集”；失败时为“暂时不能采集”及具体原因。检测中与证据过期分别显示“正在检测”“启动时自动检测”，不冒充成功或把过期当作登录失败。详细步骤默认收起，检测完成后回到结果顶部。

采集任务失败时，顶部任务条直接显示失败环节和原因，例如“搜索结果未就绪：抖音仍在加载搜索结果”。点击原因直接打开任务日志，保留原始错误及已入库计数。抖音连接状态在监控的连接页单独查看，不再用“启动时自动检测”替代任务失败原因。

遇到登录或验证页时，采集任务进入 `waiting_login`，保留原任务、已保存稿件和去重状态，页面提示登录；等待期间不继续采集、不下载、不调用付费模型，仍可停止。用户在专用窗口完成登录后，回到页面点击“检测登录状态”，不再由用户点击“已登录，继续采集”来声明成功。检测仅做浏览器与会话检查，不调用付费模型，也不新建采集任务。

检测在无头进程的持久化默认上下文中打开独立探针标签页：从首页实际搜索“历史”，核对网站生成的结果地址与输入词，再等待连续两次稳定且非加载中的视频或 `/note/` 图文卡片，或明确的结果结束提示。探针不操作时长、内容形式或发布时间筛选，不要求顶部“视频”分类；明确结束的空结果也可证明搜索能力，暂时空白或仍在加载则不能通过。仅存在认证 Cookie、HTTP 200、已保存会话、首页可打开或用户确认，都不能判为可采集。仅探针成功后发布新的 Chromium readiness revision，唤醒等待登录的原 worker；原任务复用相同 profile，重建受阻页面和当前关键词搜索，不新建任务、不导入 Cookie。检测失败不发布新 revision，不唤醒等待 worker；等待登录的时间不计入页面加载超时。探针结束仅关闭自身标签页和 CDP 连接。

`ready` 仅表示 Chromium 完整搜索探针通过，`canCollect=true` 要同时满足引擎是 `chromium`、revision 一致、检测结果不超过 5 分钟。旧 Lightpanda 检测不能授权新引擎。超过 5 分钟只表示检测证据需要更新，不证明登录失效或网站识别了自动控制；启动时自动复检，不因页面刷新或状态轮询延长有效期，也不再为此禁用启动入口。`session_saved` 不能直接视为可采集。`login_required` 表示实际页面要求登录或缺少认证证据；`blocked` 表示验证码、安全验证或实际搜索受阻，不等同于未登录；`error` 表示检测服务、浏览器连接或执行异常，不归咎为用户未登录。页面保留检测步骤和结果，便于区分这些情况。

状态轮询 `GET` 只读取脱敏状态，不启动浏览器、执行探针、保存会话或唤醒任务。检测失败时保留已完成稿件，不无限重试，不绕过验证码。**登录后是否足以恢复实站，仍须用户真实登录后复检，不能由模拟测试代替。**

真正的登录存储由专用 Chromium profile 自身维护；新的 `data/history-source-auth/session.json` 仅保存引擎与 readiness revision，不再导出 Cookie。私密目录 `0700`、文件 `0600`、原子写入；状态接口、任务事件与日志均不包含 Cookie。保留旧 Cookie 数据格式仅为兼容旧文件，不作为新引擎认证依据。不读取普通 Chrome 或创作者发布 profile。后台采集不需要保留可视窗口；不要手动结束专用无头浏览器进程。

任务停止与服务维护是不同生命周期：任务和检测器仅清理自己的标签页/CDP 连接，不关闭人工登录页；打开窗口只复用认证服务自己创建的人工标签，不接管任务或探针标签。当前窗口由 API 内 Puppeteer 启动，API 正常退出可能关闭该窗口。服务重启后从前端按原 profile 重新打开、检测，不承诺 Chrome 进程跨服务重启存活。专用连接 CDP 协议命令上限 20 秒，driver 单操作预算 30 秒；检测总预算 120 秒，状态在 125 秒无更新后才判为检测中断。业务搜索每阶段最多等待 90 秒，仍可手动停止。已连接后的导航失败提示页面加载失败，不误报为未登录。

停止先显示“停止中”，后台退出后显示“已停止”。保留已下载的视频、已成功的转写片段与校对稿，不再进入下一个处理阶段。已发给供应商的请求可能仍完成或计费，取消 HTTP 连接不等于取消供应商计费。服务中断后标记中断，不自动重试付费请求；日志和已生成稿件保留。


ASR、校对与改写各保留一份，不覆盖原始证据。模型指出疑点不等于完成历史查证；`factCheckStatus` 固定为 `needs_sources`。`artifactState=current` 仅证明输入版本匹配，不证明语义或历史事实正确。换种措辞也不自动把他人的创作变成自己的原创，应把视频作为选题线索，补充独立史料与自己的论述，核查引用及使用权限。

任务接口均使用现有响应封装：`GET /api/v1/history-scripts/jobs` 获取当前/最近任务，`POST /jobs` 启动，`GET /jobs/:id` 查看，`POST /jobs/:id/stop` 停止。启动参数为 `targetCount`（1–9999 或 `null` 持续）、`categories` 和可选的 `keywords` 独立关键词数组；未传关键词时读取保存的设置，不接受任意网页、shell 命令或模型提示词。有限目标按成功保存的待审稿数计算，单篇失败不占用目标名额；搜索明确到底时说明实际保存数、失败数及是否未达目标，没有到底证据而提前结束仍报错。单篇处理失败写入 `source_failed` 警告，带来源 ID、原因及“继续采集下一条”，不自动重试付费请求；结束、手动停止或任务级故障均汇总失败数。启动检查、浏览器任务级异常和主动停止仍终止任务。写请求要求 JSON，并拒绝非本地页面 Origin。状态、日志、取消请求存入已有 SQLite `creation_tasks` / `creation_task_events`；默认由主后端通用 worker 执行。可选独立模式的 worker 只消费 `history.source`，不执行其它制作或发布任务；`--api-only` 不消费任何任务。

任务 DTO 将业务进度和存活信号分开：`progressAt` 是最新 `history.progress` 事件时间；`heartbeatAt` 是当前任务租约 owner/token 匹配的真实续约 `heartbeat` 事件时间，首次续约前可以为 `null`；`leaseExpiresAt` 来自任务租约本身。默认任务续约每 30 秒一次、租约 60 秒；worker 另有每 10 秒写入的进程心跳。仅当任务运行中、租约仍有效，且该租约 owner 的 worker 心跳不超过 30 秒时，`workerHealth` 才是 `alive`。API 请求成功、`updatedAt` 更新或业务阶段暂时不变，都不能冒充 worker 心跳。等待登录时业务进度可以不变，真实存活的 worker 仍应持续续约。监控抽屉默认读取最新 100 条业务日志，可继续加载全部更早记录；`GET /jobs/:id/events?limit=100&beforeId=...` 返回事件页。`GET /jobs?limit=20&beforeId=...` 返回历史任务页，同时保留不受分页影响的当前任务。两个接口返回 `total`、`hasMore`、`nextCursor`。日志查询先筛选 `history.progress`，不会被周期心跳事件挤掉等待登录前的进度。

登录接口：`GET /api/v1/history-scripts/browser-session` 只返回脱敏状态；`POST /browser-session/open` 打开专用窗口，`POST /browser-session/check` 对应“检测登录状态”，执行无付费模型调用的同一 Chromium 完整搜索探针。两个 POST 只接受空 JSON 对象 `{}` 和本地页面 Origin，不接受 URL、Cookie、profile 或文件路径。检测成功才发布 readiness revision，检测失败不触发等待任务恢复；检测本身不新建采集任务。

## 独立关键词设置

在页面点击「启动采集」后，可在「采集关键词」中添加、修改、删除并保存关键词。默认只有「历史」，至少保留一个、最多三十个，每个最多八十字符。每一行是一次独立搜索：`["历史", "明朝"]` 会先搜索历史，再搜索明朝，不会拼接成「历史 明朝」。设置在后端持久保存，刷新页面仍有效；未保存的修改会阻止启动。

`GET /api/v1/history-scripts/collection-settings` 读取 `{keywords:string[]}`，`PUT` 保存同一结构。新任务保存启动时的关键词快照，修改设置不改变运行中的任务。任务内跨关键词去重，产出数量是所有关键词共用的总目标；目标达到后结束，因此有限数量任务可能在第一个词就完成。选「持续采集」可继续遍历后续词。只有所有关键词都明确到底才报告整体结果耗尽。来源 `selection.searchQuery` 记录实际命中的关键词。

设置文件默认位于数据库旁的 `huobao_drama.db.history-source-settings.json`，可通过 `HISTORY_SOURCE_SETTINGS_FILE` 配置，使用临时文件原子替换。控制接口仅接受本地页面 JSON 请求。

## 无头浏览器与人工登录

默认使用无头 Chromium 进行登录检测与采集，不显示窗口、不播放声音。页面的「采集监控 → 打开登录窗口」才会显式打开可视模式，供首次登录、登录过期和验证码处理；完成后「检测登录状态」会关闭专用可视进程，保存并复用同一 profile，在无头模式下验证真实搜索结果。profile 保存 Cookie、localStorage 等浏览器状态，不要求每轮重登。普通 Chrome 和发布账号的 profile 不参与切换。

模式切换串行执行；关闭前再次核对专用 profile，等待原进程 CDP 端口及 profile 锁释放后才能启动新进程。对本机已退出 PID 留下的锁，由 Chromium 自行恢复，不手动删除锁；活进程、其他主机或无法确认的锁会阻止启动。每个采集/检测客户端持有租用，存活期间拒绝打开登录窗口（HTTP 409），不会中断正在使用的浏览器。该租用协调针对默认的同一后端 API/worker 进程；不要同时运行独立 worker 进程管理同一专用 profile。

遇到登录或安全验证时，任务先关闭自身标签页并释放连接，进入等待登录。用户显式打开窗口处理后重新检测，只有新的有效 revision 才能恢复。恢复会重建当前关键词的普通视频与图文搜索，重新确认关键词及稳定结果或明确的结束提示，重核未处理卡片，保留已完成来源及跨关键词去重，不继续使用旧页面 ID。检测和采集均不自动弹出可视窗口，也不自动处理验证码。

本次对照发现：默认无头 UA 带 `HeadlessChrome` 时进入验证码中间页；同一 profile、同一 Chrome 使用普通 Chrome UA 后首页可用，`navigator.webdriver` 仍为 true。当前在每个任务页发出首个请求之前，从已安装浏览器读取真实 UA，仅把 `HeadlessChrome/` 改为 `Chrome/`，不硬编码版本、不安装额外伪装插件。此设置只针对本次观察到的触发点，不能证明平台永远无法识别自动化。

另修复两项实站兼容问题：搜索框在页面尚未完成加载时已经显示，过早输入会被后续初始化清空；“明朝”可能默认单列，旧卡片读取器因此一直等不到多列卡片。现在分别等待输入就绪，必要时通过真实“多列”控件切换，再确认普通视频与图文结果稳定且不在加载，或已明确结束；不再继续操作搜索筛选。浏览器验证仅导航、搜索、滚动和读取 DOM，不调用模型、下载或 ASR。

Lightpanda 是独立引擎，不能直接复用 Chromium profile。其官方 CDP 实现支持 Cookie 导入，实验适配层也有注入逻辑，但 Cookie 不等于完整抖音会话，仍需处理浏览器存储、页面 API 兼容性和验证码。当前 worker 与 readiness 只启用 Chromium，不能只改 driver 就宣称 Lightpanda 可用；遇到验证必须回到可视窗口人工完成。

官方依据：[README](https://github.com/lightpanda-io/browser/blob/2064b9092d52ef932a51abfc405797a92aaabd4f/README.md)、[CDP Cookie 存储实现](https://github.com/lightpanda-io/browser/blob/2064b9092d52ef932a51abfc405797a92aaabd4f/src/server/cdp/domains/storage.zig)。

## 来源浏览与旧版分类说明

使用与人工登录相同的专用 Chromium 持久化上下文，按任务关键词逐个进行普通搜索、点开视频或图文并滚动；任务仅操作自己创建的标签页。搜索词在「采集关键词」中单独设置。出现登录或验证码时通知用户在该专用窗口处理，通过前端“检测登录状态”的真实搜索探针后才发布 readiness revision 并恢复等待任务。

下表仅解释旧稿中保留的分类元数据，不作为当前启动、搜索或入选条件。

| 入库分类 | 选题目标 | 示例主题 |
| --- | --- | --- |
| `regional_history` | 当地观众共鸣，外地观众理解一个地点的来历 | 地名 + 历史、地方志、古城来历 |
| `unofficial_history` | 不常见的故事，但明确区分传说与史实 | 人物 + 轶事、传说、野史考证 |
| `historical_anecdote` | 日常生活与古今反差带来的好奇 | 古人刷牙、古代饮食、古代洗澡 |
| `historical_commentary` | 人物或事件中的选择与争议，能形成具体讨论 | 人物评价、事件原因、决策争议 |
| `history_trivia` | 回答一个可核查的历史问题 | 历史冷知识、文物用途、建筑工艺 |

旧版曾按互动数量、评论里的求知需求和可核查主题判断选题，这些内容判断现已停用。当前不要求读取评论正文样本，也不按评论观点或分类拦截来源；旧稿的评论证据仍保留供追溯。

早期试点的可见评论属于便利样本，不是随机抽样，不构成当前采集前置要求。未见播放量时不计算互动率，不把缩写“万”当作精确计数。

成片以 **约 10 分钟** 为制作参考，优先选择故事完整的素材，不为凑时长补写未核实内容。按每分钟约 220–280 个汉字/口播词粗估，10 分钟约为 2200–2800 个口播单位；最终以视频工厂的真实 TTS 母带时长为准。改写稿的 `reviewJson.scriptTiming` 保留口播单位、估算速率、估计秒数和区间等数值，600 秒仅为制作参考目标。当前不再生成 `fit` 分类，不据时长评判稿件过短、过长或合格，也不据此删改正文或阻止保存与入队。

**关键复核：** 抖音会自动连播。先获得固定 `https://www.douyin.com/video/<id>` 或 `https://www.douyin.com/note/<id>`，在详情核对标题、作者和实际指标属于同一个来源 ID，再保存。来源 ID 必须是数字字符串，不能转成 JavaScript `Number`；图文不要求视频时长或音轨。

候选文件格式：

```json
{
  "sourceVideoId": "7674832876206050600",
  "title": "为什么说古人吃的东西，没有现代的科技，但照样都是狠活呢？",
  "authorName": "挖点芝士",
  "category": "historical_anecdote",
  "metrics": { "likes": 93000, "comments": 2648, "collects": 13000, "shares": 37000 },
  "selection": {
    "reason": "古代食品造假与现代添加剂的反差；评论出现古今对照和史料追问。",
    "observedAt": "2026-10-14T06:24:00Z",
    "searchKeyword": "历史冷知识",
    "approximateMetrics": ["likes", "collects", "shares"],
    "comments": [{ "text": "现在叫添加剂，以前叫秘方", "likes": 31 }]
  }
}
```

可以导入一条或数组。`platform + sourceVideoId` 唯一约束防止重复入库；再次观察更新选题证据，不清空已有稿件。评论只保存公开可见的必要文本和点赞数，不收集评论者身份。

## 部署与配置

前置条件：Docker 正常运行、`gh` 可读取 GitHub、Node 与后端依赖已安装、PATH 中有 `ffmpeg` / `ffprobe`。

从仓库根目录执行：

```sh
node backend/scripts/history-sources/deploy-downloader.mjs
```

下载服务绑定 `http://127.0.0.1:9125`，Docker 项目名 `dtk-history`。脚本固定源码和浏览器依赖版本，使用独立资源限制，不修改 Docker 全局内存。镜像构建与首次浏览器资源下载耗时较长；部署日志在 `data/storage/history-source-downloader/deployment.log`。`--skip-pull` 仅用于镜像已在本机的续跑。

上游完整部署建议至少 4 GiB 加 swap，常规运行推荐 8 GiB。本机 Docker 仅约 2 GiB，且有其他项目运行，因此使用低并发和独立资源上限；当前仅证明单条流程，尚未验证批量或持续采集稳定性。

私有连接文件 `data/storage/history-source-downloader/connection.json` 权限为 0600，包含本地管理员及 API 密钥。不要复制到文档、前端、日志或提交 Git。整个运行数据目录已被项目 `data/` 忽略规则覆盖。API/worker 健康与 Douyin 身份有效是两件事，必须实际解析和下载作品验收。

ASR 同时支持 Qwen 和 MiniMax。启动校验与实际转写共用 `history-asr-config.ts`，按转写供应商选择配置，不把最高优先级的配音供应商当成 ASR 能力判断。默认沿用已启用且带密钥的 MiniMax；没有 MiniMax 时可用设置页中的 `qwen-tts` 云端凭据和对应地域地址。配置环境变量 `QWEN_API_KEY` 时优先使用环境中的 Qwen；`ASR_PROVIDER=qwen|minimax` 可指定首选。Qwen 转写模型固定为 `qwen-audio-3.1-asr-flash-filetrans`，不使用配音模型或音色。

Qwen 默认使用北京 `https://dashscope.aliyuncs.com/api/v1`；数据库配置保留其地域/业务空间的原生 API 地址，`QWEN_ASR_BASE_URL` 可覆盖地址。密钥与调用地域必须匹配。MiniMax/Qwen 在提交前明确返回认证、额度或限流拒绝时，可以尝试另一家已配置服务一次；实际结果记录供应商、模型和回退原因。网络超时、取消、损坏或不完整结果，以及 Qwen 已受理任务的轮询失败，不自动切换供应商重复提交。单次调用显式传入的 config 保持固定。配音服务的优先级和音色不变。

Qwen 将本地音频上传至百炼临时 OSS，提交异步识别任务、轮询并下载结果，将毫秒时间戳转换为现有流程使用的秒。临时音频有效期 48 小时；大量并发场景可改用自有 OSS。已完成分段继续复用，切换服务时不会主动重新转写；分段记录实际供应商和模型，混合结果标注为 `mixed`。接口依据：[官方使用指南](https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide)、[HTTP API](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-filetrans-http-api)。

MiniMax ASR 复用数据库中已启用的 `audio` / `minimax` 配置，校对与二创复用已启用的文本模型。旧 TTS 域名 `api.minimaxi.com` 自动映射为官方 ASR 域名 `api.minimax.cn`；可通过 `HISTORY_MINIMAX_ASR_BASE_URL` 指定适配账号区域的 ASR 域名。

LM Studio 已退出采集依赖，无需启动或加载本地改写模型。独立的本地改写工具代码保留供其他明确调用，但采集任务及其 `doctor` 不使用它。

```sh
node --import tsx scripts/history-sources/run.ts serve 9130
```

`doctor` 只报告转写/文本模型配置、下载服务和 FFmpeg，不探测本地改写模型，不调用付费模型，也不输出密钥。完整 `process` 默认执行到二创并保存待审稿（`--through recreate`）；`--through correct` 仅校对，不生成新待审稿，已有有效稿件仍保持 `needs_review`。不接受旧的 `--through rewrite`。不需要主后端运行。导出为 `needs_review` 草稿且拒绝覆盖既有文件，不等于确认进入生产。

每个来源的本地文件：

```text
data/storage/history-scripts/<id>/
  source.mp4
  audio-000.wav
  audio-001.wav  (超过 480 秒才有下一段)
  process.lock  (处理中存在，正常结束后移除)
```

下载原子落盘，核对字节数和 SHA256，并经 FFprobe 确认有音轨与有效时长。音频使用 16kHz、单声道、PCM WAV；按 480 秒切片，低于 MiniMax 官方 500 秒 / 50MB 单次限制。请求使用 multipart `POST /v1/speech_to_text`、`model=asr-1.0`、`language: zh` 和 `response_format=verbose_json`，保留分段时间戳。ASR 需要账户余额或适用额度。

校对输出为结构化 JSON：完整校对稿、修改前后及原因、需要文献支持的历史说法与检索词。没有音频复听依据的不确定词不强改；历史疑点不由模型凭记忆写成新事实。

二创以完整校对正文及校对阶段的史料疑点为输入，应用固定版本的 `water-koubo` 技能并调用当前启用的文本模型，只要求输出口播正文。正文原样存入 `rewrittenScript`；`reviewJson.draftOrigin = water_koubo`，`reviewJson.recreation` 保存技能版本和 SHA256、实际供应商和模型，以及旧格式中可选的标题、封面建议。`rewriteInputSha256` 继续绑定校对正文。标题和封面建议可为空，不参与正文有效性判定。`scriptTiming` 保留中性的时长估计，不据此评判篇幅是否合格。当前有效的既有稿件在续跑时不被二创覆盖，包括旧 `corrected_transcript` 起稿。

自动花生入队开启时，文章和视频分支都在将当前稿标记为完成的同一次数据库写入中持久化 `huashengQueue` 待排队标记，再通知队列。短稿、长稿及与原稿相同的非空正文遵循同一流程，不附加审核步骤。队列暂不可用时保留稿件和标记，恢复时只处理这些已标记稿件，不扫描旧稿批量补跑。历史记录中的旧长度诊断不批量改写，新二创不再写入这些诊断。

## 续跑与故障

同一个 ID 重跑会根据文件哈希和阶段检查点复用已完成成果，包括已成功的 ASR 分段，降低重复收费风险。没有供应商幂等保证：如果供应商完成但客户端在保存之前断线，重试仍可能再次计费。二创没有可用正文、模型请求失败、响应在传输中截断或 ASR 返回无效时间戳时，该篇记录失败并继续下一条；取消时停止流程并保留已完成检查点。正文为必需内容，常见格式差异由解析器修正，标题和封面建议不作为必填项，不做篇幅质量判定或长度警告。非空、来源哈希、排他锁与取消检查仍保留，防止空稿、过期稿或已取消操作进入后续流程。旧版本已失败的任务日志保持原样；当时未保存的模型正文无法事后恢复，需要单独续跑该来源。已删除来源不会自动恢复。

同来源并发处理由排他锁拒绝。进程被强行中止后，确认原进程停止再执行：

```sh
node --import tsx scripts/history-sources/run.ts unlock 1
node --import tsx scripts/history-sources/run.ts process 1
```

`unlock` 只删除本机已停止进程的锁，不能解除正在运行或另一台主机的锁。远端下载缓存被清理或文件不存在时，下一次重试重新下载，不将不可用的完成记录当成可复用文件。已有原文和稿件保留供排查，但当前输入改变后，旧改写必须通过来源哈希检查才能导出。

403、验证码、登录失效及平台风控需要分别诊断，不进行无界重试或自动绕过验证；402 是 MiniMax 余额不足。旧版因本地改写失败而中断的来源，重新执行 `process <id>` 会复用有效转写和校对检查点，通过 `water-koubo` 二创保存待审稿，无需恢复 LM Studio。二创请求取消后，即使供应商迟到返回，正文也不会保存；重试仅从未完成的二创继续。

## 数据库与前端接口

表 `history_script_sources` 保存来源 ID/URL、标题作者、五类分类、指标、评论证据、媒体元数据、原始转写、校对稿、改写稿、ASR/审查 JSON、阶段状态及错误。主后端挂载相同路由；独立 API 可绕开主后端其他模块依赖运行。

```text
GET /health
GET /api/v1/history-scripts?category=historical_anecdote&status=needs_review&q=食品&limit=20&offset=0
GET /api/v1/history-scripts/1
GET /api/v1/history-scripts/1/export
PATCH /api/v1/history-scripts/1
GET /api/v1/history-scripts/1/video
HEAD /api/v1/history-scripts/1/video
```

列表返回 `{code, message, data: {items, total}}`，详情返回全部版本与证据。每页最多 100 条；详情保留 JSON 字符串字段，前端按字段解析。列表和详情的 `artifactState` 分别指出转写、校对、改写是 `missing`、`stale` 还是 `current`，不要展示旧文本为当前可选稿。导出为 Markdown 附件，无当前有效改写稿时返回 409。独立服务仅监听 127.0.0.1，不向公网暴露数据库内容。

稿件库支持组合筛选：`video=completed|not_completed`、`titlePlan=generated|not_generated`、`cover=generated|not_generated`、`motion=generated|not_generated`；省略即全部，四组与搜索、分类、采集状态同时按 AND 生效，先筛选后计数、分页。返回 `workflowState` 的四个布尔字段 `videoCompleted`、`titlePlanGenerated`、`coverGenerated`、`motionGenerated`，列表标签与筛选共用同一判断：视频以已关联成片、最新花生任务完成或精细化成片为准；标题以方案完成且有标题为准；封面以生成完成且有三种尺寸路径为准；精细化以实际渲染出成片为准，排队、选镜及无输出的失败任务不算已生成。筛选仅读取已有记录，不启动远端状态检查、生产或额外质量审核。

开发环境主后端有活跃任务而不能重启时，可用 `TASK_WORKER_DISABLED=1 node --import tsx scripts/history-sources/run.ts serve 9131 --api-only` 启动新版本维护 API，并在 `frontend/.env` 设置 `HISTORY_LIBRARY_API_TARGET=http://127.0.0.1:9131` 后重载前端。此覆盖仅转发稿件集合列表，详情、写入、生产和上传仍使用原 5679 服务。主后端空闲并更新后，移除该环境变量、重载前端并停止 9131；默认部署仍全部使用 5679。

前端已实现左侧列表、搜索/分类/状态/分页，以及右侧原始转写或校对稿与可编辑改写稿对比、来源查看、审稿疑点展开和改写保存。四个处理中阶段均可筛选；处理中编辑和保存禁用，显示具体阶段，页面可见且没有未保存修改时每 15 秒更新进度，不重建同来源视频。失败原因在详情显示。PATCH 仅接受 `{rewrittenScript, expectedRevision}`；版本冲突返回 409，保留本地输入。服务端与处理流水线共用来源排他锁，拒绝覆盖正在处理的稿件，保留原稿、校对稿、审查信息与来源哈希，重新计算估算口播时长，状态仍是 `needs_review`。尚未清理的视频按来源 ID 定位规范 MP4，支持 Range/HEAD，不支持任意文件路径，也不向前端暴露媒体绝对路径。播放器固定尺寸并完整容纳横屏与竖屏视频；完成转录并清理后改为显示原视频链接。

脚本详情提供“删除脚本”入口；确认后软删除该稿件，列表、详情、导出和播放接口不再返回它，数据库记录及来源链接保留以便恢复和去重，后续采集不会重新入库，正在处理、被其他任务锁定或版本已更新时拒绝删除。临时视频的生命周期由转录清理流程管理。

花生自动入队、断点恢复及平台制作状态见 [花生自动化](history-huasheng-automation.md)，不增加二创人工审批步骤。稿件库早期版本的验证记录：49 项后端/前端回归测试（45 后端、4 前端）、前端生产构建、严格局部 TypeScript 检查，以及真实视频播放/跳转和数据库编辑保存/还原验证已通过。当时全仓既有类型错误未列为通过。运行前端构建会更新 `.nuxt` 并触发开发服务重启，浏览器回归须在构建结束后执行，不与构建并行。
