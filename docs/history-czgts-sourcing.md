# 百家号历史文章采集（czgts.cn）

在 `http://localhost:3013/history-scripts` 顶部点击 **启动采集**，默认优先采集 **抖音视频和图文**，使用无时长、内容形式或发布时间筛选的普通搜索，不要求顶部“视频”分类。需要文章素材时，将采集来源手动切换为 **百家号文章（czgts.cn）**，通过文章接口采集完整原文，再自动校对与二创，无需下载来源视频或 ASR。CZGTS 失败时显示具体原因，不自动切换来源。

1. 粘贴 czgts.cn 登录 Cookie，点击 **保存 Cookie**，再点击 **检测文章接口**。保存成功后输入框清空，已有 Cookie 不回显。
2. 设置开始、结束时间，均为北京时间；默认最近 24 小时。
3. 选择 **按数量** 并填写需要入库的篇数，或选择 **持续采集** 遍历该时间范围内的全部结果。结果耗尽时，即使少于目标数量也会结束；可随时停止。
4. 点击 **开始采集**。在 **采集监控 → 任务日志** 查看分页、原文读取、跳过和失败记录。
5. 原文入库后进入校对与二创，成功后显示 **待审**，在详情对照文章原文、校对稿与二创稿。开启花生自动制作时，二创成功后自动入队。旧的原文记录不会批量补跑。

接口固定查询「百家号 / 历史 / 文章」。抖音的独立关键词、点赞与评论总数门槛不参与 CZGTS 文章查询；旧版抖音时长、内容形式、发布时间及素材分类要求已停用，不是切换来源后需要设置的条件。CZGTS 使用自己的 Cookie 和文章接口检测，不依赖抖音登录或搜索探针。文章无需视频下载和语音转写；校对与二创使用已配置的文本模型及其正常用量。保存、校对和二创不代表史实已核查。模型处理失败保留原文与已完成检查点，任务日志记录原因并继续下一篇。

阅读量、粉丝数等指标保留上游可用数值；缺失或不可用的数据不补成 0，页面显示 `--`。按来源平台和百家号文章 ID 去重；已软删除文章也保留去重记录，不会再次自动入库。单篇正文读取失败会记录原因并继续；未获得完整原文的文章不入库，可在后续任务重试。

## 登录配置

Cookie 仅保存在本机 `data/secrets/czgts/credentials.json`，文件权限为 `0600`，目录权限为 `0700`；`data/secrets/` 被 Git 忽略。设置接口只返回 `configured` 与 `updatedAt`，不会返回 Cookie，前端也不将其写入日志或 localStorage。Cookie 仅发送给 czgts.cn 的固定搜索接口，不传给百家号原文页面。

macOS 可从 Chrome 默认用户配置中导入当前 czgts.cn 登录状态。在 `backend/` 目录运行：

```sh
node --import tsx scripts/history-sources/import-czgts-cookie.ts
```

脚本只读取 czgts.cn 域的 Cookie，先验证文章接口可用，再替换本地配置；输出仅包含配置状态、Cookie 数量和查询条数。用户已授权并完成一次导入；2026-10-21 验证时，接口返回最近 24 小时 246 篇文章。该数字是当时的查询结果，不是固定数量。

登录可能过期。遇到登录失效提示时，在网站重新登录，再通过页面替换 Cookie 或重新运行导入脚本并检测。
