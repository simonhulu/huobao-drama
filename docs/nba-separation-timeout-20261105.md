# NBA 现场声分离超时修复

任务：`nba-97ddb6f765f5d86d1b8e`。

## 原因

源视频约 18 分 24 秒，原分离进程使用固定 30 分钟超时。最后一次记录
持续 1805 秒后退出。配置的 Python 能正常导入 Torch/Torchaudio 2.6.0，
官方模型摘要正确，并非已证实的环境故障。

单次 6 秒窗口的 CPU 推理实测为 7.298 秒，整段约需 221 个窗口。
仅按这个短样本估算，推理约需 27 分钟，尚未包含长音频的内存压力、
解码、写盘和校验。诊断与原始测量见
`outputs/nba-audio-timeout-20261105/diagnosis.md`。

## 修改

- 采用 `max(1800, 源时长秒数 × 4 + 600)` 秒预算，每次最多 3 小时。
  该源视频的预算约 84 分钟。
- 进程超时带结构化错误码，并允许既有队列有界重试，提示不再误指向
  Python 环境。其他环境和报告校验失败仍保留原有处理。
- 每个 6 秒窗口独立原子保存；恢复时校验来源、模型、全局归一化、
  运行环境及分段摘要、尺寸和数值，损坏窗口重算。
- 保留原有 1 秒重叠和逐样本对齐，减少长音频的整段临时内存分配。
- 模型进度同步并持久保存到任务详情。

## 服务边界

现场声分离使用本地 Python 和 TorchAudio 官方
`HDEMUCS_HIGH_MUSDB_PLUS`，当前在 CPU 上推理。
公式是从原音轨减去 94% 的估算人声，再限制峰值。模型不能保证完整
消除解说，也可能削弱观众喊声。

TTS 使用已配置的远程服务。当前 NBA 字幕对齐仍调用本地 `whisper-cli`，
不能称为所有 ASR 均已走远程服务；本次未改动 ASR 或音色。
