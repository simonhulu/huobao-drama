# 从首页逐条生产，而不是每场比赛只出一条新闻

2026-10-24 实测发现，此前20条新闻中19条被归入5个比赛目录（辽宁6、山东5、北控4、天津3、浙江1），另1条多场盘点没有进入比赛流程。后端又按任务目录及任意seed关联完成状态，导致同场其他新闻在页面消失，甚至被一份成片代替。这不是首页只有几条新闻。

另一个根因是入口读取错误。`cba.hupu.com` 的 `#focusNews` 由页面脚本调用公开 `getTopNews?page=1&num=24&competitionType=cba&channel=pc` 接口动态填充；静态HTML中的旧注释和voice旧列表不是当前展示内容。23:29（北京时间）实测接口有24条唯一新闻，包含李昂首次两连胜、周鹏三分、赵柏清社媒和广东采访。正文从论坛HTML的 `__NEXT_DATA__.props.pageProps.detail.thread` 读取；`createdAt` 才是发稿时间，首页API的`uptime`是更新时间。

现有改动：

- 首页模块保存完整24个新闻位置、页面实际顺序、抓取时间及原始响应SHA256。只去重相同URL，不按比赛合并，没有默认20条上限。
- 工作台先持久化整份清单，再按4条一组研究。后端只接受本组的条目回写，保留其他组。遗漏会补回并要求一次修正，仍未完成的明确保留，不能报完成。
- 每条独立新闻用稳定目录 `<match-id>-news-<帖子id>`，主seed只能对应它自身。共享比赛和次要来源不等于新闻已制作；已交付判定必须重新验证真实产物。
- 同一主新闻只选择一个任务目录，优先复用有效交付，避免旧目录和新目录各上传一次。
- 同场追加新闻可使用 `profile.editions:["news"]`，新闻通常30–180秒，按信息量决定。首次比赛可生成双版，同场整场集锦不重复生成或上传。旧任务无editions字段仍保持双版。
- 页面按所选版本显示预览、上传回执和完成状态，并显示本轮首页总数、已研究数、待研究数和读取时间。“已研究”不等于“已出片”。

新闻单版使用现有`renderNews`；没有修改`render.mjs`，避免所有旧成片摘要失效。新闻单版交付含视频、封面、字幕和delivery清单4个校验产物；双版仍为6个。

验证：scripts门禁、单版CLI预览/渲染/缓存及标题39项；首页解析6项；后端编排13项、服务52项；前端控制器和模板15项，合计125项通过，后端TypeScript检查通过。合成媒体仅用于流程回归，未当作真实体育视频证据。新入口也已真实HTTP读取24条，原始响应随每轮homepage.json保存。

主要文件：`scripts/cba-video/hupu-intake.mjs`、`editions.mjs`、`cli.mjs`、`core.mjs`、`review.mjs`、`editorial-gate.mjs`、`title-policy.mjs`及测试；`backend/src/services/cba-video.ts`、`cba-production-pipeline.ts`及测试；`frontend/app/pages/cba-video.vue`及控制器测试；生产技能及新闻遍历说明。

仍有明确边界：赵柏清社媒、山西训练等非单场新闻即使正文自带视频，也不能虚造比赛身份进入当前比赛剪辑流程。它们须保存直接素材线索并明确标为需要非单场路线，不能写成没有素材或默默丢弃。是否能把24条全部制作成独立视频，还取决于正文信息量、确切事件、对应素材和独立审核；重复同一事件不应以换标题增加产量。
