# 历史视频标题创作

> 2026-10-28 更新：发布标题直接改写来源原标题，保留人物、年代和数字，去除推广词；不再联网搜标题或生成视频号短标题。封面主标题独立，见 [现行流程](history-workflow-upgrade-20261028.md)。下文标题检索、16 字短标题及删集数规则仅为旧版记录；新分集的集数必须保留。

> 2026-10-31 更新：花生版与精细化版在各自成片完成后分别创作标题、封面方案与三比例图片。后一版创作读取另一版已保存方案以避免重复，保存与上传都绑定具体 `video_id`；不共用稿件级旧包装。见 [每版独立的标题和封面](history-workflow-upgrade-20261028.md#每版独立的标题和封面)。

标题的任务是让观众想点开。先学习原视频标题的对象、反差、悬念和观看承诺；原题只有朝代/人物/集数时，从正文提取更强的具体爆点，删除集数和无关标签。不能把原题改成更平淡的全文摘要。

这是所有历史脚本共用的生成机制。「生成标题、简介与封面方案」读取当前脚本的原题和完整正文，依次提取关键词、联网搜索、挑选真实原题、使用指定 LM Studio 模型逐条改写，先按好奇心与求知欲选出一个短标题，再只为这一条配套平台文案与封面。通常挑选 3–5 条；只有 1–2 条相关参考时按实际数量使用；无参考或全部不相关时由项目文本模型基于正文原创一个标题。多候选才调用 `history-title-select`，单候选直接采用；不调用 `history-title-review`，不进行质量审核或按审核意见重做。`publishingCopy` 本身启用公共流程，不依赖另一个审核标志。已有记录不批量改写，点击生成后才用新机制。

一次生成三项发布文案，配套一份封面方案。字数包含标点、空格，与前后端及发布器的 JavaScript `String.length` 一致。

16字／40字是创作目标和平台发布限制，不再是草稿保存门槛。完整、非空的标题即使超长或含不支持的符号，仍参与选优并完整回填，不截断、不因这些问题重新改写或丢弃整套方案。GET 的 `publishingWarnings` 根据当前保存文案返回具体问题，页面以黄色提示展示实际字数、上限或符号问题。允许保存尚未改完的草稿，人工修正后提示即时消失，刷新会按保存内容恢复；发布准备仍严格执行平台限制。

| 文案 | 规则与用途 | API／存储字段 |
| --- | --- | --- |
| 视频号短标题／共同封面主标题 | 最多16字，逐字一致，突出具体反差、情绪和悬念；两平台封面共用 | `title`／`title`，`coverDesign.main_title` |
| 百家号标题／作品描述 | 最多40字，沿用选中短标题的角度，补充背景、冲突和观看价值；不另生成百家号简介 | `baijiahaoTitle`／`baijiahao_title` |
| 视频号描述 | 默认2–3句自然预告，不设应用层字数上限，不截断 | `description`／`description` |

前端按钮提交后由后端后台执行，不依赖当前页面持续等待。刷新或离开后再次进入，会读取数据库中的生成状态并继续轮询，完成后回填标题、简介和封面方案；失败原因持久保存，可重试且不覆盖旧文案。后台进程中断不自动重跑，租约过期后提示重新生成。任务与接口说明见 [历史脚本关联成片与封面](history-script-delivery.md)。

## 同题标题检索

1. 从本篇正文与原题提取两组不同关键词，每组 1–3 个，优先具体冲突、代价、反常行为或数量比较，逐字校验它们确实来自本篇材料。不能只用“历史 标题”等泛词，也不接受模型添加搜索运算符；提词不合法时最多修正一次，仍不合法就停止。
2. 两组关键词分别搜索今日头条和百家号。按结果的真实 URL 筛选文章页，包括百家号旧域 `baijia.baidu.com/s?id=...`，不把搜索服务返回的百科等站点冒充平台参考。某平台没有有效命中时最多补搜一次。
3. 对相关标题和文章 ID 去重，最多保留 16 条；同一文章的桌面、移动、协议或域名别名不能凑数。不强求两个平台都有命中，必须记录每次查询的成功、无结果或错误状态。有限补搜后只有 1–2 条也可继续；零条（包括所有搜索调用失败）保留真实的空检索快照，再走原创兜底。
4. 搜索原题、摘要、URL、查询词、时间和来源日期原样存入 `coverPlan.title_research`。选优仅接收原题池和本稿，不接收搜索摘要，以免把别人文章的细节当成本稿事实。通常挑出 3–5 个不同的真实编号，相关参考不足时选 1–2 个；全部与本稿主题相隔太远时返回空短名单，不允许虚构原题、硬凑来源或按搜索顺序机械截取。
5. 网络参考只负责表达方式，不提供本稿的新事实。参考中的数字、因果、内幕、对话和独特承诺不能替代正文证据。配套与最终选优也不接收搜索摘要，避免把不同稿件的材料混为一谈。

## LM Studio 标题改写

选出的每条原题分别调用本地 LM Studio，固定模型 `qwen3.5-9b-writing-dpo@q4_k_s`，关闭思考。旧 Q2 方案继续按原模型记录读取，不改写其归属。系统指令逐字使用：

> 请将下面这个标题改写为更自然、更有人类写作风格的表达，要求字数不超过16个字。更有情绪和冲突，能激起人的好奇心和求知欲

首次改写每次只发送一条真实原题，不发送完整正文、其他原题或搜索摘要。挑选参考时使用本稿正文；原题带有未获支持的人名、数字或因果时，可在该条短名单中记录最多300字的 `rewrite_guidance`，只说明删改哪些事实断言，不能代写最终标题。宿主仅把这条原题自己的事实边界交给 Q4，避免明知不适用的细节反复进入标题。这是改写输入提示，不是另加质量审核或事实合格证明。改写结果与原题一一对应，以含空格、标点最多16字为创作目标，超出则保留草稿供人工修改；不得截断或静默改用项目文本模型。宿主绑定原题、参考编号和候选 ID，全部保留在 `coverPlan.title_rewrites`，并生成 `reference_ids` 和 `reference_adaptation`。页面可展开“原标题与改写”查看对应关系。

调用 `/v1/chat/completions` 时读取纯文本最终标题，不使用 JSON grammar 或长度硬约束；使用与用户确认样例相同的 `temperature:0.3`、`repeat_penalty:1`、`seed:42`。此模型在本机的聊天模板已经追加 `<think>`，因此请求仅预填 `</think>\n\n` 关闭它，不能再嵌套一个 `<think>`。空 `content`、只有 `reasoning_content`、无实际文字或截断仍拒绝，不从推理中截取标题。保留 Q4 的完整措辞和情绪标点，只沿用中英文逗号替换为空格、去除首尾空白的通用规范化，并在说明里保留规范化前原文。超长、其他不支持符号、换行或隐藏字符均作为人工修改提示，不追加长度／符号修正请求，也不停止后续候选生成。重复标题仍可修正一次，不转发其他候选或整篇正文。传输、截断或响应结构错误仍报错。这些是响应完整性与来源检查，不是质量审核。

多候选先使用 `history-title-select` 比较短标题，选择最能激起好奇心与求知欲的一条，只返回选中编号与理由，不能改题或自创新标题，也不返回逐项审核布尔值、`title_hook` 或 `title_emotion`。单候选直接采用。选中后才调用 `history-title-packages`，其 `lockedTitles` 只有一条；配套作者填写百家号标题、视频号描述、副标题、角标和画面。宿主注入同一个视频号短标题与封面主标题。模型如回传不同的锁定标题或来源即格式不合格，最多重试一次配套，不重复搜索、改写或选优。全部改写记录继续保留，但新方案的 `candidates` 只有这一套完整成品。自动流程不因质量评价拒绝方案或增加审核轮次。

LM Studio 地址沿用 `HISTORY_LM_STUDIO_URL`，默认 `http://127.0.0.1:1234/v1`，仅接受无 URL 凭据的回环地址。指定模型须可用；连接错误、空响应、截断和不可解析的响应结构仍报错，不降级或覆盖原方案。平台字数和符号问题不属于这些调用错误。

无可用参考时不调用本地改写接口，改由已配置的项目文本模型根据当前原题和完整正文原创一个标题，再沿用锁题、平台文案和封面配套流程；单候选直接采用，无需选优或审核。保存 `coverPlan.title_fallback` 为 `no_references` 或 `unrelated_references`，并保留检索快照；不生成虚假的 `title_rewrites`、`reference_ids` 或 `reference_adaptation`。原创与配套不接收那些不相关的网络标题。视频号短标题仍与封面主标题逐字一致，创作目标为16字以内，超长或符号问题同样保留并提示人工修改。原创标题缺失、空白或JSON字段错误最多修正一次。此兜底只针对参考缺失或不相关，不用于掩盖 LM Studio 改写服务故障。

页面可查看同题标题链接、检索状态与候选借鉴说明。这里取得的是搜索标题和摘要，没有自动读取原页，也没有点击或互动数据，不能把它们标成“已验证爆款”。研究样例与读取限制见 [联网参考记录](history-title-reference-research.md)。

运行前提：后端进程的 `PATH` 中须有现有 `mcporter`，且能调用已配置的 `MiniMax.web_search`。搜索通过固定命令和结构化参数执行，不拼接 shell；单次工具请求最多 25 秒，子进程最多 35 秒，输出限制 2 MiB。无需新增项目依赖，也不读取或把搜索凭据写入方案。手工编辑、固定方案审核和非发布封面增强不触发这一步搜索。

## 创作建议与必要格式

以下关于情绪、悬念、正文承诺和画面的一致性用于指导创作与选优，不是逐项打分或否决门槛。自动流程仅保留必要格式、真实来源绑定、正文引句及并发写入保护。

- 单一信息差：观众看得懂谁出了什么反常结果，却还想知道原因。只留一个核心追问。
- 主标题自身具体：标题本身露出可辨认的对象、事件、物品或数量尺度，以及实际发生的异常动作、结果或比较。只说“又乱了”“出事了”，需要副标题补出谁干了什么，不算具体。不以字数更短为优，也不强求所有知识题都有人物动作。
- 观看预期一致：通史可以用一位皇帝的怪事开场，但标题或简介要带回多代人物的主线。正文只简述复位或失踪时，不能卖成复位谋划、失踪真相专题；引用命中事件名不代表兑现了细节承诺。
- 优先使用真实原题：发布分支按实际数量逐条改写 1–5 条已选原题，不再要求十二套或六种方法；没有相关参考时只原创一个，不再另起一批标题。保留原题有情绪与冲突的表达，不把强说法全部磨成课本设问。
- 先找情绪触发，再写标题：从正文找关系背反、到手又失去、努力或优势落空、普通人的生活代价等真实张力，选择本稿适合的主要感受，如荒唐、惋惜、不甘、心疼或惊叹。标题原词就要让人感受到这种处境，而非只报事件，再在理由里声称“令人震惊”。不是给摘要加“竟然”或问号，也不按情绪词数量打分；允许有依据的口语、评价和比喻，但不能编造苦难、动机、对话或族群对立来煽情。
- 创作与选优分工：本地写作模型使用指定系统指令，项目文本模型负责原题短名单、配套与多候选好奇心比较。两类模型明确分流，不再设置独立质量审核。
- 按标题实际承诺创作：正文有相应原因链时，“玩没、自毁、引爆”等口语不必自动读成故意自杀或此后一切历史的唯一原因；同等颗粒度的正文解释足以支撑表达，不索要标题没有承诺的权谋细节。尽量避免正文没有的人名、动机、数字及因果，这属于创作指导，不新增自动否决或重做步骤。
- 平台分工：视频号短标题与两平台封面主标题逐字一致，最多16字。百家号标题最多40字，用同一角度补足背景和冲突；副标题及视频号描述继续补充处境和悬念。答案只在内部 `payoff` 与正文中出现。
- 简介写预告：反常处境开场，具体细节推进，追问收尾。两三句自然口语，相关话题最多两个且放末尾，去掉活动标签、摘要腔、病句和无关承诺。
- 先选后配：多候选只比较短标题的好奇与求知欲、观看价值和情绪冲突，不先逐项审核再淘汰，也不因平台字数或符号问题弃用有吸引力的候选。仅选中标题生成一套配套，减少重复生成。短标题16字、百家号标题40字是创作目标及发布上限；完整草稿超限时仍保存并警告，不截断。视频号描述不设应用层字数上限。
- 标题表达建议：主标题自身露出对象、反常处境和一个值得追问的信息差，不必依靠副标题才能读懂。可以与同一事实的中性摘要比较表达入口，但不再要求 `title_hook` 检查或因其判断否决。
- 情绪表达建议：让真实处境和冲突产生情绪，不在摘要上机械堆“竟然”“震惊”。不再要求 `title_emotion`、触发词定位或情绪通过分数，也不因情绪评价增加重写轮次。旧审核记录保留原文，不补造历史评估。
- 标题符号：发布时支持书名号、引号、冒号、加号、问号、百分号和摄氏度。中英文逗号在生成、保存前替换为空格；其余标点、表情、换行和隐藏字符在草稿中保留，提示人工修改，生成和手工保存不再因此拒绝。发布准备仍拒绝不支持符号。副标题、角标和描述不受此符号限制，历史审核记录保留原文。
- 标题一致性：新候选的两个标题分别规范化逗号和首尾空格后逐字比较；文字、标点或中间空格不一致就拒绝，不能默默选用其中一个标题。

封面主标题与视频标题可以共同使用“修仙的没亡国 勤政的却亡了？”，副标题和简介再补出“大明十六帝”的群像主线。“财政、战事、灾荒相互叠加”已经列出答案，不适合作为悬念简介。正文证据由模型选择原文片段编号，再由程序填入原句，避免抄写时改字；这是原句溯源，不再额外调用模型判定其兑现程度。

例：正文讲明朝十六帝、修仙、木工、崇祯勤政和明亡，可以从“修仙的没亡国 勤政的却亡了？”找反差，追问王朝危机怎样累积。不能写“崇祯越勤政，明朝越快灭亡”，正文没有证明这种因果。封面与视频使用同一标题，新的信息和追问放进副标题与简介。

## 参考资料

- [YouTube 官方：缩略图和标题制作技巧](https://support.google.com/youtube/answer/12340300?hl=zh-Hans)：标题与缩略图搭配讲故事；最重要的词前置，集数和品牌靠后；有趣标题用于激发陌生观众好奇，内容需兑现承诺。
- [Curiosity in news consumption](https://onlinelibrary.wiley.com/doi/10.1002/acp.4195)：基于微信文章与实验研究信息差、重要性和意外性对阅读选择的作用。这里借鉴“明确一个值得知道的未知”，不据此承诺点击率。
- [LM Studio 官方接口](https://lmstudio.ai/docs/developer/rest)、[Chat Completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions)、[结构化输出](https://lmstudio.ai/docs/developer/openai-compat/structured-output)：原生 `/api/v1/chat` 与 OpenAI 兼容接口是不同协议。前者不接受 assistant 历史消息；本实现使用后者的预填与纯文本标题，不混用请求或响应字段。原生 `reasoning: "off"` 是否可用还取决于当前模型的加载路径，不能仅凭文档假定本机支持。
- 本地 `viral-title-agent`：借鉴“标题是点击承诺而不是摘要”与正文兑现检查；用户指定的 3–5 条原题逐条改写流程优先于技能的默认十二候选建议。

按钮流程由 `history-title-local-writer.ts`、`history-title-rewrite.ts`、`cover-editorial-plan.ts` 与 `history-script-delivery.ts` 实现。新自动记录为 `publishing_version: 'platform-v1'`、`selection_mode: 'curiosity'`、`reviews: []`，当前状态 `coverPlanStatus: 'selected'`；全部原题和改写保留在 `title_rewrites`，只有选中结果拥有完整配套。不把未执行的审核标成通过或失败。既有真实审核方案仍显示 `approved`；正文或方案变化为 `outdated`，无策划记录为 `missing`。没有新版本标记的旧方案继续按原25字标题、200字描述及原改写指令读取，不改写历史文案。

手工保存与自动生成都允许保留未符合平台格式的完整草稿。修改短标题会同步封面主标题，显式提交不同标题会被拒绝；百家号标题独立保存，单独修改它不使封面图片过期。新旧超长文案均完整显示和保存，不能静默截断；当前字段产生 `publishingWarnings`，不会把本次成功生成标为失败。发布准备将百家号标题填入其标题／作品描述字段，仍执行16／40字及符号限制；视频号描述完整保留。旧百家号冻结素材包保留原校验规则。

可选「审核当前方案」及 `/design/review` 接口保留；旧审核记录、非发布策划和固定方案审核保留既有原文。自动生成仅校验真实候选与来源编号、正文连续原句、输出格式以及生成期间正文或已保存文案是否变化，失败不覆盖旧方案。并发保护包含新增的百家号标题，避免后台结果覆盖后来保存的任何平台文案。

这些创作建议与好奇心选优不是点击率预测，也不是已完成事实审核的证明。格式正确、被模型选中或几次实际试生成，都不能证明真实点击率已经提高；仍需真人判断与发布后的同口径数据验证。
