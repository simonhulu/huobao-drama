# CBA 生产方案重构（2026-11-01）

本次将 `/cba-video` 的新生产任务明确分为新闻口播和比赛高亮，并把“新闻为何对应这场比赛”“录像是否真的在本地”作为可查看的生产依据。目标是减少信息单薄的数秒成片，并使素材能按比赛共享和复用。

## 现场诊断

改造前读取的77条新闻成片记录中，有19条不足30秒；18条集锦记录均不短于180秒。因此需要重点限制新闻内容与成片最低要求，不能简单将所有历史视频归为数秒片段。

原任务登记的47个不同原素材路径，在最初检查时全部缺失。历史记录中的 `media`、`matchConfirmed` 和下载成功信息不能证明文件现在仍存在；成片存在也不代表原录像存在。已从4份备份恢复14个原路径：先比对原登记SHA256，再用ffprobe确认视频、音轨和实际时长，最后建立硬链接恢复，未复制额外视频数据。已有新闻、集锦和上传回执继续保留。

## 两种产物

新任务以 `profile.productionPolicy:"cba-value-v2"` 启用规则，用户可以选 `news`、`highlights` 或 `both`。

| 产物 | 内容 | 建议时长 | 必须达到 |
| --- | --- | --- | --- |
| 新闻口播 | 根据原报道讲清事件，用对应比赛作背景 | 60–180秒 | 成片和有效比赛画面至少30秒，80个有效口播文字；实际语音至少20秒并覆盖成片一半 |
| 比赛高亮 | 按比赛进程组织精彩回合、关键转折与现场原声 | 180–300秒 | 至少90秒有效画面、3个已核验完整回合；标记 `completePlay:true` |

仅集锦任务不要求新闻口播或新闻版输出。同场比赛集锦只制作一次，后续不同角度新闻复用同场录像。新闻信息或画面不足时保留筛除/阻塞原因；最低要求不能通过重复画面、停帧、无依据扩写或大段无口播镜头绕过。旧交付不自动迁移或作废，页面展示质量提示。

## 双来源新闻筛选

默认来源是用户指定的虎扑 CBA 热榜 `https://bbs.hupu.com/cba-hot` 与新浪体育 `https://sports.sina.com.cn/`，由 `scripts/cba-video/news-intake.mjs` 采集。

虎扑读取热榜第一页实际列表，筛选已识别虎扑资讯作者的新闻帖，论坛讨论保留排除依据。新浪读取首页 CBA 标签实际使用的20条新闻接口；静态 `/cba/` 页含旧归档，不作为新入口。新浪CBA稿件可能位于 `/basketball/nba/`，必须结合标题、标签和正文判断，不能仅看路径。自媒体内容标为候选，生产前仍须可靠来源交叉核实。

真实整合请求读取到23篇候选：虎扑20个返回位置筛出12篇新闻，新浪20条筛出11篇；其余内容保留筛选原因。这是当次首屏快照的结果，不是全网站总数，也不表示23条已通过事实审核或已经出片。候选及来源证据摘要保存在 `data/reports/cba-production-refactor-20261101/news-sample.json`；完整原始响应快照保留在 `/tmp/cba-dual-source-snapshot.json`。

快照保存每源 `sourceReports` 和原始响应指纹，单源失败仍可处理另一个来源并显示部分成功；双源失败明确报错。候选交替排序，使有限条数生产覆盖两源。`listingPublishedAt`、正文发布时间和比赛日期分开；新浪正文实测存在两个冲突发布时间，模块保留冲突、让 `publishedAt` 待核实，不使用抓取时间代替。

## 新闻怎样对应比赛

关联顺序是“原报道中的日期、双方、比分、人物与事件 → 官方赛事记录 → 咪咕赛事页和回放归属 → 本地画面核验”。球队简称、球员姓名和发布时间只能提供线索，不能单独认定比赛。

新任务保存 `matchEvidence`：

```json
{
  "status": "confirmed",
  "reason": "解释原报道与比赛的对应关系",
  "sourceIds": ["保存了原文的真实来源ID"],
  "sourceExcerpt": "支持日期、双方和事件的原文摘录"
}
```

页面按新闻展示对应日期、双方、比分、关联理由和证据链接，并在比赛素材列表展示共享该场录像的任务。无法唯一确定时显示待核实及候选原因；转会、训练和多场盘点等可能没有单场比赛身份，明确保留非单场路线，不强行匹配。

匹配可以自动完成有充分证据的新闻，但不能保证每篇新闻都有唯一比赛，也不能保证咪咕为每场都提供可取得的录像。

## 录像是否真的下载了

比赛素材状态依据当前本地文件与核验记录分别判断：候选待下载、已下载待核验、已核验可用、本地文件缺失，以及搜索或下载失败。页面显示咪咕候选/来源链接、文件名、时长和核验状态；存在的本地录像可以播放核对。同场共享优先检查真实文件和指纹，不因任务中存在旧路径就宣称可用。

旧成片可以在原录像缺失时继续观看；再次剪辑需要恢复或下载原录像。搜索未完成、平台访问受阻、下载失败和非单场新闻各自保留原因，不合并成“没有视频”。

## 验证记录

新闻采集的新旧回归共13项通过，覆盖双来源、单源失败、双源失败、论坛观点和其他赛事筛除、URL去重、同场不同新闻、正文读取失败及发布时间冲突。真实请求已验证两来源均可读取。

真实页面已在3013验收：16场比赛，4场原录像可用，12场原文件缺失；其中一份咪咕录像实测319.12秒、1280×720，成功跳转到35秒。桌面与390px手机布局无页面异常和横向溢出，生产选择显示三个选项。浏览器验收没有发出写请求。截图和QA结果在 `data/reports/cba-production-refactor-20261101/`。

本次执行了真实新闻采集、原素材恢复、网页与播放验收；没有启动新一轮付费配音、批量生产或平台上传。新质量门槛通过合成视频的实际渲染和音轨检查验证；真实新闻的整体叙事质量仍需由下一轮制作及独立审核判断，最低时长不是内容质量的充分条件。
