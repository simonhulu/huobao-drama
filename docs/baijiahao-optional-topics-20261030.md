# 百家号话题选择与可选降级

## 原因

原代码把 `#热爆趣创赛#` 拼进作品描述，通过 `keyboard.insert_text` 一次输入。它没有选择平台的话题候选项，验证也只比较描述文字，因此普通文字被误当成完成话题关联。用户提供的 HTML 和真实浏览器复现确认了这一差别。

## 当前规则

发表前最后预检先核对原视频、文案和封面，再尝试添加话题。程序只选择末尾话题片段，用正常键盘输入 `#` 和关键词，等待平台候选列表，点击第一条可用候选。不固定话题 ID，也不要求候选名称完全匹配，不自行生成话题 HTML。

候选等待及选择共用最多 10 秒的预算。列表不存在、一直加载、返回空列表或选择未完成，清除本次末尾查询片段并跳过话题，继续发表；正文保持完整。旧版不支持的编辑器保留原文案并记录未添加话题。视频、正文、封面或账号本身的问题仍由原流程处理，话题可选不代表绕过这些检查。

已选择或已跳过的结果保存在原检查点的 `metadata.topicAttempt` 中，再次预检直接复用。此后不清空、重填描述。旧草稿转发表也在最后预检添加；已尝试话题的旧草稿不会重新调用全段填写。payload 及其指纹不变，保留原任务恢复能力。

回执匹配使用本次实际提交的描述，并校验正文与原任务一致，允许改变可选话题后缀。因此没有话题、或第一候选名称不同，均不会造成“平台已发表、本地因话题文字不符报错”。公开作品页面的可见话题文字仅作为观察记录，不再作为发表成功的必要条件，也不宣称文字存在就证明关联成功。

## 历史、Remotion、CBA 共用接入

`history-scripts` 与当前 `remotion` 页的自动发表都经过 `HistorySocialUploadService`；Remotion 成片交付通过 `requestHistoryVideoPublication` 进入同一个上传队列。`cba-video` 的新闻版和集锦版也使用同一个 Python 适配器，但原操作是保存草稿。本次保持各入口原有的保存/发表模式。

历史与 CBA 新建的百家号视频任务均传入 `tags: ['#热爆趣创赛']`，作品描述仍为原标题。适配器输入 `#` 再输入关键词，末尾不输入 `#`，等待并点击平台第一条候选。直接发表在发表预检执行；草稿上传新增在最后保存前执行。失败、空列表和超时都跳过话题继续原操作。选择或跳过后的实际描述写入原检查点，保存后的回执匹配采用该描述，之后不调用全段重填。

同时修复纯标题没有已有话题后缀时，折叠光标后按退格会删除标题末字的问题：只有实际选中末尾文字时才按退格。失败清理也遵守同一规则。没有改任务指纹算法或已存任务 payload；旧任务按原检查点继续，已完成作品不因补话题重新上传。
