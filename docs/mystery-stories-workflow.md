# 奇闻故事生产线

实施日期：2026-11-02。需求基准：[v0.3 需求](plans/2026-11-01-mystery-stories-prd.md)。

入口为 [奇闻故事工作台](http://localhost:3013/mystery-stories)，包含生产工作台、故事库、频道采集、成片与发表。当前频道和账号为空，等待在页面配置；未预设或猜测用户指的是哪个 YouTube 频道。

## 使用

1. 在「华生账号」创建并登录奇闻故事专用账号；只生成文稿时可先不配置。
2. 导入单视频，或添加频道后启动批次。导入本身只记录来源；选择「只生成文稿」「制作视频」或明确选择的发表目标后开始处理。
3. 来源默认下载有声完整视频，另可选择音频。完整原始转写、校对稿、真实时间块和源文件保留，支持继续未完成的转写。
4. 在「原稿理解」查看主题、讲述目的、心理需求、情绪推进、悬念揭示和辅助故事档案。主要为外语的来源先生成逐句保义中文底稿，保留原文与译文的位置映射并审校。
5. 在「轻改稿」查看完整原文与结果、每处修改及理由。可以局部等义修改、恢复原句、另存版本；后台轮询不会覆盖本机草稿。元数据保存和文稿保存都检查版本冲突。
6. 华生制作绑定具体文稿版本和账号；自动沿原项目制作、导出、下载，检查实际画面、音轨、时长、尺寸和指纹。视频可用之后准备故事标题候选、简介、标签及独立横竖封面，支持下载 ZIP 包。
7. 百家号仅在明确选择发表目标、账号、创作声明和水印时执行。批次发表对每篇使用各自生成的文案。提交待审核与已经发表分别显示；未知结果继续核对原上传记录。

## 原文保留机制

`mystery-script.ts` 先理解完整原稿，再让编辑模型返回局部替换清单。最终文稿由程序对原文应用清单生成；清单范围外的字符不经模型重新生成。每处修改绑定来源指纹、原文位置、原文字面、替换值、类别和理由。

- 原句可以完全不改，没有最低改动率。普通修改限词组或单句；禁止整篇、跨段、跨句替换、重叠修改和删除故事正文。
- 作者身份、广告和亲历归属只处理分析中标出的精确范围，不删除其中交织的故事内容，也不冒认原作者经历。
- 检查句义、内容完整、全文衔接、原作体验和身份处理；检查结果绑定原稿、文本、分析与人设四个指纹。普通修改不合格时优先恢复原句；仍有问题的版本保存待处理状态，不能送入华生。
- 原稿、译文、分析、局部替换、版本和旧成片均保留。v1 制作时可以另存 v2；v1 完成不会把 v2 或后来变更的原稿标成已经制作完成。

## 恢复与文件

新领域记录使用现有 SQLite 数据库中的 `mystery_stories`、`mystery_channels`、`mystery_collections` 等独立表。来源按 YouTube video ID 去重；运行通过现有持久任务队列执行，并使用任务租约及故事/账号资源锁。关闭页面不会取消任务，用户停止的运行不会自行恢复。

创建、导出和发表保存原编号和发送检查点。结果不明时不重复创建；页面可补录原项目或原导出编号后继续。封面失败保留有效 MP4，仅继续封面和包装。重复封面按钮不会改变正在生成的封面版本。

文件写入 `data/mystery-stories/`，登记归属并保留引用。归档隐藏故事，不删除恢复和原稿核对所需文件。ZIP 包包含绑定版本的正文、原稿、分析与对照、来源与档案、发布文案清单、视频及封面。没有取得成片字幕时不把源视频的时间码冒充新成片字幕。

## 本地运行

正常后端启动时，`backend/src/index.ts` 已注册 `/api/v1/mystery-stories` 和两个持久任务处理器。

当前采用独立本地服务运行新工作区，保留正在运行的历史/科普后端：

```sh
cd backend
npm run start:mystery
```

服务默认监听 `127.0.0.1:5682`，只领取 `mystery.workflow` 和 `mystery.collection` 任务；恢复检查也限定这两种类型。前端本地 `.env` 设置 `MYSTERY_API_TARGET=http://127.0.0.1:5682`，将这个工作区的 API 代理到独立服务。日志位于 `data/mystery-server.log`。以后统一使用主后端时，移除该代理设置即可。

以上模型和华生流程测试使用注入结果，证明机制与恢复行为；尚未用用户指定视频验证真实模型的讲述质量、ASR 质量、华生成片或实际发表。用户尚未提供具体来源频道和已登录的新工作区账号。
