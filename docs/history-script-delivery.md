# 历史脚本关联成片与封面

> 2026-10-28 更新：当前为两版成片、原标题改写和百家号直接发表，见 [现行流程](history-workflow-upgrade-20261028.md)。下文涉及自动公众号文章、视频号短标题及共同标题的内容仅为旧版记录，不再用于新制作。

> 2026-10-31 更新：花生版与精细化版各自在成片落盘并关联后自动生成独立标题和封面。页面和包装操作按 `video_id` 切换；上传只使用对应成片在 `history_video_packaging` 中的包装。旧稿件级数据保留兼容，不自动复制给两版。接口、重试及既有发表回执处理见 [每版独立的标题和封面](history-workflow-upgrade-20261028.md#每版独立的标题和封面)。

在 `/history-scripts?script=<id>` 选择脚本，详情下方的「成片与封面」用于准备发布素材，不上传平台，也不创建剧集或执行配音、分镜、渲染。

1. 可以在视频制作中启用自动导出产物，或对已有项目执行“生成产物”，由后台下载并关联花生成片。也可手动下载后，在对应稿件的「成片与封面」点击「提交成片」。支持 MP4、MOV、M4V、WebM，最大 4 GB；文件经 FFprobe 校验后关联，采集来源视频不受影响。成功关联后，后端自动生成公众号文章，无需再次点击生成；「查看公众号」打开文章进度或产物。产物自动任务还会接续标题、简介与封面方案，详见 [自动产物流程](history-huasheng-automation.md#自动导出下载与生成产物)。
2. 点击「生成标题、简介与封面方案」。系统从当前稿提词联网搜索，通常选出 3–5 条真实原题，只有 1–2 条相关参考时按实际数量使用，再调用本地 LM Studio 的 `qwen3.5-9b-writing-dpo@q4_k_s`，关闭思考，用指定系统指令逐条改写为16字以内的短标题。零条或全部不相关时，由项目文本模型基于正文原创一个标题。多候选先按好奇心与求知欲比较选出一条，单候选直接采用；随后只为选中标题配套百家号标题、视频号描述和封面，不执行质量审核或因审核意见重新生成。一次保存整套文案，封面主标题与视频号短标题逐字一致，后续配套不得改题。页面可查看全部原题与改写、选中理由和完整配套。生成或本地模型失败不覆盖旧文案；生成期间其他窗口保存了文案也会拒绝覆盖。方法及运行要求见 [历史视频标题创作](history-publishing-copy.md)。
3. 填写同一个视频号短标题与封面主标题，以及无字画面提示词后，即可点击「生成三种尺寸封面」。可修改共同标题、副标题、角标和画面提示词，生成时直接保存并使用当前内容，无需先保存或审核。短标题按16字、百家号标题按40字提示发布限制，含标点、空格；超长或符号不合规仍可作为草稿保存和生成封面。两处共同标题联动，显式提交不同标题会被拒绝。百家号标题独立填写，单独修改它不使封面图片过期。「审核当前方案（可选）」仅供参考；没有审核、审核过期或审核未通过都不阻止生成。横竖底图分别生成，中文标题由本地排版合成：3:4 为 900×1200，4:3 为 1200×900，16:9 为 1280×720。页面显示进度、失败原因以及预览/下载入口。
4. 将同一个脚本链接交给独立 `publish-baijiahao` 或 `publish-wechat`。准备阶段直接读取关联成片和封面，不需要 `history-video-publish`。

视频号封面上传失败后的重试只执行 `node scripts/wechat/operate.mjs --manifest '<wechat.json>' --step cover`。该模式先确认发布页视频已上传完成，再确认 3:4 和 4:3 封面上传成功；不重复校验或回填标题、简介、封面指纹和尺寸。完整上传流程也只以视频和封面上传状态判定成功，标题与简介仅尝试填写。

生成提示仍以视频号短标题16字、百家号标题40字为目标，但完整非空结果不因长度或符号问题被丢弃。系统继续选优、生成配套并回填，`designStatus` 为 `completed`；GET 返回由当前文案计算的 `publishingWarnings`。页面显示黄色提示及实际字数／上限，三个标题均可完整展示和修改，允许保存未改完的草稿，修正后提示即时消失，刷新后按已保存内容恢复。短标题与共同封面主标题仍逐字一致。

发布准备仍严格执行视频号16字、百家号40字要求。字数含标点、空格，计数使用 JavaScript `String.length`。视频号描述不设应用层字数上限，默认2–3句自然预告，发布准备和填入保留完整描述，不按200字截断。百家号没有单独生成的简介，独立标题承担其标题／作品描述用途。旧冻结素材包保持兼容。

三个标题字段发布时支持书名号、引号、冒号、加号、问号、百分号和摄氏度；中英文逗号替换为空格。生成与保存草稿时，其他符号、换行和隐藏字符保留为人工修改项，不能因此丢弃或删截标题；发布准备仍拒绝不支持的符号。空响应、截断、无实际文字或无法解析的模型响应仍是错误，不能伪造完整结果。封面副标题、角标与描述不受标题符号限制。百家号采用 16:9 和 3:4，视频号采用 4:3 和 3:4。

成片和封面分别记录所依据的正文 SHA256。正文变更后页面提醒核对，发布工具拒绝使用旧版本；请重新关联匹配的成片并生成封面。更换视频或封面失败会保留旧文件。封面方案修改后需要重新生成，旧图片仍保留供预览。生成失败不会悄悄退回视频截图。

封面失败后可点击「重试生成封面」。502、网络超时等导致回执未知且没有远端任务 ID 时，本次运行停止，不自动重复付费提交；下一次明确重试会为失败方向新建生图记录，保留原失败记录，继续使用绑定的图片服务配置。已完成的底图和合成文件会复用，已有远端任务 ID 则继续查询原任务。只有仍在生成中的任务会拦截重复点击；中断后租约过期也可重试，不会因 `HISTORY_COVER_SUBMISSION_UNCERTAIN` 永久锁死。原请求回执未知时无法保证服务商未计费，页面会在重新提交前展示可能再次计费的提示。

## 提交成片后自动出文

视频关联和 `history_script_article_queue` 待办在同一 SQLite 事务提交，固定原文、脚本及视频指纹。最终提交时再次检查稿件版本和旧成片关联，拒绝并行上传覆盖。视频成功关联后即与文章执行结果分离；文章失败不移除已提交视频。

GET delivery 的 `articleGeneration` 为 `null`，或 `{ status, message }`，状态是 `queued`、`generating`、`completed`、`failed`。前端轮询时保留未保存的封面文字，并在状态变化后刷新文章。上传响应丢失时先读取当前成片核对，不自动重传视频或重发文章请求。

后台 worker 仅处理上传事务留下的待办，不扫描历史成片补建文章。待办跨重启保留；已完成且版本匹配的文章直接复用，正在生成的文章只等待结果。模型调用意图先落库，失败或启动结果不确定时保留失败原因，不自动重复付费生成；在公众号页明确点击生成可重试。文章仍基于完整纠错原文独立二创，不限制字数，配图取自关联成片。后端进程需保持运行，可用 `HISTORY_ARTICLE_WORKER_DISABLED=1` 关闭自动待办 worker。

数据存储：`history_script_deliveries`，以 `script_id` 唯一关联脚本；`title` 为视频号短标题，新增 `baijiahao_title` 为百家号标题，`description` 为视频号描述。GET／PUT 使用 `title`、`baijiahaoTitle`、`description`；旧行的新字段默认为空，读取不改写旧文案。素材位于 `data/static/history-deliveries/<id>/`。不混用来源视频的 `media_json`，不伪造 episode ID。三种尺寸封面图片在历史脚本 API 进程中后台生成，页面离开后继续；进程中断后的租约过期会标记失败，可重新生成。

标题、简介与封面方案也由后端后台生成：`POST /design` 接受任务后立即返回 HTTP 202，GET 返回持久化的 `designStatus`（`idle`、`generating`、`completed`、`failed`）、`designRunId` 和 `designError`，与图片的 `coverStatus`、`error` 分开。刷新或离开页面不停止任务，重新进入后根据生成中状态恢复轮询，完成后回填整套文案；失败原因保留，允许重新提交。运行期间拒绝重复生成、可选审核及生图；其他窗口手工保存仍允许，但后台结果不能覆盖后来保存的修改。视频上传独立，不受文案生成影响。提交时固定当前正文与文案基线，结果和完成状态一次性保存；过期任务的迟到结果不能覆盖新任务。

文案后台任务在当前 API 进程执行，每30秒续约，租约有效期120秒。浏览器刷新不影响执行；后端进程中断则不自动续跑，租约过期后下一次读取会标记中断并提示重新生成，不会永久显示生成中。已保存的标题、简介、方案和素材保持不变。

自动策划只做选优，不执行自然通顺、情绪、因果承诺等质量审核，不调用 `history-title-review`，也不因 `title_hook`、`title_emotion` 或审核布尔值否决、重做候选。多候选先使用 `history-title-select` 比较短标题，单候选无需选优调用。配套格式失败最多只重试一次配套，不重新搜索、改写或选择。正文贴合、情绪与画面一致性仍是创作提示，不是自动保存门槛；必要格式、来源绑定和正文原句校验保留。可选的「审核当前方案」仍可手工触发，结果不作为生成图片的前置条件。选优或审核都不保证点击表现。

每次自动策划搜索今日头条、百家号同题标题。`title_research` 保存完整检索快照，`title_rewrites` 保存指定模型、原样系统指令、短名单及一一对应的原题和改写；`reference_ids` 和借鉴说明由宿主绑定。搜索摘要仅供存档，不进入配套写作或选优，不能作为新事实依据。参考缺失或全部不相关时保留真实检索记录与原创原因，不伪造网络来源。运行需已配置 `MiniMax.web_search` 的 `mcporter` 及可用的指定 LM Studio 模型；旧方案无需补搜或启动模型即可查看与手改。

策划记录由服务端保存在 `cover_design_json.editorial_plan`，包含版本、候选、选中理由及正文/方案摘要。新自动方案保存 `publishing_version: 'platform-v1'`、`selection_mode: 'curiosity'`、`reviews: []`；`title_rewrites` 保留全部改写，`candidates` 只保存一套选中成品，包含 `video_title`、`baijiahao_title`、`video_description`。不伪造审核通过记录。GET 分别返回 `coverDesign`、`coverPlan`、`coverPlanStatus`：当前自动选优方案为 `selected`，有真实通过审核记录的旧方案仍为 `approved`，正文或方案变更为 `outdated`，无记录为 `missing`。旧25字方案与原改写指令继续兼容读取，超长标题完整展示和保存。可选审核接口与旧审核记录继续保留。客户端不能提交或伪造策划、选优或审核记录；生成图片保留已有记录，不会把未审核方案标记为审核通过。生成或审核期间正文、已保存方案或任一平台文案变化时拒绝覆盖。生成仍校验当前脚本、必要字段和重复任务，并在失败时保留旧素材。

接口前缀 `/api/v1/history-scripts/:id/delivery`：GET 读取、PUT 保存文案/方案、PUT `/video` 上传原始文件流（`X-File-Name` 为 URI 编码文件名）、POST `/design` 后台生成候选并按好奇心选优（HTTP 202，单候选直接采用，无质量审核；通过 GET 跟踪结果）、POST `/design/review` 可选审核当前方案（正文与 PUT 相同）、POST `/covers` 按当前提交或已保存的方案直接启动三比例生图。

独立发布准备命令（工作目录 `backend/`）：

```sh
node scripts/baijiahao/prepare.mjs 'http://localhost:3013/history-scripts?script=10'
node scripts/wechat/prepare.mjs 'http://localhost:3013/history-scripts?script=10'
```

以上仅准备并校验发布清单，不打开平台、不上传、不保存草稿。
