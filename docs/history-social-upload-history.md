# 历史上传旧版实现与验收记录

以下是 2026-10-26 简化上传结果之前的历史记录，不代表当前操作流程。当前规则见 [历史项目平台上传](history-social-upload.md)。旧版的自动恢复、续传、结果待确认和人工核对入口已取消。

# 历史项目平台上传

入口：`/history-scripts` 的「上传队列」，或稿件详情的「平台上传」。制作看板的已完成项目也有上传入口。

## 使用

1. 关联下载好的成片，准备既有发布标题、简介和封面。百家号图文复用项目已生成的独立文章及其本地配图，不重新生成文案。
2. 单项目直接打开「平台上传」；批量在「上传队列」先筛选「待上传 / 已上传 / 全部」，再全选当前筛选结果或多选项目。默认显示待上传；平台默认勾选百家号视频、百家号图文、视频号视频。
3. 「预检素材」只读取素材和登录状态。表格按项目、平台、内容形式列出缺项；不能上传的项不会被伪装成成功。
4. 默认「上传到草稿箱」，自动上传并保存草稿，不再逐次询问。只有主动选择「仅上传预览」才停在编辑页。两者都不会点击公开发布；接口省略 `mode` 时也默认 `draft`。
5. 队列状态独立持久化。刷新页面只读状态，不重复创建任务。可恢复故障自动读取检查点，继续未完成步骤；保存结果不明时自动核对草稿箱。仍无法处理的目标单独保留，其他目标继续上传。

上传完成按「项目 + 平台内容形式」记录。平台确认保存草稿后自动显示「已上传」，附确认时间；用户确认的历史记录显示「人工确认已上传」。选择某平台时只提交尚未上传的目标，重复提交或更改本地标题不会再次上传已完成目标。全部目标已上传的预检直接返回结果，不再检查浏览器或已删除的旧素材。上传历史保留，可通过「已上传 / 全部」筛选查看。

点击任一成片筛选（包括当前已选的「待上传」）或重新回到窗口时，重新读取本地上传标记，保证已有页面能看到补录或其他页面保存的结果；不触发平台浏览器检查。取消全部平台选择时，筛选仍按全部目标的已上传记录判断，不把旧稿误列为待上传。已人工确认上传而停止重试的历史任务显示「已上传（人工确认）」。此修复已通过 170 项前端回归，覆盖旧页面中的 #67/#73 标记更新和 #74 边界。

历史标记接口：`POST /uploads/mark-uploaded {"sourceIds":[71],"targets":["baijiahao-video","baijiahao-article","tencent-video"]}`。仅保存人工确认，不访问平台、不伪造草稿 ID；已有平台成功凭证优先保留。正在执行的目标拒绝标记；尚未执行或待处理的旧任务停止重试并保留历史。

## 后台 CLI 上传

默认草稿任务由现有 `social-auto-upload` Python CLI 在独立后台 Chrome 中执行，登录资料保存在持久 profile，不抢占前台窗口。百家号视频、百家号图文、视频号视频共用串行队列和原有保存检查点。CLI 内部仍通过平台网页上传；百家号图文使用本项目扩展。

首次使用时只读导入原历史专用 Chrome 的平台登录，在后台验证成功后保存。历史账号与 CBA 账号隔离；登录文件放在私有 `data/social-auto-upload/history-sessions/`。后续复用后台会话，登录失效时在原专用窗口登录，再点击对应「同步登录」。同步验证失败保留原会话；队列执行时不允许替换登录，避免切错账号。

后台模式的运行环境区始终提供「打开百家号登录窗口」「打开视频号登录窗口」，即使当前状态为「检查失败」「上传正在运行」或已就绪，也可主动打开原专用 Chrome。此按钮只打开可见窗口；完成扫码／安全验证后，待当前上传结束再点击对应「同步登录」导入后台。打开窗口时清除上一次同步提示，避免旧成功消息与本次操作混淆。2026-10-26 已通过 49 项登录／运行环境相关前端回归（含真实 Nuxt 模拟交互），真实打开百家号接口返回 `opened:true`。

已开始的旧任务保留原账号、可见编辑页及检查点，从原处恢复；尚未执行的新草稿任务使用后台。主动选择「仅上传预览」仍打开可见编辑页。后台任务的「打开平台」打开草稿链接，不尝试将无头页面切到前台。

平台上次检查未登录或连接失败时，「上传到草稿箱」仍可点击，会重新预检；预检不通过则逐项说明本次未上传的原因。按钮暂时禁用时，下方显示具体原因。需要连接浏览器的运行环境检查、预检、提交、登录及打开平台请求最多等待 90 秒，覆盖后端 75 秒检查预算及退出时间；普通队列读取最多等待 60 秒。超时解除页面等待；已提交但未收到回执的请求仍先核对队列，不重复提交。

失败后的操作：在上传队列选择「待处理」，单项点击「重试上传」或「重试并核对」，也可以点击「批量重试失败项」。操作把原任务重新排队，立即返回，不要求等待其他上传完成，也不在 HTTP 请求中等待浏览器。缺素材的任务提供「查看并补齐材料」入口；补齐后重试会读取当前素材，更新尚未上传的任务快照。已经开始上传的任务保留原快照和检查点，从未完成步骤继续；点过保存的只核对实际草稿。已保存、正在上传或已经排队的任务不重复执行，批量请求逐项返回接受和跳过结果。

恢复接口：`POST /uploads/jobs/:id/retry {}`，`POST /uploads/jobs/retry {"jobIds":["21","23"]}`，返回 HTTP 202。任务编号与原提交时间保持不变；手动重试重新给予两次有限自动恢复机会。重试时素材仍不足会重新显示具体缺项，不会永久禁用重试按钮。重试的旧快照若已有其他对应上传任务，则指向该任务并跳过重复上传。

「重试并核对」与「核对草稿状态」有明确区别：后者保持只读；前者除核对草稿外，可在原页面证明平台因表单校验拒绝保存时修复该错误并继续原保存。已保存、正在保存、页面被替换或没有明确拒绝证据时，不能用重试绕过防重复保存。

2026-10-23 重试验收：原任务 18、19、20、25 通过批量接口立即重新排队，重新检查后分别报告 #62 的封面／配图与 #67 的文章缺项，没有建立新上传任务。真实本地页面验证「待处理」筛选、材料入口、POST 网络失败后解锁、再次点击返回 202、缺素材后仍可重试，页面无运行异常。界面验证期间只替换运行环境查询，避免为了验证界面额外打开平台浏览器；上传队列与单项重试使用真实后端。

本批实际恢复：#66 的百家号任务 21 已通过原任务重试核实草稿 `1879839061486449024`，原保存时间为 19:17:12；没有再次上传或保存。视频号任务 23 在原页面确认「网络出错，请重新上传」且尚未尝试保存后，重传原视频、填写文案与封面、保存草稿，并于 20:45 从草稿箱读回核实。两项均为 `saved:true,published:false`，仍使用原任务编号。

本次变更涉及 `frontend/app/components/HistorySocialUpload.vue`、后端 `routes/history-social-upload.ts`、`services/history-social-upload.ts`、`services/social-auto-upload.ts`、`scripts/social-auto-upload/bridge.py` 及对应回归测试。验证包括前端 136 项、后端 126 项、Python 恢复 74 项、类型检查，以及真实队列按钮和三个原失败任务的恢复；实测发现的空草稿 ID 差异另经 7 项拒绝保存恢复测试复核。

## 平台边界

| 目标 | 运行方式 | 必需素材 |
| --- | --- | --- |
| 百家号视频 | 现有 social-auto-upload 安全上传扩展 | 关联成片、百家号标题、16:9 和 3:4 封面 |
| 百家号图文 | 本项目扩展，不是上游原生功能 | 当前独立文章、文章标题、至少两张不同的清晰正文配图、4:3 主封面 |
| 视频号视频 | 现有 social-auto-upload 安全上传扩展 | 关联成片、视频号短标题、简介、4:3 和 3:4 封面 |

不设置文稿篇幅、文章质量或审稿门槛。检查平台技术限制、素材可读性、归属及版本、登录状态，并按用户要求筛选清晰封面配图。超出实际控件限制时报具体字段，不静默截断。

百家号新版视频编辑页只有「作品描述」，没有独立长简介框：复用已保存的百家号标题填入该字段，完整简介仍保留在项目中。视频号使用其短标题和简介，不重新创作。

## 安装与登录

### 登录故障与草稿核对恢复（2026-10-25）

- 正常草稿任务仍由 SAU CLI 在无头 Chrome 执行；登录操作使用有界面的原专用 Chrome。任务行遇到登录／验证阻塞时提供「打开百家号／视频号登录窗口」和「同步登录」，无需寻找隐藏的后台窗口。同步后重试原任务，不重新提交项目。
- 当前上传未结束时，可以先打开登录窗口完成扫码／验证；同步登录等待当前上传结束，避免执行期间替换账号。可见浏览器的登录与后台登录是两个会话，只有同步验证成功才代表后台登录恢复。平台仍要求后台会话单独验证时，不能把可见窗口已登录当作上传成功或自动绕过验证。
- 登录、连接、保存核对失败不再统一提示「补齐素材」。只有实际素材缺项才显示材料入口；其他错误显示对应恢复动作。
- 视频号冷启动直接访问 `/platform/post/draftListManager` 会被页面跳回首页。只读核对改为先加载首页，再通过「内容管理 → 草稿箱」进入；只对自己的核对页设置 1440×1000 桌面视口，避免无头默认 800×600 下菜单被微前端图层遮挡。按原文案与保存时间匹配草稿并打开核对，不重新上传、保存或发布。
- 百家号图文初始化失败时，如果检查点与原页面均证明尚未上传／写入／保存，而且页面完全空白，自动单次重载原页后继续。已有正文、输入、图片、可见或含内容的 iframe、保存尝试时不重载；允许加载失败后残留的隐藏空 iframe。
- 新图文编辑页的 `edit-<账号>-news` 缓存按任务隔离到当前标签的 `sessionStorage`：首次读取保留设置、清空旧正文；之后刷新仍恢复本任务缓存。不会删除或改写共享缓存，也不影响已有 `article_id` 草稿、其他页面或登录。旧失败任务仅在从未写入素材、标题和正文为空、配图与共享缓存精确对应时，保留原页和检查点备份，在同一任务下建立隔离的新编辑页继续；未知内容仍保留待处理。
- 本批 #127 的登录阻塞发生于 21:24；后来同一后台会话已可正常打开首页。旧错误记录不是当前登录结论，先重试原任务重新检查，无需仅凭旧提示反复更换登录。

本批真实验收：稿件 #127／#128／#129 的任务 36–44 共 9 个目标均为 `saved:true,published:false`。视频号任务 38、41、44 的 `saveClickedAt` 保持原值，通过草稿箱回读纠正状态，没有重复保存；图文 40、43 保留原缓存页面和检查点备份，以原任务完成隔离编辑并回读核实。相关 Python 回归 98 项、前端原套件 177 项及追加的登录错误分类定向测试通过；非文本内容恢复边界另经 4 项图文恢复测试复核。后续批次仍需按实际平台反馈处理，不以这批验收替代所有长期稳定性验证。

默认复用 `~/.local/share/social-auto-upload` 和其中的 `.venv/bin/python`。需要现有 `stage_only`、`cdp_url` 安全扩展以及对应的 `stage.py`；缺少扩展时拒绝回退到上游直接发布入口。不会自动覆盖本机安装或升级依赖。

原历史登录窗口分别使用独立 Chrome CDP：百家号 `127.0.0.1:9225`、视频号 `127.0.0.1:9222`。登录和验证码由用户在这些窗口完成；新草稿任务导入登录后在后台自己的标签中执行，旧任务和主动预览仍使用原窗口。

如果调试端口仍响应，但浏览器会话已经失效，预检会说明具体原因。「登录平台」入口可以恢复空的专用浏览器：核对本机监听 PID、官方 Chrome 路径、项目 profile 和端口，确认没有任何 target 后才终止该进程并重开；已有页面、归属不明或超时均停止并说明原因。此恢复只在主动点击登录时执行，不在状态检查或定时刷新中重启、弹窗。

可选配置见 `backend/.env.example` 中的 `SOCIAL_AUTO_UPLOAD_*`。持久队列与请求回执保存在主数据库的独立表中；私有浏览器检查点和截图位于 `data/social-auto-upload/`，不放到静态资源目录，也不纳入 Git。

## 完成后的资源释放

后台 Chrome 启动时默认加 `--mute-audio`，上传、封面预览和核对页面均不向扬声器播放声音。对于尚有恢复任务、不能重启的旧浏览器，连接时对现有视频／音频（含 shadow DOM）静音，并为后续页面和播放动作安装静音保护；不因禁音失败中断上传。2026-10-26 已实测稿件 #115 的任务 #71 原恢复页曾有视频有声播放，现场暂停静音后，任务在 02:10:30 点击保存、02:10:40 从草稿箱回读完成，原标签页及该后台浏览器随后退出。静音／连接／生命周期相关 22 项回归通过。

草稿确认保存后关闭本任务的原上传页；平台核对用的临时页也会关闭。预览、失败和结果待确认页面保留，继续使用原检查点恢复。清理失败不把已保存草稿改成失败，也不触发重传。

历史专用后台浏览器在没有上传／恢复页面时自动退出 Chrome 进程，磁盘 profile 和登录文件保留。下次使用按需启动，并保留 profile 中已经更新的 Cookie，不用旧导入快照覆盖。后台登录检查和同步完成后也释放空闲浏览器；账号操作锁与 profile 锁保护清理和启动，页面或进程归属不明时不强制关闭。

2026-10-26：独立真实 Chrome 完成两次启动／退出验证，两个进程均退出，更新后的测试 Cookie 在重开后保持。生产账号在空闲退出后重新检查，两平台均返回 `ready:true`，总用时 8.6 秒，随后后台进程退出；未要求重新扫码。任务页清理的真实隔离浏览器验收也通过：只关闭原任务页，保留无关页面；最后空闲时 Chrome 进程退出。补充识别 Chrome 自身 `browser_ui` 与扩展 `background_page`，避免把内部后台目标误当作未完成网页；资源释放专项回归 29 项通过。

## 可靠性

- 项目编号使用历史素材 source ID，不是 episode ID。
- 提交请求有唯一 request ID；已上传标记优先阻止重复任务，尚未完成的任务再按项目、平台与素材指纹去重。
- 任务执行前再次检查素材和项目版本，变更后阻塞，而不是上传旧快照。
