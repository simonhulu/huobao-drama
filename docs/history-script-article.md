# 历史原文转公众号文章

入口：在 `/history-scripts` 选择稿件，在「成片与封面」关联最终成片，然后在「微信公众号文章」生成文章。不设置目标篇幅或字数限制，也不提供篇幅选择器。生成完成后提供排版预览、文字查看、内部截图时间查看、富文本复制及 HTML／Markdown 下载。

文章基于具有当前检查点的完整校对原文 `correctedTranscript` 二创，面向 40 岁以上读者写成独立可读的公众号文章。模型使用自己的段落表达和章节组织，保留原文的事实、人物关系、因果、条件及不确定性；无需逐句摘录或沿用口播顺序。完整原文提供给模型，不先按字数截断或摘录压缩，不传目标字数，也不按正文长短拒绝保存或重试。

模型通过 `sections[].paragraphs[].text` 返回文章正文，`highlights` 为可选的段内强调文字。改写段落的 `sourceEvidence` 可以是空数组，不伪造逐字引文或原文位置，也不依赖证据数组重新拼接正文。旧 `sentenceIds` 和 `quotes` 格式仍兼容读取、转换；新生成以独立文章正文为主。生成过程会在本地清理“本期视频”“上期讲过”“点赞关注”等视频串场和操作套话，不增加质量审核模型或篇幅判定。

生成调用正文二创模型，随后直接截取成片画面并排版保存，不调用独立的保真审核模型，也不进行审核反馈修复。新文章不写入审核通过记录，旧文章不再因缺少审核记录或审核版本不同而禁止导出。正文仍须可用；模型请求失败、响应结构不可用、超时或取消按原有失败处理保留前一篇。原文、校对稿、二创稿、来源版本与任务锁保护保持不变。

正常生成调用一次文本模型。遇到已识别的连接超时或连接重置，最多重试一次；不重试鉴权、额度或其他未知错误。两次尝试共享六分钟时限，本地也强制执行该时限，即使模型服务忽略取消信号，任务仍会结束并显示超时；迟到响应不会覆盖结果，已取消或超时的任务不再调用模型。

模型返回的附加展示字段不阻塞生产，例如章节上的 `highlights`、根级说明或段落额外元数据会被忽略，实际标题、章节、正文完整保留。只有正文结构确实不可用时才报错，不为无关字段重复调用模型。回放稿件 #74 的真实失败响应后，8 个章节、25 个段落全部保留，无需再次生成。

普通生成使用 `selectionMethod=model-adapted`。旧存档的 `model-extractive` 与内部维护样稿的 `manual-source-exact` 继续兼容；该字段仅记录生成方式，不表示经过人工或模型审核。HTTP 接口不接受自定义正文、维护模式标记或审核结果。

截图关联与提取流程不变：只取关联的最终成片，不用采集来源视频或 AI 生图替代。使用 FFprobe 检查视频，FFmpeg 截取 3–5 张，优先取视频章节中部，没有章节时按时长均匀取样并避开首尾。每个取样点附近最多 ±1.5 秒内比较五个候选画面，短视频及相邻取样点会进一步收窄范围；以画面主体的拉普拉斯清晰度评分择优，评分忽略底部常见字幕区和边缘。输出保留完整画面及原视频分辨率，使用高质量 JPEG（q=1、4:4:4），不缩放、不裁切、不额外锐化。评分只用于相邻候选比较，不能恢复原片丢失的细节，也不保证消除噪点或字幕。截图时间戳保留在内部元数据和工具页面，公开文章的图片说明不显示时间戳。章节配图按位置分配，不声称已完成语义画面匹配。

截图完成后，在文章生成阶段完成清晰主体、明显模糊、马赛克和重复画面的筛选，选出两张用于后续三图封面的正文图。背景虚化但主体有足够连续清晰区域的镜头可以使用。结果连同图片 URL、内容 SHA256 和评分写入截图目录的 `body-cover-selection.json`，完成后才将新文章标记为完成；确实不足时在文章生成阶段说明原因，保留上一版文章。上传阶段直接消费该记录，只检查文件和版本是否一致，不重新审核图片质量。已有文章可以单独准备这份记录，无需重新生成正文。

HTML 使用 `gzh-design` 的红白主题与通用图片组件：内联样式、`span leaf` 文字、中文章节标题、章节编号、关键词下划线、响应式截图，不再添加 `HISTORY`、`ANALYSIS`、`THE END`、`END` 等英文装饰标签。正文片段可粘贴到公众号；下载的 HTML 内嵌真实 JPEG，离线打开可看图。Markdown 保留站内图片路径，适合在当前项目内继续编辑，图片说明同样不带时间戳。复制后需要在公众号编辑器检查图片上传结果。此功能不执行发布。

公开文章在正文结尾自然结束，不附加素材来源、原视频链接、署名、账号自我介绍或推广文案，不读取本机作者介绍配置。来源记录继续保存在脚本元数据中。

接口前缀 `/api/v1/history-scripts/:id/article`：

- `GET /`：返回生成状态、旧／新文章、过期原因及生成前提。
- `POST /`：JSON `{}` 启动一次后台生成，前端轮询状态；重复运行被任务锁阻止。兼容旧客户端可选的数字字段 `targetLength`，但忽略其值，不向模型传递目标篇幅；新文章不再写入 `targetLength`。
- `GET /export?format=html|markdown`：下载文章；HTML 内嵌截图，不依赖本机图片 URL。

产物在 `STORAGE_PATH/history-articles/:id/`（默认 `data/static/history-articles/:id/`）独立保存。按原文内容、来源元数据、成片脚本与视频文件指纹检测过期，生成期间版本变化会拒绝覆盖，失败保留前一篇。任务最长十分钟，进程意外中断后十二分钟租约到期可重试。过期文章仍可预览，重新生成后才能复制或导出。

已保存文章读取时使用原有章节和截图重新排版，因此刷新预览、复制及 HTML／Markdown 导出都会去掉旧的来源、署名和账号介绍页脚，无需重新调用模型。磁盘中的旧存档、正文、生成时间、旧生成方式和旧 `targetLength` 字段不改写，也不批量重生成。重新生成成功后，该篇才采用新的完整原文二创规则；截图仍从原先关联的当前成片提取。

失败状态另带脱敏诊断：失败阶段、JSON／结构／来源验证类别和有问题的字段路径。失败模型响应最多保留四份、每份最多 128000 字符，默认写入不由静态服务公开的 `data/history-article-diagnostics/:id/:runId.json`，文件权限为 `0600`；不记录请求凭据或上游错误响应原文。该诊断文件上限不是正文长度上限。短名字、缺失或无效的可选高亮会被忽略，不会单独使正文保存失败。
