# 科普工作台异常恢复

同日后续严格复核补齐了并发、后台接续、停止和封面校验，见 [科普创作流程可靠性复核](science-workflow-robustness-20261102.md)。下述最初部署时的“独立服务只执行显式操作”已由授权任务自动恢复取代。

任务详情顶部按具体原因显示处理入口，列表增加全部、待处理、进行中和已交付筛选。完整错误保留在折叠详情中，最新查询结果独立显示。旧“排队”记录没有实际执行者时显示“待开始制作”，提供启动按钮。

## 处理入口

| 情况 | 操作 |
| --- | --- |
| 封面失败或暂停 | 重试封面生成、继续生成封面，复用已有视频和原生成记录 |
| 封面请求已提交但无回执 | 生成新一版封面，明确确认新生图请求，保留旧素材 |
| 花生身份检查失败 | 检查花生账号、只查询制作进度、查看原项目 |
| 花生方案或点数待确认 | 打开原项目，确认后继续原制作任务 |
| 花生项目链接丢失 | 填写原项目链接，验证后绑定 |
| 上传结果不明确 | 只核对上传结果，打开原编辑页或同账号内容管理 |
| 平台安全验证 | 在百家号核对窗口完成验证，再继续原发表任务 |

“只查询制作进度”和“只核对上传结果”不会创建制作、导出或发表请求。只有可信的平台回执才能更新为已提交或已发表。未确认的上传不会因为重复点击而被强制重传。

核对窗口使用任务绑定账号的实际后台会话，可查看画面、点击、拖动、滚动和输入。原编辑页已关闭时打开同账号内容管理；不替换原任务页面或上传记录。每次操作核验目标页面、账号和原上传绑定，并与正在执行的账号操作互斥。

花生只读查询允许与同账号制作并行。自动继续导出的互斥只检查正在制作或导出的任务，不再被本地封面或百家号上传阻塞；确有占用时显示任务名称和 ID。身份接口对网络错误及 HTTP 408、429、5xx 最多尝试三次，账号过期与接口暂时失败分开报告。

## 本地运行

主后端已有其他工作台的任务在运行，本次使用可选的科普独立服务加载新接口，不重启主后端。

```sh
cd backend
npm run start:science
```

默认监听 `127.0.0.1:5683`，`SCIENCE_PORT` 可覆盖端口。前端本机 `.env` 设置 `SCIENCE_API_TARGET=http://127.0.0.1:5683`，仅转发科普 workflow 路径；其他工作台仍沿用原服务。未配置该变量时使用主后端现有路由。独立服务只执行显式操作，不额外启动全局恢复或生产 worker。
