# 历史视频本地素材检索修复

## 根因与修复

官网分镜的画面检索要求一直保存在 `huasheng_material_clips.query`；原选中视频的说明也在 `selected_caption` 和 `metadata.video.caption` 中。采集器却把时间线合成片 ID 当作原素材 ID，导致说明无法归到正确的本地视频。此次改为使用 `metadata.video.id`，兼容原有完整推荐检查点，不重新采集推荐或下载文件。

生产库已从保存的原元数据修复 8,952 条分镜的原素材身份，修复 33 条原说明，补齐 7,471 个资产的说明。1 个资产存在不同原说明，保留每条分镜自己的同 ID 说明，不擅选全局值。回填不修改检索要求、原元数据、推荐、下载状态或媒体文件；再次只读预览的待修复身份、说明均为 0。

检索现在优先考虑实际素材说明；只有素材 ID 等于分镜原素材 ID 时才能使用该分镜的原说明。原项目旁白和画面检索要求仍是独立的上下文字段，不会被写作其他推荐素材的真实画面说明。

自动选片先排除本片已经使用的素材 ID 与文件 SHA，再按资产排序、去重、截断；返回候选再次按文件 SHA 去重。指定景别没有精确结果时，只补充景别未标注的候选，并保存降级记录，已知冲突景别仍被排除。最终选片继续保留实测媒体检查、抽帧审核与同片资产唯一性规则。

同一素材被多处登记时，首条路径丢失、为空或不可用，会用现有 `findFiles` 查找同 ID 的有效副本，并使用副本自己的时长、尺寸和 SHA。越界文件和本片已用 SHA 仍不可使用，不会因为首条路径失效而隐藏已有有效视频，也不会因此重新下载。

分镜规划遇到 429、503、超时等临时错误时，在原任务退避重试，不继续调用配音、补图或渲染。成功的 30 镜规划批次保留，只请求失败批次；旧空规划缓存重新规划。个别镜头缺少有效设计时，从本镜原旁白分词提取最多 5 个关键词，避免全片都按一个标题搜索。已有有效画面和已完成作品不自动重制。

## 实库验证

只读重放最近 10 部完成作品中原本使用图片的 31 个镜头，按每部最多 2 个无候选、2 个候选耗尽的镜头抽样。旧检索有 1 个镜头找到未使用候选，新检索有 20 个，新增召回 19 个，旧有召回丢失 0 个。评估耗时约 40 秒，未调用模型、生成媒体或修改成片。

这验证的是候选召回，并不表示新增视频都已通过画面审核，不能直接换算成全片视频使用率。仍有 11 个样本没有候选，素材自身没有说明的情况也仍存在。

用户示例 `267993779273818 / 100001` 的原素材 `180bf4a2-0017-4343-a2a8-dadba7681fb6` 已能按“司马懿”找到，并返回《虎啸龙吟》原素材说明。运行中的实际搜索接口也返回 HTTP 200 和相同身份、说明。
