# 科普创作流程可靠性复核（2026-11-02）

## 用户报告与实际原因

初次复核时，斑马任务 `science-b7d29b8e-d003-4abb-b09c-57f25abd5502` 的花生项目为 `266942141431898`。官方接口已确认 144/144 个分镜素材就绪；本地却仍保存早先的身份核验失败，且没有执行句柄、没有下载成片。当时尚未完成交付，后续结果见下文最新记录。

“继续导出下载”在真实页面复现为 HTTP 409。原因是本地把同账号另一任务整个制作和导出期间都视为独占，包括远端等待。此提示不是花生平台的并发限制。芒果任务 `science-3c9d39fa-b600-4c18-8149-140eeb4cc721` 后来已导出下载，随后遇到封面标题格式校验失败。

早先身份错误的日志没有记录具体 HTTP 状态，不能反推出当时的网络原因。此次复核确认官方账号身份有效；代码中明确临时身份故障的可重试属性曾在浏览器、账号和制作接口之间丢失，最终被当作需要人工介入的故障。

## 已修复

- 只对创建、确认项目的浏览器操作串行；独立项目可同时等待远端制作、查询进度和导出，不再让一个长任务拒绝另一个原项目的接续。
- 用既有 SQLite 依赖的写事务获取、回收执行租约，并按 token 释放。任务执行与浏览器操作分别加锁，避免双进程在崩溃恢复时同时取得同一执行权。
- 同步队列只覆盖初次核验，随后释放；导出和下载继续使用原项目、原导出编号与版本。
- 网络、408、429、5xx 等明确临时错误保留可重试属性。过期登录、403 验证和账号不一致仍要求处理，不自动放行。
- 单个安全操作最多尝试 4 次；仍失败时，对可恢复的原项目安排最多 3 轮后台接续，记录下次时间。等待状态为 `retry_wait`，支持立即重试或停止。
- 尚未发起创建的 `opening` 步骤也能安全重试；已派发却没有项目链接或导出编号的未知结果仍需核对，不重发。
- 科普独立服务和主服务均启动科普恢复循环。重启后继续已有授权任务和中断批次，不重试所有历史失败任务，尊重明确停止。
- 旧批次中的单条手动任务即使在创建项目前中断，也可接续；批次遇到独立执行或自动重试中的原任务时只读等待并采纳结果。
- 停止批次会清除本批次本轮自己启动的恢复意图，并取消该任务链已经开始的活动重传；外部独立任务继续保留。服务关闭则保留重启恢复意图。
- 封面模型的 JSON、短标题行数、字数及依据校验失败会自动反馈原因纠正，最多 3 次，并与临时 HTTP 故障共用预算。图像提交仍在校验通过后进行，未知图像回执不自动重放。
- 接续按钮显示处理中与已受理反馈；旧身份错误标为历史记录，最新制作、导出进度和自动恢复时间持续显示。素材就绪与成片交付分开呈现。
