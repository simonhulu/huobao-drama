# 科普上传自动重传与花生项目打开规则（2026-11-02）

## 上传结果不明时自动恢复

按本次用户授权，科普工作台在无法确认上传结果时自动重传，接受可能产生重复作品。其他工作台不会因这项授权默认放开重复提交保护。

- 上传结果不明时进入 `retry_wait/upload`，记录 `uploadRetry.attempt` 和 `nextRetryAt`，后台到期继续。
- 退避从 30 秒开始，依次为 60、120、240 秒，之后每次最多等待 5 分钟；没有重试次数终止上限。这与花生制作查询的有界重试分别处理。
- 需要重新上传时，使用显式的 `allowDuplicateSubmission: true` 归档旧尝试，再以原账号、原素材和新的 attempt ID 上传。旧检查点、发表尝试、错误及关闭原因保留，任务记录上传尝试历史。
- 同账号上传串行，正在执行的写入不会被清理或重置；账号忙时等待后继续。
- 获得与原任务账号绑定的可信 `submitted` 或 `published` 回执后结束重试，已有可信回执直接采纳，不再创建新上传。

真实的登录失效、安全验证、额度或权限限制，以及账号、凭据、文稿、素材快照不一致等完整性错误，仍进入需要处理状态。未完成的原封面修订也会阻止重置，处理原因后才能继续。

`submitted` 表示平台已接收提交，尚不能据此认定审核通过或已公开发表。

## 停止与批次归属

用户主动停止任务会取消自动接续计划。停止批次时，也会取消本批次本轮自己发起的待重试计划及已经开始的活动重传，阻止该任务链继续重传或发表。

批次遇到原本由外部流程独立执行的任务或重试计划，只读等待并采纳其最终结果；停止批次不会取消这些外部任务。服务正常关闭保留中断批次与恢复意图，重新启动后继续原记录。

## 在原账号打开花生项目

三个工作台的 `open-project` 都从保存的记录读取账号和项目绑定：

| 工作台 | 绑定来源 |
| --- | --- |
| 科普 | 原科普任务的花生账号和项目 |
| 历史 | 原制作任务；缺少有效项目时可打开原账号主页核对 |
| 奇闻故事 | 指定 edition 的原账号和项目 |

打开操作使用绑定账号的专用 Chrome profile，复用已有项目页或打开新页。请求不能覆盖账号、项目链接或 profile，也不会启动制作、导出或发表。

手动查看不依赖在线 UID 核验，以便在身份接口暂时不可用或需要修复登录时仍可进入原浏览器；连接时仍校验 profile，不能连接到其他用户数据目录。生产和导出继续核验原账号 UID，手动打开页面不会绕过生产身份检查。

## 验证场景

- 显式允许重复提交后，不确定和损坏的旧记录可以归档；未开启时仍保持原保护。
- 已确认提交直接返回回执；其他账号的回执、变化的素材或凭据、活动写入及未完成封面修订仍被阻止。
- 批次在上传自动重试、后台执行和最终提交之间持续等待，不重复启动同一任务。
- 停止本批次自启的待重试或活动重传会取消该任务链；外部独立任务不被取消。
- 项目打开使用原任务或 edition 绑定，拒绝调用方替换账号、链接和 profile；手动查看与生产 UID 核验分别覆盖。
