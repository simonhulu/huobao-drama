# CBA 视频工作台

入口：`http://localhost:3013/cba-video`，顶部导航“CBA视频”。

## 使用

1. 点击右上角“百家号账号”，填写账号备注，点击“添加并扫码”，用百度 App 扫码并确认。可添加多个账号、检查登录、设置默认账号。百家号由 SAU 在后台运行，无需手动打开或保持浏览器。视频号和自动生产状态在“平台连接”检查；生产执行器使用本机 Codex CLI，支持 Codex 登录及已配置的自定义模型服务。自定义服务不依赖 `codex login` 状态。工作台以生产相同的 workspace sandbox 配置，实际检查模型响应、咪咕首页联网、任务临时目录和本地进程通信；成功缓存 5 分钟，“检查连接”可刷新。
2. 处理列表中未完成的任务时，点击右上角“继续未完成（N）”。默认选中可续做条目，可逐条取消或全选；每条显示恢复阶段和原上传平台、账号。点击“开始续做”后，按选择窗口的顺序串行处理，不重新采集首页。已有任务运行时可点击“加入续做队列”，等当前任务结束后自动开始。若要读取当前虎扑 CBA 首页的新新闻，使用独立的“采集新新闻”入口，可限制数量或关闭自动上传。提交表示授权所选范围的自动核验预览、MiniMax A 音色配音及渲染。
3. 在新闻任务中查看实际阶段、缺少素材的原因和产物。未执行咪咕搜索、部分请求失败、检索未找到以及下载受阻分别显示实际原因；点击“继续生产”从该步骤恢复。成片默认可直接预览，切换查看新闻版、集锦版；“文稿与来源”保留报道依据和标明“待核验”的咪咕候选页面。
4. 开始生产或手动上传时，选择百家号账号，新闻和集锦都保存到该账号。新生产默认选用默认账号；原任务继续时保持原账号，回执按账号分别核对。上传失败时先处理具体原因，再继续原上传；结果不确定时核对原检查点，避免重复上传。“管理上传”可选择其他账号或增补平台，已经保存的对应账号草稿会复用。
5. 队列进度显示当前任务、已处理、完成、等待上传、没有对应视频、失败与待执行数量；“查看队列”可逐条查看结果和原因。成片就绪但上传服务占用计入“等待上传”，明确没有对应比赛视频单独列出，不计为制作失败。单条失败后继续下一条，失败任务留待下次明确续做，不在同一队列无限重试。“停止队列”停止本队列、剩余条目及其待上传恢复，保留已有成果；即使制作已结束但仍在等待上传，也可停止。上传中会等待当前步骤结束再停止。等待队列前面的其他运行不受影响。

选中任务后，详情标题右侧的垃圾桶按钮可删除单条任务。删除前会二次确认，并校验当前标题；生产中、排队中或上传中的任务必须先停止或等待结束。删除会清理本地成片、任务目录、上传检查点、失败记录和续做队列条目，已经保存到视频号或百家号的外部草稿不会被远程撤回。

“继续未完成”保留每条任务原有的自动上传设置、平台和百家号账号，不改用新的默认账号。已有有效成片且原来要求自动上传的任务仅恢复草稿上传；已完成、重复、跳过、正在执行的条目，以及已完成本地出片且原来未要求上传的任务，不加入队列。单条“继续生产”和“上传到草稿箱”仍可单独使用。

工作流的上传终点是平台草稿保存成功。公开发布在平台处理。当前是手动启动一轮的自动流程，不是定时调度器。

## 数据与恢复

- 现有任务从 `data/cba-video/<job-id>/job.json` 自动读取。
- 新闻扫描结果位于 `data/cba-video/batches/<run-id>/intake.json`。
- 咪咕检索结果位于各任务的 `job.json.mediaSearch`，保留入口、查询、每页请求结果和候选。`status` 区分 `candidates_found`、`partial`、`not_found`、`access_blocked`，`completed` 记录检索完成情况。部分失败不计作“没有录像”；候选的 `verified:false`、`replayCandidate` 与 `matchEvidence` 只供后续核验，不等于已取得完整比赛。旧任务没有搜索记录时先补查，已有录像和成片继续复用。
- 对应同一比赛的候选按时长从长到短尝试，时长相同或缺失时按搜索结果顺序。集锦模式遇到“全场/半场”等标题冲突，保留原始标题并继续获取，由后续画面核验确定可用范围。没有对应单场比赛的新闻统一显示“没有对应视频”；网络失败或尚未完成搜索仍保留各自原因。
- 工作台运行、续做队列、上传检查点和设置位于 `data/cba-video/.console.json`。刷新或关闭页面不影响后台队列；服务退出后保留范围和成果，由用户重新点击“继续未完成”启动，重启不自动开展新的模型生产。
- 账号备注和默认选择位于 `data/social-auto-upload/accounts.json`；登录文件沿用 SAU 的 `cookies/baijiahao_<accountName>.json`，不经 API 返回。每个账号使用独立的后台浏览器；已保存成功或尚未选入素材的失败会关闭任务编辑页，并在浏览器空闲时退出专用 Chrome，下一条任务按需重新打开。已经选入素材、已尝试保存或结果不明的任务保留检查点和原编辑页，避免误重传；重新扫码后若旧上传尚未完成，会要求核对原草稿，避免误用旧会话。百家号新视频编辑页还按任务隔离草稿缓存，不会带出上一条任务的文案或视频。
- 制作调用已有 `cba-video-factory` 技能和制作 CLI；上传复用 `social-auto-upload`。新闻、下载和编辑仍由执行器逐项核验。默认要求完整录像；用户允许对应比赛集锦时显式使用 highlights 范围，不把集锦标为全场录像。缺少可靠事实或合适素材时记录实际阻塞。
- 成片只有在事实与素材核验、审核摘要、当前渲染摘要和交付文件哈希均有效时才上传；后台还通过 ffprobe 检查真实音视频、尺寸、帧率和时长，并解码封面、检查新闻字幕。校验失败时保留旧预览，并提供“继续生产”修复入口。
- 首次编辑集中读取主新闻正文、已支持事实和匹配素材，按新闻信息量确定篇幅；已有来源与同一媒体指纹下的有效切点证据优先复用。后台子执行器不在每次编辑、审核时重复环境体检或锁巡检，具体失败才触发对应诊断。
- 独立首审一次列全实质错误，首审后最多一轮内容修正，修改只针对错误清单；纯润色、非误导的资料画面切点偏好不阻断出片。审核报告的重复观察、缺字段或引用格式问题独立修复，不退回编辑重写或重剪。事实无依据、比赛错配、动作指认错误和失效证据仍阻断；修正后仍有错误则保留成果及原因，继续队列下一条。
- 恢复旧任务时，修正旧审核意见同样计入本轮一次内容修正额度；报告修复复用没有变化的证据包，稿件或镜头变化后生成对应的新证据。重复镜头观察仅合并记录及引用，不丢弃问题或捏造观察。
- 最终 AAC 响度首次不达标时，按实测响度与峰值余量自动调整一次音量，视频直接复制，不重剪或重做配音；再次测量仍须满足 −16±1 LUFS、真实峰值不高于 −1 dBTP。校正前后测量和最终文件哈希保存在响度报告。
- 服务重启时若原子执行器仍存活，保留运行占用；等其退出再核对结果，不自动启动第二份任务。
- 服务进程中断时，只有已经派发的项目会记录为中断；续做队列中尚未派发的项目保留为待执行，不计入失败。恢复后的队列不会自动启动模型，用户再次明确续做时从这些项目继续。
- 新的对话任务默认仍要求用户确认完整预览；工作台本轮授权在批准备注中如实记录，不能伪称用户已观看预览。

## 实现与验证

- 页面：`frontend/app/pages/cba-video.vue`；导航：`frontend/app/layouts/default.vue`。
- 账号弹窗：`frontend/app/components/BaijiahaoAccounts.vue`；账号接口：`backend/src/routes/cba-accounts.ts`；账号服务：`backend/src/services/social-upload-accounts.ts`。登录桥接为 `backend/scripts/social-auto-upload/accounts.py`，后台会话为同目录 `account_browser.py`。
- API：`backend/src/routes/cba-video.ts`，注册在 `backend/src/index.ts`。
- 续做接口：`GET /api/v1/cba-video/resume-queue` 读取可选条目；`POST` 同一路径仅接受 `requestId` 和去重的 `jobIds`（最多500条），固定每条原配置并幂等创建队列；`POST /api/v1/cba-video/resume-queue/:queueId/stop` 停止队列。总览返回 `resumeQueue` 和 `resumeCandidatesCount`。
- 队列条目保留历史 `status`，用 `outcome` 表示当前结果，并返回 `resolvedJobIds` 关联实际制作任务。仅原运行、原账号、当前成片版本与所有所选平台/版本的上传记录匹配时，才能归为等待上传或完成。前端兼容旧服务时按原任务 ID 只读解析并缓存关联，串行查询，主状态刷新不等待这些额外查询。
- 自动上传恢复在两条新闻之间获得一次执行机会，不与当前 CBA 生产项目并行。仍遇到共享上传服务占用时冷却至少60秒，不消耗三次真实恢复预算，继续下一条新闻；生产队列结束后仍会定时检查原上传记录。
- 上传互斥按平台与账号划分，不同百家号账号不因其他项目上传而互相阻挡。同账号跨项目保持串行，视频和图文也使用同一账号锁；旧无账号任务按浏览器会话互斥，同一上传任务始终有独立防重复锁。旧进程的全局独占锁仅在迁移期间等待其自然释放。
- 百家号新建视频页支持批量上传，真实入口带 `multiple` 属性，不能用“不允许多选”筛掉它。上传适配器优先定位空白上传区域，再核对控件唯一且可用；Playwright 和 CDP 使用同一选择器，每次只传一个文件。系统已关闭、且检查点证明尚未传入素材的失败页，可在原任务下重新打开。初始化失败保留具体错误；队列对已出片的任务明确提示对应平台和版本的上传原因，不再只显示泛化结束语。
- 状态与编排：`backend/src/services/cba-video.ts`。API 只接受本机工作台写入；媒体使用白名单和任务目录约束，支持 Range 播放。
- 咪咕检索：`scripts/cba-video/migu-search.mjs`，由 `cli.mjs migu-search --job <任务目录>` 调用。执行器在缺素材且没有有效候选的任务中运行；恢复优先复用候选，只处理指定任务。临时失败保留旧候选并标明 retained，最新失败状态继续如实展示；工作台只展示咪咕公开播放页面作为候选链接，去除查询参数，不返回直链、签名或账号信息。
- 执行器检查：`backend/src/services/cba-production-executor.ts`。使用与生产相同的工作目录、网络权限和任务临时目录执行 `scripts/cba-video/executor-check.mjs`，必须取得命令成功输出、预期回复及完整结束事件；仅登录或模型回复不能通过。安装、认证、配置、超时分别提示，不输出原始凭据日志。并发检查合并，成功缓存 5 分钟、失败缓存 10 秒。
- CBA 研究、编辑、独立审核和执行器检查固定使用 `gpt-6.1-sol`、`xhigh` 思考级别，通过命令行显式覆盖全局及仓库默认值。仓库 `.codex/config.toml` 的其他项目配置不受影响。首次准备集中核对事实与素材，后续沿用最多一轮实质内容修正；独立审核仍使用独立上下文，项目仍串行。
- 设计约定：`DESIGN.md` 的 CBA video workspace contract。
