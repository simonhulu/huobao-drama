## 持久化主播资源等待

`1a7f3ce` 增加显式 `waitForPresenter` 恢复选项，供已有可读正片、尚待 MuseTalk 主播合成且没有上传绑定的原任务使用：

- 启动前保存 `presenterWait.requestedAt/nextCheckAt`。即使在归档恢复或健康检查期间关闭后端，重启仍能接续等待；明确停止任务则撤销等待。
- 健康探针仅 GET `/health`，总期限 22 秒，始终关闭自建隧道。服务离线、加载或临时 HTTP 故障约 60 秒后再查，不消耗普通制作重试，不提交音频或创建 GPU 任务。
- SSH 认证、主机密钥、选项、缺失客户端以及服务模型和协议错误明确阻断。SSH stderr 仅在内存中保留最多 8192 字符用于分类，不暴露原始诊断或凭据。
- 等待分支先于花生同步和普通重试；单任务及批量“同步花生”不能覆盖等待。批次将等待视为未完成，不会把已下载但尚未合成主播的正片当作成片，也不会提前生成封面或上传。
- 只有 MuseTalk 恢复并通过原模型、头像和帧率健康校验后，才继续现有合成与封面流程，沿用原上传设置。该功能不释放 H3 会话，也不负责启动被 H3 暂停的服务。
